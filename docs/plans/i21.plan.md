- Why this design: the launch flag and the environment switch are small constant changes in `step_argv`, `judge_argv` and `step_env`, so a step, its retry (a fresh `run_step`, ECC-B9) and a judge follow one rule (ECC-B18, ECC-B20). A step that declares an MCP tool needs its server under `--strict-mcp-config`, and the only source then is a private config (ECC-B19), built per launch beside the judge's helpers in `mcpconfig.py` with the declared servers as the operator's configuration defines them, placed and removed as WSP-B5 and SEC-B12 say. Where the state root has no scratch folder (a request with no session folder), WSP-B5 allows no other place, so no config exists and the step launches strict with no `--mcp-config`, as when no declared server is defined. The live probe result of 2026-11-25 is recorded in the runbook, and `LIVE_FACTS` and `executor_compat.json` carry P-CC-13 as `confirmed` (hand-off decision), the rest staying `not run`.
- Measured signs, for `complex`: more than 12 task rows, more than 6 test rows, more than 10 files named, and more than 3 verification commands. The expand step writes the rows and the proof table.
