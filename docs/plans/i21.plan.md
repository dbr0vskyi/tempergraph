## 2. Phases

### Phase 1: The strict flag and the environment switch on every launch

Goal: argv of a step, a retry of it and a judge launch holds `--strict-mcp-config` in every case, a step holds `--mcp-config` only when it declares an MCP tool, and the environment of all three holds `ENABLE_CLAUDEAI_MCP_SERVERS=false` over a host or profile value; tests of ECC-AC12, ECC-AC13 and ECC-AC15 come first, and the tests that pin the old argv or the exact step environment (`test_step_env`) are changed.
Weight: light

### Phase 2: A step's private config of its declared servers

Goal: a step that declares an MCP tool is launched with `--mcp-config` naming a private config of exactly the declared servers the operator's configuration defines, as defined, removed when the session ends on any exit path and masked in the recorded argv, so the server's tools are still offered (ECC-AC14, with ECC-AC12 through `run_step` for a step and a retry).
Weight: light

### Phase 3: The live probe, the runbook and the recorded probe state

Goal: runbook row L-43 and its 2026-11-25 result (the operator's run, with the facts of the task's probe table) are in `live-checks.plan.md`, a live P-CC-13 probe test exists, `LIVE_FACTS` and `executor_compat.json` carry P-CC-13 as `confirmed`, and the tests that pin every fact as `not run` are changed; a runbook test carries AC 6.
Weight: light
