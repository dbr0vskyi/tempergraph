- Why this design: the hand-off fixes the flow and the plan keeps it: `triage` routes a discovery-route note that is not `covered: yes` to a script `owner_questions`; the route `ask_route` sends a run with a question to the engine's ask unit `ask_owner` and any other to `read_gap`; `ask_owner` declares `on_deadline: defaults` and its check refuses a reading called `wrong`; the `answers` artifact reaches discovery and the last stage. The script needs the triage note and the conversation value, which the engine does not give a script's callable today (`nodes.py` `_run_script` builds its context with `unit`, `workdir` and `request` only), so Phase 1 is a general engine fix of that context, as SCR-B5 and RST-B25 already state, tested with an engine fixture that names no workflow (ADR-0129). The deadline is the unit key `ask_owner.deadline_s` with a default of 86,400 seconds (OWQ-B7), not a second declared workflow setting, because no engine mechanism binds a setting to an ask's deadline; AC 5 holds either way. The four open questions of the hand-off are taken on their option (a).

## 2. Phases

### Phase 1: The engine gives a script its artifacts and settings

Goal: the callable of a script unit receives the artifacts and values of the run so far and the resolved workflow settings, and an engine test with a fixture workflow proves it.
Weight: light

### Phase 2: The setting and the sort under three values

Goal: the setting accepts `never`, `blocking` and `always`, the triage prompt, the task-notes rule and the triage check ask for and test the sort and the owner decisions under all three, and `outcome.json` holds the criterion at a new revision.
Weight: medium

### Phase 3: The list of questions and the route

Goal: the script `owner_questions` builds the list for `blocking` and `always` with the limits of OWQ-B6, and `route_triage` and `ask_route` send a run to the pause only when the list holds a question.
Weight: medium

### Phase 4: The pause, its answers and its deadline

Goal: `ask_owner` pauses once with the list, keeps partial answers, refuses a reading called `wrong`, goes on past the pause on complete answers and takes the defaults after the deadline, and the workflow's order, blueprint, diagram, authoring record and fixture agree.
Weight: medium

### Phase 5: Discovery closes each owner decision on its answer

Goal: the discovery prompt and judge references take the answers, close each owner decision on its answer or default with no open question, list how each was closed under `Decisions`, and end blocked only as CONV-B5 says.
Weight: light

### Phase 6: The description lists decided and assumed

Goal: the pull request description lists answered owner decisions under `Decided` and every other under `Assumptions to confirm`, read from the answers file with no model.
Weight: light

### Phase 7: The documents and the whole check

Goal: the README, the task-notes rule, the research note and the module docstring say what is built, and the package tests, the engine suite, `ruff check src tests` and `mypy` pass.
Weight: light
