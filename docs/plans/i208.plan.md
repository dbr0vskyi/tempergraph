# Plan: the loop's dry run as a run setting, with two arguments and a filing state

## 0. Hand-off

- Triage note: `docs/tasks/i208.triage.md`; hand-off: `docs/tasks/i208.handoff.md`
- Specs read: `plugins/tempergraph/docs/specs/loop-filing-state.spec.md` (LFS-B1 to LFS-B7, LFS-AC1 to LFS-AC7), `run-options.spec.md` (ROP-B2, ROP-B9, ROP-B14, ROP-B15, ROP-AC8, ROP-AC12, ROP-AC13), `run-events.spec.md` (EVT-B10, EVT-AC11), `loop-summary-and-review-retries.spec.md` (SIL-B52, SIL-AC63), `durability-and-resume.spec.md` (DUR-B17, DUR-AC15), `promotion-check.spec.md` (PRO-B8, PRO-AC7), `runs-without-a-final-exit.spec.md` (SIL-B47, SIL-AC57), `self-improvement.spec.md` (SIL-B6), `improvement-proposals.spec.md` (PRP-B31), `contracts.spec.md` (CON-B4), all under `plugins/tempergraph/docs/specs/`. Extra files opened beyond the hand-off's list, each for what the list did not answer: `plugins/tempergraph/engine/tests/test_autonomy.py` (a test patches `prp.autonomy` with a three-parameter lambda, which pins its signature), `plugins/tempergraph/engine/tests/test_loop_child.py` (the fixture helpers `blocked_run`, `judge_says`, `tickets`), `plugins/tempergraph/engine/tests/test_promotion.py` and `test_loop_summary.py` (the files of the PRO-B8 and loop-summary tests), `plugins/tempergraph/engine/src/tempergraph/improve/lost.py` (the lost-runner caller passes `options` and `settings` None), `tempergraph.commands.json` and `tempergraph.regenerations.json` (the commands; the regenerated files are package stamps no row touches).
- Why this design: the dry run becomes the catalog key `run.loop_dry_run`, so the flag layer, the snapshot of a thread (RST-B26) and the resolver already give "given last wins", "neither keeps" and "`--unset` returns to the declared value" with no new rule. The two words are computed once, where the ticket is made (`hand_to_loop` reads the thread's snapshot, never the files; `child.hand_off` computes the level and the words), and the loop child copies them into `loop_summary`; `status` reads the newest summary. The level lift calls the existing `prp.autonomy` unchanged (the test that patches it keeps working) and is decided in a new function beside it.
- Left to the plan, settled here:
  - U6, the refusals: both options in one call raise the CLI's usage error from the code that builds the flags (exit 2, before any write), worded as the mutually exclusive group of `--workspace` is; a bad value is `setting_value` from the key's check, so `run --check`, `run` and `resume` share the words (R2, R4).
  - The key's check must be strict (`1` and `0` are refused), so the key gets its own check and `worktree.read_worktreeinclude` keeps `_bool` (R2).
  - `config show` keeps printing a row only for a value that a layer above `engine` sets (RST-B27, RST-AC4); the default `false` is the resolved value and the catalog default, which LFS-AC1 reads (R2).
  - The declaration is a field of `WorkflowSpec`, put on `workflow:default`; `Workflow()` accepts it because it takes every field of the class (R3).
  - `RunOptions.dry_run` and `RunSettings.dry_run` stay as the engine's own flag of the runs it starts dry, so RST-B16 stays true and no row edits it; the CLI no longer sets `RunSettings.dry_run` (R4, R7).
  - The run meta and `run_started`: a segment writes `dry_run` when the engine flag, the meta of an engine-started thread or the resolved `loop_dry_run` is true, so a resume with `--no-dry-run` writes none (R7).
  - `hand_to_loop` takes the value, its layer and the lift from the snapshot it is given, and the legacy dry run from the log; its three callers pass a snapshot already, so none changes signature (R6, R8, R9).
  - A run the engine starts dry has `dry_run` on its `run_started` and no row for the key, so LFS-B3 reads it as a dry run with `argument`; no further word is added (R9).
  - `--set run.loop_dry_run=…` with a named option in one call: the named option lands last, as every spelling does (ROP-B2); no row needs it.
  - `rerun` takes neither option; its flag copy is RST-B26 and needs no row.
  - DUR-B17 reads the newest summary of each thread with the existing `loop_summary.thread_newest`; a thread with no `loop.jsonl` costs one missing-file check, and a thread whose exit started no child keeps the earlier words (R10).
  - `attention` shows neither word; the task asks for `status` only, so no requirement.
  - The open question of the hand-off is taken as its default: every flag-layer `false` lifts a declared `record`, with no check of how the flag arrived (R8).
  - FIN-B4 and FIN-B6 are not touched; they are a candidate issue.
