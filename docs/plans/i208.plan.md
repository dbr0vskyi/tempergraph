- Why this design: the dry run becomes the catalog key `run.loop_dry_run`, so the flag layer, the snapshot of a thread (RST-B26) and the resolver already give "given last wins", "neither keeps" and "`--unset` returns to the declared value" with no new rule. The two words are computed once, where the ticket is made (`hand_to_loop` reads the thread's snapshot, never the files; `child.hand_off` computes the level and the words), and the loop child copies them into `loop_summary`; `status` reads the newest summary. The level lift calls the existing `prp.autonomy` unchanged (the test that patches it keeps working) and is decided in a new function beside it.

## 2. Phases

### Phase 1: The setting and its declaration

Goal: `run.loop_dry_run` is a strict catalog key that a workflow can declare, a settings file or profile can set and `config show` prints, and `run_started` holds `dry_run` for the value in force.
Weight: light

### Phase 2: The two arguments

Goal: `run` and `resume` list `--dry-run` and `--no-dry-run` as spellings of the flag, refuse a call that gives both before any write, and the value given last wins on resume.
Weight: light

### Phase 3: What decides an exit

Goal: at a final exit the thread's value of the setting, the legacy log rule, the lift of a declared `record` and the hold decide the level and the dry run on the ticket, and the mode decides nothing of it.
Weight: medium

### Phase 4: The two words

Goal: the loop child writes `filing` and `filing_source` in `loop_summary`, and `status` shows them on the thread's row.
Weight: light

### Phase 5: The guide and the tests that pin the old shape

Goal: the guide states the whole rule in one section with its test, and the existing tests that pin the old switch, the old signature of the level function and the specs they scan are changed only where a criterion changes their fact.
Weight: light
