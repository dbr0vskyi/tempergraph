- Why this design: the executor already returns `usage_limit`; the run reads it at three places only. `_session` stops its infra loop on it and `step`/`_judge_session` turn it into the escalation cause `usage_limit` (a new member of `ESCALATE_CAUSES`), so `decide` pauses with kind `escalation` before any counter or verdict is read. The pause payload, `pause` record, status row and detail block carry the instant. A resume with no decision at such a pause skips the `decision_missing` refusal, writes the HUM-B6 ledger row with an empty decision (the first open question's default, a) and routes from the human node to the node the refused session belongs to (`<unit>.step` or `<unit>.judge`) with no counter write; the step node then reuses the refused attempt's number and its prompt inputs, which the refused record keeps.
- Open questions of the hand-off, taken at their defaults: the plain resume writes an intervention row (decision spelled as the empty string, touch class that of an escalation); `proceed` stays accepted at a usage-limit pause (no new rule).
- Fixtures: a new `plugins/tempergraph/engine/tests/test_usage_limit.py` built on `tests/test_run.py` helpers (`go`, `records`, `judge`, `registry`), a `ScriptedExecutor` queue holding `SessionResult(ok=False, usage_limit=True, usage_limit_resets_at=<now + 3600>)`, and `resume(...)` from `run/runner.py`. Tests that pin edges or the human node's targets (`tests/test_compiler.py`, `tests/test_contest_diagram.py`, `tests/test_council_diagram.py`, `tests/test_ask_wait.py`, the diagram-reading tests of `tests/test_package.py`, `tests/test_scaffold.py`, `tests/test_stamp.py`, `tests/test_upgrade.py`) are searched by the expand step before it writes the row that changes `human_targets`; each test it would break gets a row.
