- Why this design: the specs make a stop at a pause and a lost runner two more final exits that feed the existing recorder (`record_exit`) and hand-off (`hand_off`, `_loop`), so the plan reuses those and adds only the three things no code has: a stop that records before it returns, a catch-up of the findings of earlier pauses that no loop judged (it needs a record of what a loop judged, so `loop_started` gains the fingerprints it covered), and a hand-off of a lost segment made by the three verbs.
- The lost-runner hand-off is its own function called by `cmd_status`, `cmd_stop` and `cmd_attention`. `durability.status.status()`, `observe.attention.items()` and `observe.detail.detail()` stay pure reads, so DUR-AC3, RDD-B6 and the read-only fixtures hold and `status --detail` keeps `health.orphaned` true (SIL-B26, RDD-B14). The claim is the thread's run lock taken without waiting (DUR-B10): a verb that finds it held skips the thread. A lost segment is already recorded when the thread's ledger holds a `runner_lost` row at or after the segment's `run_started` record (SIL-B27); a thread's earlier `runner_lost` ticket is read from the ledger and the loop records (SIL-B28). The engine writes no `run_exit` for the lost segment (hand-off, Decisions).
- Tests that pin what the change touches: `test_improve.py::test_every_threshold_is_a_parameter` (iterates `params.PARAMS`; the new record needs a provenance and a source); `test_fallback_breakpoint.py` lines 132 to 141 (stop of a breakpoint thread: asserts the exit code and no executor calls, and holds when a ledger row and a `finding_recorded` record are added); `test_detail.py::test_orphaned_thread` (its fixture is a lost runner but it calls `detail()`, which hands nothing over). The expand step searches again before it writes each row and names the tests it finds.
- Assumptions, all taken from the hand-off's defaults and recorded in the specs' open questions: once per trigger and thread, not once per end; 7 days as `lost_runner.window_days`, provenance `default_no_data`; a lost runner is no stable-mode signal of its own; `resume` and `wait` do not find a lost runner; a thread resumed with `proceed` after a pause and then finished is unchanged. The monitor's own documents (`plugins/tempergraph-monitor/docs/adr/0002-poll-files-and-read-only-verbs.adr.md`, `plugins/tempergraph-monitor/docs/specs/01-data-sources.spec.md`) call `status` read-only; the hand-off leaves them to the monitor's owner, outside this task's gaps, and the plan does too. The final report names them.
- "Not built yet": spec 16 has no such line, and the one in spec 44 is about corroboration (SRV-B7), which this task does not touch. Nothing is removed.
