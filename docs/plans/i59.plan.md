- Why this design: the specs make a stop at a pause and a lost runner two more final exits that feed the existing recorder (`record_exit`) and hand-off (`hand_off`, `_loop`), so the plan reuses those and adds only the three things no code has: a stop that records before it returns, a catch-up of the findings of earlier pauses that no loop judged (it needs a record of what a loop judged, so `loop_started` gains the fingerprints it covered), and a hand-off of a lost segment made by the three verbs.
- The lost-runner hand-off is its own function called by `cmd_status`, `cmd_stop` and `cmd_attention`. `durability.status.status()`, `observe.attention.items()` and `observe.detail.detail()` stay pure reads, so DUR-AC3, RDD-B6 and the read-only fixtures hold and `status --detail` keeps `health.orphaned` true (SIL-B26, RDD-B14). The claim is the thread's run lock taken without waiting (DUR-B10): a verb that finds it held skips the thread. A lost segment is already recorded when the thread's ledger holds a `runner_lost` row at or after the segment's `run_started` record (SIL-B27); a thread's earlier `runner_lost` ticket is read from the ledger and the loop records (SIL-B28). The engine writes no `run_exit` for the lost segment (hand-off, Decisions).
- Tests that pin what the change touches: `test_improve.py::test_every_threshold_is_a_parameter` (iterates `params.PARAMS`; the new record needs a provenance and a source); `test_fallback_breakpoint.py` lines 132 to 141 (stop of a breakpoint thread: asserts the exit code and no executor calls, and holds when a ledger row and a `finding_recorded` record are added); `test_detail.py::test_orphaned_thread` (its fixture is a lost runner but it calls `detail()`, which hands nothing over). ## 2. Phases

### Phase 1: The window parameter and the record of what a loop judged

Goal: `lost_runner.window_days` is a parameter record, and a loop's start record names the fingerprints it covered, so later phases can tell which findings no loop judged.
Weight: light

### Phase 2: A stop at a pause is an exit that covers the earlier pauses

Goal: a person's stop of a thread paused at a gate or before a `--pause-before` unit writes the records of an exit with code 4 and reason `person`, and its ticket carries the unjudged findings of the thread's earlier pauses, in dev and in stable mode.
Weight: medium

### Phase 3: A lost runner is a final exit found by `status`, `stop` and `attention`

Goal: a thread whose runner is gone without an exit is written as a final exit with code 5 and reason `runner_lost`, once per segment and once per thread for the loop, by a hand-off the three verbs call, with their output and exit codes unchanged.
Weight: heavy (many-tests)

### Phase 4: Docs that call `status` free of effects

Goal: the guide and the two skills tell what the loop now starts on, and no document the change touches says `status`, `stop` or `attention` write nothing for a lost runner.
Weight: light
