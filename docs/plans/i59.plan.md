## 2. Phases

### Phase 1: The window parameter and the record of what a loop judged

Goal: `lost_runner.window_days` is a parameter record, and a loop's start record names the fingerprints it covered, so later phases can tell which findings no loop judged.
Weight: light

### Phase 2: A stop at a pause is an exit that covers the earlier pauses

Goal: a person's stop of a thread paused at a gate or before a `--pause-before` unit writes the records of an exit with code 4 and reason `person`, and its ticket carries the unjudged findings of the thread's earlier pauses, in dev and in stable mode.
Weight: medium

### Phase 3: A lost runner is a final exit found by `status`, `stop` and `attention`

Goal: a thread whose runner is gone without an exit is written as a final exit with code 5 and reason `runner_lost`, once per segment and once per thread for the loop, by a hand-off the three verbs call, with their output and exit codes unchanged.
Weight: heavy (many-tests)

### Phase 4: Docs that call `status` free of effects

Goal: the guide and the two skills tell what the loop now starts on, and no document the change touches says `status`, `stop` or `attention` write nothing for a lost runner.
Weight: light

### Phase 5: The criteria of the contracts the change edited are carried by tests

Goal: RCT-AC5, CLI-AC5 and OVR-AC5, the criteria of the stop, attention and read-only-verb contracts that SIL-B26 gave an exception, are each carried by a test that runs, and each test passes on the tree.
Weight: light
