- Why this design: the executor is the only place that knows the allowance is spent and when it resets (EXI-B7 forbids reading text), so Phase 1 adds two result fields from the `claude` stream's last `rate_limit_event`. The review then names its class and stops at once (Phase 2), the summary and `attention` count by class (Phase 3), and the loop child's flow, owned by SIL-B17, waits and retries once before it writes the summary (Phase 4). One rule decides "failed" in the summary and in `improve review show`: a review is failed when the latest `review_done` or `review_failed` record of its session is `review_failed`, so a retry that succeeds clears it in both places.
- The loop child reads the clock and sleeps through replaceable functions so a test can run on a fake clock. A wait starts only when `mode()` is not `inline` and only in the child's own flow, never in `improve review`.
