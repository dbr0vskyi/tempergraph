## 2. Phases

### Phase 1: The executor reports a spent allowance

Goal: a `claude` session that ends not ok after a rejected rate limit report returns `usage_limit` and its reset instant, every other session returns false and null, and a stand-in executor can script a failed session that reports one.
Weight: medium

### Phase 2: A failed review names its class and a usage limit ends it at once

Goal: `review.run` writes `error_class` (and `resets_at`) on every `review_failed` record, ends a review at once on `usage_limit` with one reviewer session per target, and lists in `improve review show` only the reviews whose latest record is failed.
Weight: medium

### Phase 3: The summary and `attention` count the failed reviews

Goal: `loop_summary` holds `review_failed` by class, the child's whole-review error counts as one review of class `error`, and `attention` prints and carries a loop whose reviews failed.
Weight: light

### Phase 4: The loop child retries a usage-limit failure once after the reset

Goal: the loop child waits for the latest reported reset within `review.retry_wait_hours`, runs those reviews once more with `retry` true on every record and its cost in the `loop` ledger row, never waits in the foreground or for an unknown or distant reset, and writes its summary after the last retry.
Weight: heavy (large-context)

### Phase 5: The guide says what a person does

Goal: the improving-workflows guide tells a person where a failed review shows and that a review that failed on a usage limit is rerun with `improve review` after the reset.
Weight: light
