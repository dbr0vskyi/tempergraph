# Plan: A judge's read share counts only the paths the judge was there to read

## 0. Hand-off

- Triage note: `docs/tasks/i201.triage.md`
- Hand-off: `docs/tasks/i201.handoff.md`
- Specs read: `plugins/tempergraph/docs/specs/judge-read-share.spec.md` (SRV-B31, SRV-B34 to SRV-B45, SRV-AC13 to SRV-AC49), `plugins/tempergraph/docs/specs/workflow-model.spec.md` (WFM-B14, WFM-AC8), `plugins/tempergraph/docs/specs/session-review.spec.md` (SRV-B11, SRV-B12, SRV-AC1), `plugins/tempergraph/docs/specs/contracts.spec.md` (CON-B7, read to decide the docs question in section 4).
- Code read, from the hand-off's reading list: `git.py` (`changed_paths`), `run/nodes.py` (`_entry_commit`, `_session` and `_judge_session`), `improve/digest.py` (`build`, `write_segment`, `causes`), `improve/record.py` (`judged_units`), `contracts.py` (`GateSpec`, `ToolCall`), `api.py` (`Gate`), `model/validate.py` (`_unit`, `_judge`), `executors/standins.py`, `executors/claude.py` (`parse_line`), `run/risk.py`, `run/checks.py`, and the tests `test_judge_changed_paths.py`, `test_judge_changed_paths_map.py`, `test_session_review.py`, `test_validate.py`, `test_session_record.py`.
- Files opened beyond the list, and why: `tempergraph.commands.json` (the commands a verification line may start with); `store/layout.py` (`session_key`: an item's session key is `<unit>.<item>.<attempt>.<kind>`, which the per-item key of SRV-B44 reads); `run/log.py` (`session_sink`: shows that a scripted read event reaches `activity.jsonl`, the file the digest reads).
- Why this design: the spec edits are already made by discovery, so this plan is the code and the tests that make them true. The three open questions of the hand-off are built on their defaults: the field `judge_may_skip` is a field of the gate (WFM-B14); `changed_left_out` counts the gate's patterns only (SRV-B43); a judge record with no `changed_base` key is read as it was counted, its `changed_paths` giving `changed_total` (SRV-B38 names a null `changed_base` only). The stand-in reports a read through a subclass of `ToolCall` kept in `executors/standins.py`, so the shared contract `ToolCall` does not change. The judgements of a map are keyed by unit and item, with a non-map unit keeping its bare unit name as the key, so the existing tests that pass `judged={"draft": ...}` keep their shape.
- Pinned by existing tests, to be given rows by the expand step: `test_judged_units_marks_the_attempts_that_gave_a_judgement` in `tests/test_session_review.py` groups two items `x` and `y` of one unit under one key, and changes with SRV-B44; the hand-built journal of the SRV-AC22 test in `tests/test_judge_changed_paths.py` changes with SRV-AC47. No test constructs `GateSpec` or `JudgeSpec` by position (both are keyword-only), so the new gate field breaks none.
- Spec wording seen while reading: the longest behaviour sentences, SRV-B34 (about 486 characters by my count) and SRV-B37 (about 453), are under 500; no placeholder text found. The gate measures sizes; the session-review spec is the one close to its 30,720-byte limit and this plan edits no spec.
