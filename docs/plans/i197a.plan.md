- Why this design: the engine reads a check result's environmental mark before it routes (hand-off U1: `nodes.py` lines 1512-1515), so the whole change is in the package's outcome check. The mark is one boolean of the result and `_result` sets it only when nothing else fails, so `_result` gains a keyword that the outcome check sets, and the code gate keeps its own rule (`ts-code-mixed`, assumption A4). The two facts become `_Environmental` findings, so `_result` already puts them first in the evidence (OGT-B15). The comparison of a failing command is the code gate's own function, `_verify` with `compare=True` (its default stays `False`, so `test_temperspec.py` line 1057 is untouched).
- Design settled for the rows:
  - `_result` takes a new keyword-only `pause` (default `False`); the result is marked environmental when an `_Environmental` finding fails and (`pause` or no other finding fails). Only `outcome_check` passes `True`. No other caller changes.
  - `_fresh` returns an `_Environmental` failing finding for each stale spec. Its message names the path, the run's base commit and the base branch's head as 10-character abbreviations, so that the cause stays inside the 200 characters the run log keeps after the engine's "N of M deliverables present" line (hand-off, "The evidence is bounded"). Its fix is one constant: bring the head of the base branch into the run's branch, then answer `retry`. `outcome_check` also adds that action as a line of the evidence, before the push line, when `ts-spec-fresh` fails, so the pause shows it (task AC 1).
  - `outcome_check` calls `_verify(ctx, plan, "ts-verify", compare=True)`.
  - No unit's `serves` changes: no unit serves `ts-spec-fresh` (still pinned by `test_side_by_side_runs.py`), and `ts-verify` keeps its serving units for the caused-by-the-change case.
