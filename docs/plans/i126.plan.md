## 2. Phases

### Phase 1: The reuse key names the tree's content

Goal: a command run stored before a commit is reused after it when no file changed, and a changed or added file makes it run again, proved in the engine with a scratch repository and with a preview, an `after` script that commits, and the gate's check.
Weight: light

### Phase 2: The code step: preview declared, prompt reordered, criteria mirrored

Goal: the `code` step declares the preview, its prompt tells the session to run each verification command once through it after the last phase with the plan marked and the report written, and `outcome.json` at revision 9 holds each new or edited row with its pins updated.
Weight: light

### Phase 3: The code gate: a preview that runs the commands, reuse after the commit, evidence per command

Goal: a preview of the code gate's check runs each verification command with no failure for the missing report or the pending commit, the gate then reuses those runs on the committed tree and runs them again after a change, and its evidence says for each command whether it was reused or run.
Weight: heavy (many-tests)

### Phase 4: Documents

Goal: the research note and the overview spec say what is true after the change.
Weight: light
