## 0. Hand-off

- Triage note: `docs/tasks/i206.triage.md`
- Hand-off: `docs/tasks/i206.handoff.md`
- Specs read: `plugins/tempergraph/docs/specs/script-units-and-hybrid-steps.spec.md` (SCR-B10, SCR-AC6), `plugins/temperspec-tgraph/docs/specs/independent-review.spec.md` (IRV-B3, IRV-B15 to IRV-B23, IRV-AC3, IRV-AC15 to IRV-AC23), and the check contract's CHK-B10 and CHK-B19 and the regeneration spec's Purpose, RGN-B3 and RGN-B13 through the hand-off's reading list.
- Files opened beyond the reading list: `tempergraph.commands.json` and `tempergraph.regenerations.json` (the verification commands, and which files a regeneration writes), `plugins/temperspec-tgraph/README.md` (a document the change makes incomplete), `plugins/tempergraph/engine/tests/test_workflow_packages.py` (how a package's tests run), and a search of the engine's and the package's tests for code that pins a script's `git` (none found).
- Why this design: the engine already builds `GitFacts` for a check from the state's `workspace.base_commit`; a script's callable is built in `_run_script` from the same state, so it takes `GitFacts(base=<that commit>)`, the empty string when the run has none, and no signature changes (`CheckContext.git` exists). The package then builds the reader's inputs from `ctx.git.base`, writes the base it used beside them, and the check compares. Every other guard is a finding of `review_check` on the existing criterion `ts-rev-form`, whose text and `outcome.json` stay as they are (PKG-B22 binds the two).
- The plan is `complex`: more than 3 phases, more than 6 test rows to come, and the files the rows name (`run/nodes.py`, `checks.py`, `test_independent_review.py`) are over 200,000 bytes together. The expand step writes the rows and the proof table.

Decisions that settle the hand-off's `Left to the plan` and the triage note's `Detail` rows:

- U6 (size of "a large diff"): no number. The brief says a change that does not fit one read is read page by page until its last line (IRV-B23); R7.
- U7 (names): the inputs stay in `.tempergraph/review/`. `files.txt` is the file list, one row per file as `+<added> -<removed> <path>`, a generated file's row ends with ` [generated]`, a file git counts no lines for (binary) shows `+0 -0`. `base.txt` holds the commit the inputs were built from. `failed.txt` holds the failing git command. None ends in `.md`, so the hand-over pattern of `review.py` does not match them. R2, R5, R6.
- Where the base is recorded, and a missing record (U8): `base.txt`; a missing `base.txt` with a base commit given is a base the change was not built from, so IRV-B15's finding names the check's commit and says none was recorded. R3.
- "The run changed at least one path" (U3): measured after the exclusions of IRV-B3, from the check's own changed paths. R4.
- How a git failure reaches the check (U4): the `before` script catches it, removes the earlier inputs, writes `failed.txt` and returns; a raise would carry no text and escalate as environmental (SCR-B8). `review_check` reports one finding on `ts-rev-form` that names the command, and adds no empty-change or base finding for the same failure. The reader's session still starts before the check; each retry rebuilds the inputs, so a git that keeps failing repeats the finding until the attempt cap. R5.
- Stale inputs (IRV-B19): the script first removes `change.diff`, `files.txt`, `base.txt` and `failed.txt`, and writes `base.txt` last, after every git command succeeded. R5.
- Prepare-step files once the base is the engine's: a new function lists the commits of `<base>..HEAD` whose subject is a run's `prepare` commit and reads their files; the inputs and `review_check` both call it, so the diff and the check's changed paths agree. `run_base` and its lenient `_git` stay, because `regeneration.py` calls them and moving it is out of scope. R2.
- Generated files (U5): a changed file is generated when it equals a path in `regeneration.declared_outputs(workdir)` or lies under one (the folder rule of `regeneration.py`), not `_regenerated` of `checks.py`, which needs commit history. R6.
- No base commit: the script writes no change and no `base.txt`; the check fails with IRV-B17's finding and adds no other base finding. A callable with no `git` (an older engine) reads the same empty base. R4.
- Cached script (SCR-B9): the key holds no base and the base is fixed for a thread, so nothing is added; `review_before` declares no cache.
- Cases of the file list: a rename is a deletion and an addition (the diff uses `--no-renames`), no cap on the number of files, an empty list when the change holds no file, a path with an unusual character is written as git prints it with `-z`.
- Out of scope, named in the code report: item 2 (reads outside the diff), the brief's new questions and the backstop, the unit's off switch, the loop's reading of a review, the live run, and `regeneration.py` moving to the engine's base. The candidate issue about SCR-B5's `ScriptContext` stays as the hand-off records it.
