- Why this design: the mod has no host call that reads the environment or the home folder (research F6), so MAC-B6's `TEMPERGRAPH_HOME` or `~/.tempergraph` is learned the way the Processes tab learns `ps`: one constant POSIX probe argv (`sh -c 'printf %s "${TEMPERGRAPH_HOME:-$HOME/.tempergraph}"'`), run only when the setting and `PATH` have both exited 127, so the idle poll budget of MDS-B1 and the session tests that answer on `PATH` are untouched. The probe builds no engine verb and writes nothing; the read-only guard accepts it by exact match, as it accepts the `ps` listing, and the one `$.process.run(` call site stays behind the guard (MDS-AC-2). The first program that does not exit 127 is kept for every verb after it (MAC-B5); when that kept program later exits 127, the lookup starts again from the `engine_path` setting, as MAC-B5 says ("or the program it found exits 127"), and the answered home is reused, not asked again. The pane's not-installed text reads the places the failed lookup recorded in the engine state. The hand-off's open questions (the "until the person runs the installer" clause, the bare `tempergraph` in prompt fills) keep their defaults (a) and no row serves them.
- Points sent back by earlier reviews, and what this plan does with each: (1) no duplicate places: the ordered places never hold one program twice (a setting equal to the home shim is one place) and one lookup never runs a program twice; (2) a rejected `$.process.run` of an engine verb counts as a failed place, like exit 127, because MAC-B5 says a program exits 127 "when it does not exist"; (3) a new state shape: the engine atom gains `looked`, so the shape key of the state atoms becomes `m2` and state saved under `m1`, which has no `looked`, is not read; (4) an idle re-look: none. Once the engine is marked not installed no engine verb runs until the session restarts (MDS-B6, default (a) of the open question), and a restarted lookup happens only after a kept program exits 127, so MDS-B1's idle budget holds; (5) `$.env.get`: I searched the repository for a host call that reads the environment (`$.env`, `env.get`) and found none in the mod, its types or its research note (F6 lists `$.fs` and `$.process` only; the only hits are in the Python engine), so the home is still learned by the constant probe; (6) spec wording: row 3.2 writes the table row and the sentence as what the monitor does now, with no mention of a task or of an earlier state.
- State of the tree: the earlier visit already left code and tests for these rows in the repository. This plan is new, so every row starts unmarked; the code step checks each row's change against its file, builds what is missing and marks the row.
- The test kit passes plugin options with `test(name, { options: { engine_path } }, fn)` (found by the earlier visit); the session tests of row 1.1 to 1.3 and 2.1 use that form.
