- Files opened beyond the hand-off's reading list, each for what the list does not answer: `tempergraph.commands.json` (the commands a verification line may start with); `plugins/tempergraph/engine/tests/test_workflow_packages.py` (lines 29-60: how the engine's suite runs a package's own tests, from the package folder); `plugins/tempergraph/engine/src/tempergraph/author/verify.py` (lines 202-210 and 268-320) and `plugins/tempergraph/engine/src/tempergraph/package/stamp.py` (lines 112-188) (what `author verify` writes to `stamp.json` and `authoring.json`, and that it runs the package's own tests as rung 4); `plugins/temperspec-tgraph/tests/test_judge_reading.py` (lines 146-190: phrases every judge text, the outcome stance among them, must keep); `plugins/temperspec-tgraph/tests/test_owner_pause.py` (line 367: the only test that reads `authoring.json` decisions, by unit names); `plugins/temperspec-tgraph/evals/calibration/outcome/unmet-ts-spec-sync/case.json` (a seed carries no stance and no `serves`, so the seed digests stay).
- Why this design: the engine derives the back target from the criteria that `serve` a failing final criterion and never from the judge's place (OUT-B3, OUT-B16; the engine stays as it is). So the package changes which criteria serve `ts-spec-sync`: the criteria of the setup step (`ts-set-links`) and of the triage step (`ts-tri-gaps`) stop serving it, and the plan step's `ts-plan-spec` serves it, which leaves `ts-dis-links` (full discovery), `ts-plan-spec` (plan step) and `ts-code-related` (code step) as the criteria that serve it. The engine then returns to the full discovery on a path that holds it, to the plan step on a path with a plan and no full discovery, and to the code step on the quick lane. The reason of the visit is the judge's evidence (`gate.py` builds it from each blocker's `problem`), so the outcome judge's stance asks for the place and the fix in the evidence of each criterion it grades PARTIAL or UNMET (OGT-B12). The serving of `ts-accepted` is not changed (OGT-B9, OGT-B10).
