## 2. Phases

### Phase 1: The marks and the answer format

Goal: a judgement block carries `unread` on a finding and `gap_unread` beside `gap`, `parse_judgement` reads them (absent or false is not marked), the answer format asks for them with the places in `fix`, and a judgement without the fields derives as before.
Weight: light

### Phase 2: One re-read before the verdict

Goal: the judge node guards the first session, and when the first judgement has a failing blocker or a `gap`, no unmarked failing blocker and a marked `gap` if it has one, runs one `judge_reread` session with the re-read prompt on the first request's executor, model, effort, views and subject, derives the verdict from its judgement alone, and starts no third judge session.
Weight: medium

### Phase 3: The re-read under the guard, the usage limit and the risk rule

Goal: a re-read that times out, is discarded by the guard or has no parsable block after its JDG-B2 re-ask is an unparsed judgement, a re-read ended by a usage limit writes no `judgement` record and starts no later judge session, an infra failure of the re-read ends the attempt as JDG-B5 says, and a re-read runs on the risk rule's model with the same views and no second `judge_risk` record.
Weight: medium

### Phase 4: The re-read in the records, the counts and the cost

Goal: `judge_reread` is a session kind of the contract, the report, the detail document and the digest, its folder and `agent_run` record are its own and its cost is in the run's, the `judgement` record of a re-read attempt holds `reread` with `criteria` and `gap` and none otherwise, and the report and the detail document count the re-read with the judge's sessions.
Weight: medium

### Phase 5: The judge briefs

Goal: each of the 11 briefs of `judges/` and the outcome judge's stance say that a file a row or a criterion names is opened with the read tool before it is graded, that lines a search printed are not a reading, and that a grade that fails only for want of a reading is marked with the path and lines as its `fix` (the code brief keeping JRD-B4's file beyond the budget unmarked); a test asserts the three sentences in each brief the loaded workflow hands a judge; `outcome.json` and `stamp.json` take the new revision.
Weight: medium

### Phase 6: The stand-in run on the `phases` arm and the closing checks

Goal: a stand-in run of the package on the `phases` arm whose phase judge first marks a gap and then grades every blocker MET passes the phase gate on its first attempt with no pause, and the changed specs, the ids on the new tests and the unchanged JDG-AC, JRD-AC and PRL-AC tests are proved by the suites.
Weight: light
