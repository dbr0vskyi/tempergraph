- Why this design: the rule is stated once, in KMK-B9, and three texts carry it (the code prompt, the phase prompt and the plan rule), so one test over the three texts with one shared phrase proves KMK-AC16 and KMK-AC17, and the same test file reads this repository's installed copy of the plan rule. The task's criterion 2 (the installed copy equals the package's) is held by the existing test `test_the_copy_of_the_rules_installed_beside_the_package_is_the_same` in `tests/test_temperspec.py`; the code step cannot run `install_rules.py` (not in `tempergraph.commands.json`), so one row edits the installed copy by hand to the same text. The retry hints in `checks.py` and `PROMPT_SAYS` are not changed: the task does not ask for it, and the hints name no count of edits.
- Wording the rows share. In the prompts: "write the completed marks of the rows you built in one phase in one edit of the plan, after the change of each row is in its file and the test files that the phase's rows name pass, and not in one edit for each row". In the plan rule, third person: "writes the completed marks of the rows it built in one phase in one edit of the plan, after the change of each row is in its file and the test files that the phase's rows name pass, and not in one edit for each row". One edit is one change to the plan file that marks every row built in the phase; the unit is the phase, so a code session that builds two phases writes two edits.
