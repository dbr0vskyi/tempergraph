# Plan: the isolation plugin loads without importing the engine and covers the whole session; `stats forget` loses nothing

## 0. Hand-off

- Triage note: `docs/tasks/i144b.triage.md`; hand-off: `docs/tasks/i144b.handoff.md`
- Specs read: `plugins/tempergraph/docs/specs/test-suite.spec.md` (TST-B2, TST-B5, TST-B7 to TST-B12, TST-AC6, TST-AC7, TST-AC9 to TST-AC18), `plugins/tempergraph/docs/specs/central-run-stats.spec.md` (CST-B8, CST-B17 to CST-B24, CST-AC5 to CST-AC14); contracts, engine-cli and self-improvement specs are read through the hand-off's list (CON-B13 exit 2, CLI-B19 exit 1, SIL-B1 loop values) and are not changed.
- Extra files opened beyond the hand-off's reading list: `tempergraph.commands.json` (the commands the check accepts), `plugins/tempergraph/engine/tests/test_cli.py` (the `cli` helper that `test_central_stats_forget.py` calls), and a search of `src` and `tests` for `stats_path`, `_locked`, `REWRITE_TRIES`, `pytest_plugin` and `pytest11` (to find every writer of the stats files and every test that pins the plugin's module name: only `tests/test_suite_isolation.py` does, in `PLUGIN`, `package_pytest` and the entry-point test; no test pins `forget._rewrite`).
- Why this design, plugin: the defect is that loading the entry point imports the engine package (`tempergraph/__init__.py` imports `tempergraph.constants`) before `tests/conftest.py` can put `src` first. The plugin module moves to a top-level module of the same distribution, `tempergraph_pytest_plugin`, that imports only the standard library and pytest, so loading it leaves `tempergraph` unimported (TST-B12). The entry point keeps its registered name `tempergraph.pytest_plugin` (the name `-p no:` takes, TST-B11). A hook that pytest calls before any conftest is imported sets the session's home and loop variables (TST-B9, TST-B10); the function-scoped fixture stays for the per-test home (TST-B7, TST-B8).
- Why this design, `stats forget`: the writers of the stats files take no lock today (`append_jsonl` is a bare `O_APPEND`), so a size check cannot make a replace safe. The writers (`on_run_exit`) and the verb take the same exclusive-create lock `rows._locked` that the machine index already uses, one lock per stats file, held by the verb across its read and replace (CST-B23). The verb rewrites both stats files first and writes the index last (CST-B22), and refuses `--month` with exit 2 (CST-B24, the default of the triage note).
- Tests of the installed route use a stand-in for an installed engine: a folder holding only a `.dist-info` with an `entry_points.txt` read from the engine's `pyproject.toml`, put on `PYTHONPATH`. `importlib.metadata` finds it as pytest finds a pip-installed distribution, so the entry-point route itself is exercised without a network or a pip install; the code report says this is what the test covers and what it does not (the build of the wheel).
- The environment's own editable install, when it has one, registers the entry point as it was at install time. After the pyproject row the code step runs `python -m pip install -e '.[dev]'` in the engine folder, so that a registration of the removed module `tempergraph.pytest_plugin` does not stop every pytest start with an import error. Tests use the stand-in and do not depend on it.
