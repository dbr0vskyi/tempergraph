# Hand-off: i201

## Problem

A judge's changed paths were every path that differs from its visit's entry commit, so a notes file that every judge opens, files a command generated, a deleted file and a name git prints quoted all took part in `changed_total` and `changed_read`; `judge_unread_pass` could not fire for a workflow whose steps write a notes file, and a base that git does not hold counted as "nothing changed". For a map the last item's judgement stood for every item's judge, and the read-share criteria were proved on a hand-written journal. The specs now say which paths a judge's counts cover, what the judge's record holds about the commit it counted from, how a map's judgements are read, and that the thresholds keep their value and comparison; each criterion is a fixture run of the engine.

## Open questions

- Where does `judge_may_skip` live, and is its name right? The task says "on the gate's judge" and also refuses "a pattern on a gate with no judge", which cannot arise for a field of the judge. Options: a) a field of the gate, `judge_may_skip` (as written in WFM-B14); b) a field of the judge, with the "no judge" refusal dropped from WFM-B14; c) the gate field under another name. Until answered: a.
- Should `changed_left_out` also count the paths that a declared file artifact leaves out? Options: a) the gate's patterns only (as written in SRV-B43; the task asks how many paths "the rule" left out, the rule being the gate's patterns); b) both, as one number. Until answered: a.
- How is a judge session's `agent_run` record with no `changed_base` key read? The re-ask session of a judge (`judge_reask`, `plugins/tempergraph/engine/src/tempergraph/run/nodes.py` lines 1757-1763) passes no extra record keys, so its record carries neither `changed_paths` nor `changed_base`, and its digest holds `changed_total` 0 today; a record written before the key existed has none either. SRV-B38 speaks of a null `changed_base` only. Options: a) a record with no key is read as it was counted, its `changed_paths` giving `changed_total` (0 for a re-ask); b) it is read as a null base, with no `changed_total`. Until answered: a. The judge node is shared with the task that changes the re-ask.
