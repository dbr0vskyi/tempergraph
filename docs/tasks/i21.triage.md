# Triage: i21

## Task

`batch-queue/tasks/i21.md` (GitHub issue #21): step and judge sessions must be offered no MCP server they do not declare. A live probe of 2026-11-25 showed that the account's claude.ai connectors reach a step session (about 165,000 tokens of tool definitions). Area: the engine, which names no workflow.

## Acceptance criteria

1. Every step launch, and every retry of one, passes `--strict-mcp-config`, with `--mcp-config` only when the step declares an MCP tool, so a session is offered no MCP server of the account, the user or the repository that its step does not declare.
2. A step that declares an MCP tool is still offered that server's tools.
3. Every judge launch passes `--strict-mcp-config` too, and a judge with MCP views still gets its views.
4. The environment of a step and a judge session carries `ENABLE_CLAUDEAI_MCP_SERVERS=false`.
5. The spec `executor-claude-code` states the behaviour as a rule of the launch, and its acceptance criteria are proved by argv and environment tests of a step, a retry and a judge launch.
6. The engine's live-checks runbook has a new probe row for this (a P-CC row), with the result of 2026-11-25 above recorded in its results table as the operator's live run.
