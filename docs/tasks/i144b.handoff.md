# Hand-off: i144b

## Problem

The first run's isolation plugin and `stats forget` passed their gates; an independent review then found a blocking defect and smaller ones. Five of them are gaps in two specs: the isolation says nothing about code that runs outside the tests, about an environment where the engine is installed, about how a person switches it off, or about which copy of the engine a suite run tests; `stats forget` states neither the order of its two writes, nor a row appended while it runs, nor `--month`; and a scenario of CST-B8 contradicts CST-B17. Each is now stated in the spec that owns it. Code, tests and the plugin's design are the plan's.

TST-B7 and TST-B8 stay the per-test rules. Task criterion 2. Read: the plugin is one function-scoped autouse fixture, so wider code sees the real environment.

Task criterion 4 (first half) and, through TST-AC15, task criterion 5.
- G3: `plugins/tempergraph/docs/specs/test-suite.spec.md` (TST-B12, TST-AC17, TST-AC18): the suite tests the engine code of the checkout it runs from, in one process and on workers, whatever other copy of the engine is installed. Task criterion 1.

## Decisions

- Owner decisions of the triage note: none listed (`None`), so none answered and none defaulted. The conversation value and the owner's answers arrived as unfilled placeholders, so no pause is assumed and nothing below waits on an answer.
- `--month`: the task allows refusing or honouring it; the triage note takes the refusal as the default (it changes least and is cheapest to undo) and this step follows it. CST-B24 refuses with exit 2 (CON-B13), the form `IndexInUse` already takes in the CLI. The verb also ignores its other reader options (`--source`, `--local`, `--sync`, `--since`, `--by`, `--projection`, `--live`); the task names only `--month`, so no behaviour is written for them.
- The name a person types after `-p no:` is the entry point's registered name `tempergraph.pytest_plugin` (the key under `pytest11` in the engine's `pyproject.toml`), the name in use today; TST-B11 states it. A plugin module moved outside the package to fix the blocking defect should keep the entry point under that name. If the plan has to change the name, it changes TST-B11, TST-AC16 and the Purpose of `test-suite` in the same change.
- "Installed" is read as: the engine is installed in the environment (an editable install included), so that its entry point registers the plugin. An engine reachable only through `PYTHONPATH` is outside TST-B7 to TST-B11; the first run's tests reach the plugin there by naming it with `-p`, and the specs say nothing about that route. TST-AC15 is the criterion of the installed route, which task criterion 5 asks one test (or a reason) for.
- TST-B9 and TST-B10 are two behaviours, as TST-B7 and TST-B8 are: each states one result. "Each test its own inside it" is stated as the third scenario of TST-B9 (a test's home differs from the home that code outside the tests sees); "inside" is how a plan builds it and is not stated.
- The month of `stats forget` stays the month in which it runs (UTC), as the first run's hand-off decided; CST-B24 follows from CST-B18.
