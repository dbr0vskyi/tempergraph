# Review: i203a

## Findings

1. `tempergraph.regenerations.json:5` blocking: the declared commands are `tempergraph author verify <path>` with no `--json`, and without that flag `author verify` prints plain text (`cli/author.py:245-255`), so `findings_of` in `workflow/temperspec/regeneration.py` finds no JSON line and falls back to one finding made of the last 40 lines of output. In this repository a failed regeneration of a package therefore never comes back as one numbered finding per rung finding (criterion 5, RGF-B1, RGF-B3). The tests that prove RGF-B3 feed JSON directly, and the worktree test runs `python -m tempergraph author verify` without `--json` and only checks PASS, so none covers the repository's real declaration.
2. `plugins/temperspec-tgraph/tests/test_spec_budget_and_moved_ids.py:297` blocking: the change removes the assertion `stamp["outcome_revision"] == o["revision"]`, while `outcome.json` goes to revision 25 and `plugins/temperspec-tgraph/stamp.json:104` still says 24. The check was dropped so that a stale stamp passes, which weakens an existing test. The stamp's digests are stale too, and no `authoring.json` is among the changed files (criterion 10).
3. `plugins/temperspec-tgraph/workflow/temperspec/regeneration.py:174` not blocking: `changed_paths()` returns `[]` when `run_base` finds no run commit (`review.run_base`). The unit then passes with nothing run and gives no sign that the base was not found, so a run whose commit subjects do not match `RUN_COMMIT` skips every regeneration without a trace.
4. `plugins/tempergraph/engine/src/tempergraph/author/verify.py:186` not blocking: `_name_of` takes a `caps` parameter it never uses.
