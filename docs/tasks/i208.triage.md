# Triage: i208

## Task

`batch-queue/tasks/i208.md` (GitHub issue #208): the loop's filing is on by default, a dry run becomes its own run setting `loop_dry_run` with the arguments `--dry-run` and `--no-dry-run` on `run` and `resume`, `--no-dry-run` wins over a declared autonomy `record` for one run, and `loop_summary` and `status` say what was in force.

## Acceptance criteria

1. A workflow that declares nothing about filing, run with no argument, files; a test proves it at mode `dev` and at mode `stable` against the memory code host, and no code path reads the mode to decide a dry run.
2. `loop_dry_run` is in the settings catalog at scope `run` with the values true and false and the default false; `config show` prints its value and the layer it came from. Any other value is refused before any spend, in the same words on `run` and `resume`.
3. A workflow that declares `loop_dry_run` true writes `would_file` results with titles, and makes no issue and no comment, at every final exit of its threads; the same holds when a settings file sets it. A fixture run proves both.
4. `run --help` and `resume --help` list `--dry-run` and `--no-dry-run`; each is recorded as the flag `run.loop_dry_run`, and a call that gives both is refused before any spend.
5. The argument overrides in both directions: a thread of a workflow that declares a dry run, started with `--no-dry-run`, files; a thread of a workflow that declares nothing, started with `--dry-run`, files nothing. A fixture run proves both.
6. The value given last wins: a thread started with `--dry-run` and resumed with `--no-dry-run` files at its final exit, and the reverse files nothing. A resume that gives neither keeps the value the thread holds, and `resume --unset run.loop_dry_run` returns the thread to the declared value.
7. A thread started before this change, whose log has `run_started` with `dry_run` and no value of the setting, is a dry run until a later call gives `--no-dry-run`.
8. `run_started` holds `dry_run` when the value in force for that segment is a dry run, from any source, so the counts of real runs (PRO-B8) leave out a run that a declared setting made dry.
9. A thread of a workflow that declares autonomy `record`, started or resumed with `--no-dry-run`, files its findings on the memory code host; a second thread of the same workflow with no argument files nothing and records the reason `autonomy_record`; the package's `tempergraph.json` is unchanged. The thread with the argument proposes nothing and runs no trial.
10. The hold wins over the argument: with `loop_autonomy` set to `record` in a settings file before the final exit, or `TEMPERGRAPH_AUTONOMY=record`, a thread started with `--no-dry-run` makes no issue and no comment and records each decided finding with the reason `autonomy_record`.
11. The `loop_summary` record holds what was in force at the exit: `filing` (one of `file`, `dry_run`, `held`) and `filing_source` (one of `default`, `workflow`, `settings`, `argument`, `machine_hold`, `declared_record`). A test proves each of the six sources on a fixture thread, and the thread of criterion 9 that files has `file` and `argument`.
12. `status` shows the same two words for a thread's latest final exit, in its text and in `--json`.
13. A finding of an exit that ran dry is handed again at the thread's next final exit, as SIL-B47 says today; the test of that behaviour covers a dry run that came from the declared setting.
14. `docs/guides/improving-workflows.guide.md` states the whole rule in one section: the default, the declared setting, the two arguments, that `--no-dry-run` files for one run of a workflow that declares `record`, the hold and their order, and that the mode has no part in it. A test asserts the sentences the guide must hold.
15. The specs changed by this run state what the code does without naming any workflow and stay within the spec budget. Each new test carries the id of the spec criterion it proves, and the tests of runs i171b and i170c still pass, changed only where a criterion above changes the fact they assert.

## Intent

- Goal: an operator gets a loop that files by default, with a dry run that is an ordinary run setting (declarable, settable in files and profiles, overridable per run in both directions), and can see afterwards whether an exit filed, ran dry or was held and why. One run may file even where a workflow declares `record`, without changing that workflow.
- In scope: the `loop_dry_run` setting in the catalog; `--dry-run` and `--no-dry-run` on `run` and `resume` as spellings of `--set run.loop_dry_run=…`; the argument-only override of a declared `record`; precedence with the machine-wide hold; `filing` and `filing_source` in `loop_summary` and in `status`; reading old threads; `run_started` `dry_run` from any source; the guide section; spec edits and tests.
- Out of scope (the task's own list): anything the mode decides; re-reading `loop_dry_run` from the settings files at each final exit; the engine's own dry runs (trials, eval suites, authoring trials); changing a package's declared level or raising a run above `file` by argument; removing `TEMPERGRAPH_AUTONOMY`; reviewing or sending the filing outbox; what a `would_file` row shows beyond its title; the body of an issue (#210) and findings about a failed judge (#209). No file of a workflow package changes.
- Assumptions:
  - A1: the default autonomy of `file` already holds (the task says so). If wrong: criterion 1 needs a code change the task does not list.
  - A2: `--no-dry-run` given on `resume` lifts a declared `record` for that thread, as criterion 9 says "started or resumed". If wrong: a resume argument would not override `record` and criterion 9's resume half fails.
  - A3: `filing_source` `declared_record` names an exit held at `record` because the workflow declares it, and `machine_hold` one held by `loop_autonomy` or `TEMPERGRAPH_AUTONOMY`. If wrong: the six-source test measures a different split.
  - A4: the new `loop_summary` fields are added to the existing record without a schema version change (CON-B14 tolerant read). If wrong: a version bump touches readers.
