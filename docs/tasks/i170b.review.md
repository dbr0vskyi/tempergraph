# Review: i170b

## Findings

1. `plugins/tempergraph/engine/src/tempergraph/run/runner.py:1187` not blocking: `take_pause_mark` deletes the pause marker as soon as it is read, before `attach_workspace` has succeeded. When the attach refuses (branch missing or checked out elsewhere) the person fixes it and resumes again, and the second resume has no marker. It then falls back to the old `last_head` and status comparison, which reports the run's own uncommitted files as `external_change`. That is the false "changed" WTR-B28 removes. The marker could be removed after the attach succeeds.
2. `plugins/tempergraph/engine/src/tempergraph/workspace.py:524` not blocking: the comparison with the pause marker uses porcelain status lines only. A person who edits a file the run had already left modified (the line stays ` M path`) or who edits a file the run had already left untracked (`?? path`) between the pause and the resume gives equal head and equal status lines. That resume is recorded `reused`, so the judge is told "workspace unchanged". WTR-B28 says the head or the status differs, so this follows the spec, but it should be written as a known limit or the marker should hold a digest of the dirty files.
3. `plugins/tempergraph/engine/tests/test_workspace.py:1378` not blocking: the WTR-AC15 test covers `attach_workspace` with a hand-written marker, and the end-to-end fixture (a step that commits, then pause and resume) is in `test_pause_findings_at_final_exit.py`. No test covers a resume of an older thread that has no marker file, which takes the unchanged fallback path in `attach_workspace`.
