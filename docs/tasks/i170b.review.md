# Review: i170b

## Findings

1. `plugins/tempergraph/engine/src/tempergraph/run/runner.py:1187` not blocking: the pause marker is read and deleted by `take_pause_mark` as an argument of `attach_workspace`, before the attach or any later refusal in `_resume`. If the resume is then refused and the person resumes again, the second resume has no marker and falls back to the old comparison, which reports the run's own commits and uncommitted files as a workspace change.
2. `plugins/tempergraph/engine/src/tempergraph/workspace.py:524` not blocking: with a marker, "unchanged" means the head and the sorted `git status` lines are equal. A person's edit to a file the run had already left modified or untracked gives the same status line, so the resume is recorded as `reused` and the fact says "workspace unchanged". This follows WTR-B28 as written, but the limit is not stated in the spec.
3. `plugins/tempergraph/engine/src/tempergraph/improve/pause_facts.py:48` not blocking: a finding line without `segment_started` (a thread recorded before this change) is matched to its segment by the second of its `at` equalling the second of the segment's `run_exit`. `at` is taken in `record_exit` after the exit record and the digests are written, so the two often differ by a second or more. Such a line then gets no row, where the earlier code gave it one.
4. `plugins/tempergraph/engine/src/tempergraph/improve/pause_facts.py:77` not blocking: the answering decision is the first intervention of the paused unit after the pause time, with no check of the item. In a map that pauses at several items of one unit, an answer to another item can be read as the answer to this pause.

## Earlier review

1. `plugins/tempergraph/engine/src/tempergraph/run/runner.py:1187` not blocking: `take_pause_mark` deletes the pause marker as soon as it is read, before `attach_workspace` has succeeded. When the attach refuses (branch missing or checked out elsewhere) the person fixes it and resumes again, and the second resume has no marker. It then falls back to the old `last_head` and status comparison, which reports the run's own uncommitted files as `external_change`. That is the false "changed" WTR-B28 removes. The marker could be removed after the attach succeeds.
2. `plugins/tempergraph/engine/src/tempergraph/workspace.py:524` not blocking: the comparison with the pause marker uses porcelain status lines only. A person who edits a file the run had already left modified (the line stays ` M path`) or who edits a file the run had already left untracked (`?? path`) between the pause and the resume gives equal head and equal status lines. That resume is recorded `reused`, so the judge is told "workspace unchanged". WTR-B28 says the head or the status differs, so this follows the spec, but it should be written as a known limit or the marker should hold a digest of the dirty files.
3. `plugins/tempergraph/engine/tests/test_workspace.py:1378` not blocking: the WTR-AC15 test covers `attach_workspace` with a hand-written marker, and the end-to-end fixture (a step that commits, then pause and resume) is in `test_pause_findings_at_final_exit.py`. No test covers a resume of an older thread that has no marker file, which takes the unchanged fallback path in `attach_workspace`.
