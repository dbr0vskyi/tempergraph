# Review: i170b

## Findings

1. `plugins/tempergraph/engine/src/tempergraph/improve/pause_facts.py:81` not blocking: the decision is the first ledger row for the paused unit at or after the pause's time, with no upper bound at the segment's end or at the next pause. A pause with no recorded answer can pick up a later answer to a later pause at the same unit and show it as that pause's decision, caller and touch.
2. `plugins/tempergraph/engine/src/tempergraph/run/runner.py:1187` not blocking: `take_pause_mark` deletes the marker as soon as the resume reads it. If the resume dies before the next pause or exit, nothing is left to compare with, and the next resume falls back to the old `last_head` comparison (`workspace.py:535`), which the change was meant to replace. The marker is also written only after `run_exit`, so a kill between the two leaves no marker.
3. `plugins/tempergraph/engine/src/tempergraph/improve/issue_context.py:64` not blocking: `log_lines` and `environment` (line 103) take a `facts` parameter that they never use. The docstrings say it is "accepted for the same call shape". This is dead surface.
4. `plugins/tempergraph/engine/tests/test_pause_findings_at_final_exit.py:481` not blocking: the guide test looks for any paragraph that holds "final exit" and "exit 5", then checks for the substrings "exit 0", "exit 4" and "exit 5". It does not check that each exit SIL-B9 makes final is listed (the stop-by-request and attempt-cap reasons, the lost runner), so criterion 9's guide clause is only loosely proven.
5. `plugins/tempergraph/docs/specs/runs-without-a-final-exit.spec.md:26` not blocking: the sentence of SIL-B37 asks for eight results in one `WHEN … SHALL` (reason, decision, caller kind, feedback, ruling, touch class, workspace change, next gate), which goes against the spec rule "one behaviour, one result". The row is the single observable result, but the sentence is close to the 500-character limit.

## Earlier review

1. `plugins/tempergraph/engine/src/tempergraph/improve/issue_context.py:156` blocking: the facts line written under `## Run` of an issue or comment holds only pause reason, decision, ruling, touch, workspace and next gate. It leaves out the paused unit and item, the caller kind and whether feedback was given, which criterion 7 (the facts line of criterion 1) and ISS-B15 and its first GIVEN require. The test `check_paused_context` asserts only `unresolved_gap` and `next_gate=none`, so the gap is untested. Visit: built
2. `plugins/tempergraph/engine/src/tempergraph/improve/issue_context.py:160` blocking: `_facts_line` passes each value through `_safe`, and `SAFE` (line 19) rejects a comma. A decision that touched two classes (`stop` on an escalation gives `rescue,steer`, SIL-B43) therefore has its `touch=` fact silently dropped from the issue and comment body, though it is told to the judge. Visit: built
3. `plugins/tempergraph/engine/src/tempergraph/improve/causes.py:262` blocking: `classes[...]` is overwritten by each decision of the same unit and cause in a segment, while `add` merges their counts. If one agent other than the starter and then the starting caller both rescue the same unit and cause, the last decision wins and the finding becomes `designed`. That hides a fault of another agent from the judge and from filing, against FRC-B6 ("a decision by another agent still yields the fault"). The class should be `fault` if any decision of the group is not the starter's. Visit: built
4. `plugins/tempergraph/engine/src/tempergraph/workspace.py:524` not blocking: the resume compares the head and the sorted `git status` lines. A file already dirty at the pause that a person edits further keeps the same status line (` M file`), so the resume records `reused` and not `external_change`. The marker holds no content digest.
5. `plugins/tempergraph/engine/src/tempergraph/improve/pause_facts.py:66` not blocking: a finding whose segment has no `pause` record gets no row even when a decision or a gate is recorded for it. Criterion 1 says no row only when no pause, no decision and no gate is recorded. In `of`, `answers[0]` (line 81) takes the first later decision of the unit with no upper bound at the next pause, so an unanswered pause can be given a later pause's decision.
6. `plugins/tempergraph/engine/src/tempergraph/improve/child.py:425` not blocking: `listed` is built from `segment_started` only. Findings written before this change have none, so their earlier paused segments get no section in the prompt (criterion 6), while `pause_facts._own_segment` has a fallback by `at` for them. The two readers disagree on old findings.
