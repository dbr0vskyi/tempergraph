# Hand-off: i141

## Problem

The monitor mod runs engine verbs through `tempergraph` on `PATH` or through the `engine_path` option, so an engine installed without the `PATH` change (its shim only in the engine home) shows as not installed, and the pane names no place it looked at. The task asks the mod to try the option, then `PATH`, then the engine home, and to say the engine is not installed only when all three fail, naming what it looked at. The documents now state the order, the engine home, the option's validation, the not-found result and the pane text; no code, test, configuration or plan was touched.

How the task's criteria map to the documents:

## Decisions

- The triage note lists no owner decision (`Owner decisions: None`). The run's conversation setting and its answers file arrived as unfilled placeholders and the run made no pause, so nothing waited on an answer.
- The order is the task's: the option, then `PATH`, then the engine home (criterion 3). A place that exits 127 is passed over and the next is tried, because criterion 2 lets the pane say "not installed" only when all three fail.
- The setting's meaning (where the monitor looks, what a refused value does) is in `actions-and-safety.spec.md`, and what happens when no place holds the engine is in `data-sources.spec.md`, as the owners in the triage rows name them. The setting's validation was stated only as a build note in `data-sources.spec.md`; it moved into MAC-B7 so the rule lives in one place.
- The monitor's design set stays in the earlier layout: the spec rule says to leave an earlier layout as it is when a spec is edited, the structure check reads such a spec for no form, and the monitor overview's own criterion keeps its specs in the six-section layout. A new spec would have to use the current layout and so break that set, and the rules sit with the specs that own them, so no new spec was written. The new behaviours are `Given … when … then …` paragraphs and the criteria are `MAC-AC-<n>` and `MDS-AC-<n>` list items, as their neighbours.
- No decision record and no research note: no gap asked for one. How the mod learns the engine home (the environment, the home folder) is not in any monitor document; it is the plan's to settle (see the reading list).

## Open questions

None blocks planning; each has the default the documents use.

- The error row of `data-sources.spec.md` says polling stops "until the session restarts or the person runs the installer". The code only restarts: `register.tsx` marks the engine not installed at line 91, nothing marks it installed again (the only `installed: true` is the atom's first value, line 42), and `tick` returns at line 269 while it is marked; no test pins either reading. MDS-B6 says only that polling stops, and the row keeps its last clause as it was. Options: (a) leave both as they are, the clause staying unconfirmed; (b) reword the row to "until the session restarts", with no code change; (c) make the monitor look for the engine again at the idle rate (every 30 s) after it was marked not installed. Until answered: (a). A candidate issue.
- The prompt fills name `tempergraph` bare: the stop fills are built as `!tempergraph stop …` (`plugins/tempergraph-monitor/hooks/lib/actions.ts`, lines 42-43) and the resume fill must start with the engine's printed `tempergraph resume` line (line 27). With the engine only in the engine home, the person's shell may not find the command a fill holds, though the monitor now reads the runs. The task's four criteria do not ask for it. Options: (a) leave the fills as they are, the person's shell deciding; (b) the stop fills name the program the monitor found, the resume fill keeping the engine's line; (c) both name it. Until answered: (a). A candidate issue.
