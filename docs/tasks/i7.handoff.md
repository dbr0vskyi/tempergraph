# Hand-off: i7

## Problem

The session review's money cap is the lower of the run share and the per-run cap and, in stable mode, of the day's room under SIL's daily cap. A run with a small cost therefore gets a cap below the price of one review, and the review skips its only target as `skipped: budget`. The spec had no rule for a cap that cannot pay for one review and no term for the session the task calls "most signalled". SRV-B33 now lifts the plan's `cap_usd` to the estimate of the review of its first target, the one SRV-B24 puts first; in stable mode SIL's daily cap still lowers it (owner decision G3, default taken).
