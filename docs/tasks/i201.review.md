# Review: i201

## Findings

1. `plugins/tempergraph/engine/tests/test_judge_read_share_privacy.py:45` not blocking: the `loop.jsonl` check passes on an empty string when the file is absent, and the fixture sets `session_review="off"`, so the loop may never write that file. If so, criterion 8's `loop.jsonl` leg proves nothing. The test could assert the file exists, or run a review that writes it.
2. `plugins/tempergraph/engine/tests/test_judge_read_share.py:243` not blocking: the run-level test for an entry commit that git does not hold (SRV-AC33) checks the judge's record only. It does not check that the digest has no `changed_total` or that no finding is made, which criterion 4 names for that fixture. Those two checks exist only in `test_session_review.py:151`.
3. `plugins/tempergraph/engine/tests/test_session_review.py:151` not blocking: the SRV-AC34 test builds its judge journals by hand with `session(...)`. Criterion 6 says no test of this spec writes a judge journal by hand. `test_causes_read_each_items_own_judgements` at line 175 (SRV-AC42) does the same.
4. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:86` not blocking: `_skip_match` uses `fnmatchcase` on the normalised pattern, so `[` and `?` act as wildcards. A pattern with a trailing slash such as `dist/` becomes `dist` and matches no file under it. Neither is stated in SRV-B42 or WFM-B14.
5. `plugins/tempergraph/engine/src/tempergraph/api.py:162` not blocking: `Gate(judge_may_skip="dist*")` takes a string as an iterable of characters. Validation catches `/` and `..` characters but not a lone `*`, and a `*` pattern leaves every path out of the judge's count. Rejecting a bare string would prevent this.
6. `plugins/tempergraph/engine/src/tempergraph/git.py:295` not blocking: `rel in found` scans a list for each path, which is quadratic when `judge_changed_paths` is called with a limit of 100000 on a tree with many untracked files. A set beside the list would avoid it.
7. `plugins/tempergraph/engine/src/tempergraph/improve/digest.py:445` not blocking: a map item with no judgement record of its own falls back to the bare unit's record. For a map whose join gate records a judgement without an item, an item whose judge left no record would be judged by that record's `passed`, which SRV-B44 rules out.
8. `plugins/tempergraph/engine/tests/test_judge_read_share.py:183` not blocking: the second half of the deleted-path test runs a second task in the same repository and expects `changed_total` 1. That holds only if each run works in its own worktree and leaves nothing untracked behind. The test does not state this, and `worktree prune` suggests it was needed to make the run pass.

## Earlier review

1. `plugins/tempergraph/engine/tests/test_judge_read_share.py:243` not blocking: criterion 4 asks that an entry commit git no longer has gives null and no finding, and criterion 6 asks that no test of this spec writes a judge journal by hand. Criterion 6 says the fixtures of criteria 4 and 5 are proved by a fixture run with the stand-in. The run-level map tests in `test_judge_read_share.py` cover SRV-B44, but this unit test is still a hand-made journal.
3. `plugins/tempergraph/engine/tests/test_judge_read_thresholds.py:47` not blocking: the parameters `[2, 3, 3, 4, 8, 10, 10]` are counts that include the notes file. The counted paths are therefore 1, 2, 2, 3, 7, 9, 9. SRV-AC45 in the spec says "one, four and nine other changed paths", and the fixture does not produce a case with four. Duplicate parameter values (3, 3 and 10, 10) run the same case twice.
4. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:86` not blocking: `_skip_match` uses `fnmatch.fnmatchcase`, so `[` and `?` in a `judge_may_skip` pattern act as wildcards or character classes. SRV-B42 names only `*` and `**`. `posixpath.normpath` also turns a trailing-slash pattern such as `dist/` into `dist`, which matches no file under it. Validation in `validate.py` does not refuse either form.
5. `plugins/tempergraph/engine/src/tempergraph/git.py:295` , not blocking: `rel in found` scans a list for each candidate, and each candidate also gets an `exists()` call. `_judge_count` calls this with a limit of 100000. The old count was capped at 500 paths. A workspace with tens of thousands of untracked files makes the scan quadratic. Use a set beside the list.
6. `plugins/tempergraph/engine/src/tempergraph/api.py:162` not blocking: `tuple(judge_may_skip)` turns a bare string such as `"dist/**"` into one-character patterns. Validation accepts these, so the declaration does nothing and no error says so.
7. `plugins/tempergraph/engine/src/tempergraph/author/blueprint.py:52` not blocking: `GATE_KEYS` leaves out `judge_may_skip`, so a blueprint cannot state the new gate field. I did not check how the scaffold or compare code treats a gate that declares it.
8. `plugins/tempergraph/engine/src/tempergraph/improve/digest.py:445` not blocking: when no judgement is recorded for `unit.item`, the digest of a map item falls back to the bare unit's record. That record belongs to the map's join gate, so its pass or fail is read as the item's. The record exists whenever the item's judge ran to the end, so this affects only an item judge cut short.
9. `plugins/tempergraph/engine/tests/test_judge_read_share.py:183` not blocking: the second half of `test_two_deleted_paths_and_one_added_leave_one_and_a_rewritten_path_counts_once` assumes the second run starts from a worktree of its own at the committed tip. It neither states that nor checks it. The `worktree prune` call does not establish it.
