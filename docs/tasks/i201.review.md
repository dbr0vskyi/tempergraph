# Review: i201

## Findings

1. `plugins/tempergraph/engine/tests/test_judge_read_thresholds.py:1040` not blocking: criterion 9 (task AC 7) fixes the seven notes-only sessions as "two, three, three and four changed paths in all" and AC45 as "one, four and nine other changed paths". The test parametrizes `n` as the number of files written, notes file included, so the counted paths are 1, 2, 2, 3, 7, 9, 9. The shapes still all give `judge_unread_pass`, but they are not the review's shapes as the criterion states them, and no fixture has four other changed paths.
2. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:466` not blocking: `_skip_match` hands the pattern to `fnmatch`, so `[`, `]` and `?` in a `judge_may_skip` pattern act as character classes and wildcards. SRV-B42 and WFM-B14 say only that `*` and `**` cross directories. A path name with `[` in it cannot be matched literally, and the spec does not say so.
3. `plugins/tempergraph/engine/src/tempergraph/settings.py:261` not blocking: `VERIFICATION` lists the unit fields that no setting may change because they decide what verifies the work. `judge_may_skip` narrows what a judge is held to open and is not in that set. I did not trace whether a setting can reach it, but if one can, it would loosen the judge check without the guard the other judge fields have.
4. `plugins/tempergraph/engine/src/tempergraph/author/blueprint.py:48` not blocking: the authoring path's list of gate fields does not include `judge_may_skip`. A workflow authored from a blueprint cannot declare the new field, and neither the criteria nor the spec say whether that is intended.
5. `plugins/tempergraph/engine/tests/test_judge_read_share.py:776` not blocking: the second half of `test_two_deleted_paths_and_one_added_leave_one_and_a_rewritten_path_counts_once` starts a second run (`S-8`) in the same repository after run `S-7`, using `git worktree prune`. It passes only if run `S-7`'s `new.md` and deleted `t1.md` do not carry over into `S-8`'s workspace. That holds only if every run gets an isolated worktree, and the test does not state it or check it.

## Earlier review

1. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:1682` blocking: `_declared_files` looks up the `produces` key as it is (`key not in values`), but a map unit stores its artifacts per item as `key[item]` (`run/mapping.py:116`) and holds the plain key only once the map has joined, and then only for the last item (`nodes.py:1095-1099`). The judge of a map item therefore never leaves that map's declared file artifacts out of `changed_total` and `changed_read`. This is a wrong count for a declared file artifact, which SRV-B41 and criterion 1 say no judge counts. No test covers a map unit with a file artifact. Visit: built
2. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:88` not blocking: `fnmatch.fnmatchcase` also treats `?` and `[...]` as wildcards, but SRV-B42 names only `*` and `**`. A pattern with a bracket, or one with a trailing `/` (`posixpath.normpath` drops it, so `dist/` matches nothing), skips different paths than the spec describes.
3. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:1699` not blocking: any exception from `base_problem` (for example a git timeout) is recorded as `outside_repository`. That reason is wrong for a workspace inside a repository.
