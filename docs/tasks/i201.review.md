## Findings

1. `plugins/tempergraph/engine/tests/test_judge_read_share.py:243` not blocking: criterion 4 asks that an entry commit git no longer has gives null and no finding, and criterion 6 asks that no test of this spec writes a judge journal by hand. This run-level test checks only `changed_base`, the reason and the empty path list. It does not read the digest or the findings. The "no `changed_total`, no finding" half is proved only by `test_a_null_changed_base_gives_no_count_and_no_finding` in `test_session_review.py`, which builds its journals with the hand-written `session(...)` helper.
2. `plugins/tempergraph/engine/tests/test_session_review.py:175` not blocking: `test_causes_read_each_items_own_judgements` (SRV-AC42) uses the same hand-written `session(...)` journals. Criterion 6 says the fixtures of criteria 4 and 5 are proved by a fixture run with the stand-in. The run-level map tests in `test_judge_read_share.py` cover SRV-B44, but this unit test is still a hand-made journal.
3. `plugins/tempergraph/engine/tests/test_judge_read_thresholds.py:47` not blocking: the parameters `[2, 3, 3, 4, 8, 10, 10]` are counts that include the notes file. The counted paths are therefore 1, 2, 2, 3, 7, 9, 9. SRV-AC45 in the spec says "one, four and nine other changed paths", and the fixture does not produce a case with four. Duplicate parameter values (3, 3 and 10, 10) run the same case twice.
4. `plugins/tempergraph/engine/src/tempergraph/run/nodes.py:86` not blocking: `_skip_match` uses `fnmatch.fnmatchcase`, so `[` and `?` in a `judge_may_skip` pattern act as wildcards or character classes. SRV-B42 names only `*` and `**`. `posixpath.normpath` also turns a trailing-slash pattern such as `dist/` into `dist`, which matches no file under it. Validation in `validate.py` does not refuse either form.
5. `plugins/tempergraph/engine/src/tempergraph/git.py:295`, not blocking: `rel in found` scans a list for each candidate, and each candidate also gets an `exists()` call. `_judge_count` calls this with a limit of 100000. The old count was capped at 500 paths. A workspace with tens of thousands of untracked files makes the scan quadratic. Use a set beside the list.
6. `plugins/tempergraph/engine/src/tempergraph/api.py:162` not blocking: `tuple(judge_may_skip)` turns a bare string such as `"dist/**"` into one-character patterns. Validation accepts these, so the declaration does nothing and no error says so.
7. `plugins/tempergraph/engine/src/tempergraph/author/blueprint.py:52` not blocking: `GATE_KEYS` leaves out `judge_may_skip`, so a blueprint cannot state the new gate field. I did not check how the scaffold or compare code treats a gate that declares it.
8. `plugins/tempergraph/engine/src/tempergraph/improve/digest.py:445` not blocking: when no judgement is recorded for `unit.item`, the digest of a map item falls back to the bare unit's record. That record belongs to the map's join gate, so its pass or fail is read as the item's. The record exists whenever the item's judge ran to the end, so this affects only an item judge cut short.
9. `plugins/tempergraph/engine/tests/test_judge_read_share.py:183` not blocking: the second half of `test_two_deleted_paths_and_one_added_leave_one_and_a_rewritten_path_counts_once` assumes the second run starts from a worktree of its own at the committed tip. It neither states that nor checks it. The `worktree prune` call does not establish it.
