# Hand-off: i150

## Problem

When the outcome judge grades `ts-spec-sync` PARTIAL or UNMET and names no place, the engine sends the run back to the earliest step of the run's path that has a criterion serving it, which is the setup step or the triage step, so one sentence of a spec costs a whole run. No package spec states where a failing judged final criterion goes, or what the step it goes back to is told. The outcome gate spec now states both for the two criteria the judge grades (`ts-spec-sync`, `ts-accepted`), and the decision record `ts-spec-sync` agrees with it.

So "how its outcome gate names the place of the defect" cannot route a run by itself, and the package changes the serving instead.
