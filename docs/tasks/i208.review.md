# Review: i208

## Findings

1. `plugins/tempergraph/engine/src/tempergraph/run/runner.py:380` not blocking: a thread that has `dry_run` in its meta and in its log but no row for `run.loop_dry_run` stops being dry as soon as any layer gives the key a value that is not `true` (a workflow declaring `loop_dry_run` false, or a settings file setting it false). The thread is then no longer dry until a call gives `--no-dry-run`, which is what criterion 7 and LFS-B3 say. LFS-B3 says "no row for the setting" in the log, so the case is arguably covered, but the first scenario of LFS-B3 does not name it and no test covers it.
2. `plugins/tempergraph/engine/src/tempergraph/run/runner.py:604` not blocking: `lift` is true for any `false` on the flag layer, so `--set run.loop_dry_run=false` lifts a declared `record` the same way `--no-dry-run` does. The guide (`improving-workflows.guide.md`) and criterion 9 name only `--no-dry-run`, and LFS-B4 says "from the flag layer". The two do not match, and no test shows the `--set` case.
3. `plugins/tempergraph/engine/src/tempergraph/cli/main.py:405` not blocking: `--dry-run` or `--no-dry-run` silently replaces a `--set run.loop_dry_run=...` given in the same call, with no refusal and no word in ROP-B15. Both options are written to the same flag-layer key.
