Monitor finds the engine at its default shim path when it is not on PATH (GitHub issue #141)

The monitor mod (`plugins/tempergraph-monitor`) runs the engine's read-only verbs through the program `tempergraph` from `PATH`, unless its `engine_path` option names the shim. With the engine installed without the `PATH` change (`tempergraph install` without `--add-to-path`), the shim is only at `~/.tempergraph/bin/tempergraph`, and the monitor pane said "tempergraph is not installed here" while two runs were live in the repository. A Claude Code session that was open before an install with the `PATH` change has the old `PATH` and shows the same. Setting `engine_path` by hand fixed it. Monitor spec `actions-and-safety` (the options table) says `engine_path` is the path to the shim, or empty for `PATH`; nothing says what happens when the engine is installed and `PATH` does not hold it, and the pane's message is then false.

The mod's own tests are of two kinds: session tests (`tests/*.test.tsx`), run by `claude plugin test plugins/tempergraph-monitor`, which this repository declares as a verification command; and model tests (`tests/*.spec.ts`), run by `bun`, which is not installed on this machine and is not a declared command. A test that proves a criterion of this task is a session test.

Acceptance criteria:

1. With the `engine_path` option empty and no `tempergraph` on `PATH`, the mod runs the shim of the engine home (`$TEMPERGRAPH_HOME/bin/tempergraph`, by default `~/.tempergraph/bin/tempergraph`) when that file exists, and shows the runs.
2. The pane says the engine is not installed only when the option, `PATH` and the engine home all fail, and it names the path it looked at.
3. The monitor's spec states the order: the option, then `PATH`, then the engine home.
4. A session test of the mod covers each of the three places and the case where none holds the engine.
