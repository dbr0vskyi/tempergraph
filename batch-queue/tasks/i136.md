temperspec: the component reading step checks that it opened the extraction rule (GitHub issue #136)

The prompt of `read_component`, the read-only reading session that the setup step of temperspec (`plugins/temperspec-tgraph`) starts for each component folder, tells the session to open `extraction.rule.md`. Seven other steps have a blocker that confirms from the session record that each rule file their prompt names was opened (`ts-set-ruleread`, `ts-dis-ruleread` and the rest, spec `session-record-checks`, SRC-B1; the reasons are in the decision record `a-step-check-confirms-that-each-rule-file-its-prompt-names-was-opened`). `read_component` has a judge only (`ts-rdc-answers`, `ts-rdc-cited`) and no check, so nothing confirms it. It was not built with issue #133 because a unit with a check needs a `must-pass` and a `must-fail` fixture, and a fixture carries no session record: a check that reads only the record cannot have a failing fixture. The step therefore needs a second criterion that needs no record first, for example that every path the findings line names exists in the folder the session was given. The area is temperspec (`plugins/temperspec-tgraph`).

The issue's third criterion asks the same of `read_gap` if its prompt comes to name a rule file. Its prompt names none today, so that criterion asks nothing of this task.

Acceptance criteria:

1. `read_component` has a check with a blocker criterion `ts-rdc-ruleread` that fails, naming the rule file, when the session record shows no opening of a rule file that the step's prompt names and the repository holds (SRC-B1).
2. The check of `read_component` has a `must-pass` and a `must-fail` fixture.
3. `tempergraph author verify plugins/temperspec-tgraph` passes its model-free rungs.
