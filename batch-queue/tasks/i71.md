temperspec: the code step marks a phase's rows in one edit (GitHub issue #71)

Once a phase passes, the coding session marks all of that phase's rows in the plan in one edit, not one edit per row. Code sessions made 30 to 44 single-row edits each in four runs; in run r3-t5-2 ten failed in a row because the cells the session guessed were not there (research `does-the-improvement-loop-find-what-a-reviewer-finds` F7). Every single-row edit is a model turn that re-reads the session's context, so this costs money and time in every run. The area is temperspec (`plugins/temperspec-tgraph`).

Acceptance criteria:

1. The instructions the code step and the phase step give their sessions say that the Completed marks of the rows built in one phase are written in one edit of the plan, after that phase's tests pass, and not one edit per row.
2. The plan rule says the same where it describes status and marks, and this repository's installed copy of the rule files is the same as the package's.
3. A test in the package's suite fails when the code step's or the phase step's instructions lack that sentence.
