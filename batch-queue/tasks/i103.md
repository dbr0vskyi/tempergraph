temperspec: commits and the draft pull request name the run that made them (GitHub issue #103)

A commit made by a temperspec run is recognisable today only by its subject (`<type>(temperspec): <unit> for <task>`), and the pull request description names the task, not the run. A reviewer cannot get from a change to the run's detail, costs and judgements, and the share of a repository's changes made by runs cannot be counted. The engine's shared format and helper for a run trailer (GitHub issue #94) are not built; this task writes the same format directly, so that it can switch to the helper later. The area is temperspec (`plugins/temperspec-tgraph`); engine VAL-B8 says `thread_id` is an engine template key, and the engine's `finalizer-contract` spec says what the last stage is given.

Acceptance criteria:

1. Every commit a run's steps make carries a trailer line `Tempergraph-Run: <workflow>@<version>/<thread id>`.
2. The draft pull request's description has a line with the thread id and the command that shows the run.
3. A test in the package's suite checks the trailer and the description line on a fixture run.
4. The package's docs state the format in one place.
