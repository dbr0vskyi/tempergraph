temperspec: the judges of the plan, expand and phase gates read what the visit changed, and a phase session learns of a missing criterion id before its gate (GitHub issues #114 and #117)

Two issues filed by the improvement loop against the temperspec workflow (`plugins/temperspec-tgraph`), read against the runs of 2026-11-25.

#114, `judge_unread_pass` at the units `plan`, `expand` and `phase`: in earlier runs the judge of each of these gates passed every blocker without opening one changed path. On 2026-11-25 the cause could not fire in any of nine threads: the engine counted a judge's changed paths from the uncommitted files, and each unit commits before its judge (#169). That silence was a missing measurement. Session reviews of the same judges returned `judge_unread` 61 times and kept `judge_shallow` 72 times. The package's spec `judge-reading` lists the changed source files and tells the judge to read them only at the code gate (JRD-B1 to JRD-B4); the briefs `judges/plan.md`, `judges/expand.md` and `judges/phase.md` hold no such rule. This task starts after the engine counts the visit's own changes (#169) and after the phase check lists the phase's own paths (#148); both are taken as given.

#117, `check_fail:phase` at the unit `phase`: run `temperspec/i21` recorded it twice. Both failing checks said `ts-phs-proof`: no test in the row's file carried the criterion id. The retry passed each time. The phase prompt already says that a test carries the id its row names (`prompts/phase.md`), so the loop's remedy ("say what it checks in the prompt") is done and did not hold. The `code` step is declared with `self_check=True` and the step of the `phase` map is not (`workflow/temperspec/__init__.py`), so a phase session ends without hearing what its own check will say, and each miss costs a gate retry with a fresh session. The pauses of the same unit that day came from the judge (`ts-phs-scope`), which is #148 and not this task.

Acceptance criteria:

1. The check evidence of the plan, expand and phase gates lists the paths the judged visit changed (for a phase: the phase's own paths), and each judge's brief tells the judge to open each listed file itself, not only search results from it, before it grades a criterion that rests on that file.
2. Each of the three briefs tells the judge to name a listed file it did not open and to grade UNVERIFIABLE a criterion that rests on it.
3. The spec `judge-reading` states both rules for the three gates, and a test of the package proves each brief and each check's evidence, as the tests of JRD-AC4 and JRD-AC5 do for the code gate.
4. A phase session whose test file lacks the criterion id of a test row is told so, with the id and the file, before the session ends, and can fix it in the same session.
5. A fixture run on the `phases` arm in which a phase session first leaves the id out and adds it after being told passes the phase gate on its first attempt, with no `check` record of result FAIL for `ts-phs-proof`.
6. The specs `phase` or `phase-coding` state the rule of criterion 4, and no criterion of the phase gate is dropped or lowered.
7. `outcome.json` carries a new revision where a criterion changed, and `tempergraph author verify plugins/temperspec-tgraph` passes its model-free rungs.

Out of scope: the engine's count of a judge's changed paths (#169); which paths the phase check hands its judge and `ts-phs-scope` (#148); a reader of the whole diff (#173); the code gate's reading rules, which stand; closing #114 and #117, which a person does after later runs show the causes gone.
