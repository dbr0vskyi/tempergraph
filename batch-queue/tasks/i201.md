A judge's read share counts only the paths the judge was there to read: finish the change after its review (GitHub issue #201)

Since merge `aca69138` a judge's changed paths are counted from where its visit began (SRV-B34 to SRV-B36), and the improvement loop makes `judge_unread_pass` for a judge that passed every blocker having opened none of them and `judge_partial_read` for one that gave a judgement having opened under a share of them (SRV-B31, `digest.judge_read_share` 0.25). The area is the engine (`plugins/tempergraph`): specs `judge-read-share` (SRV-B31, SRV-B34 to SRV-B36, SRV-AC13, SRV-AC14, SRV-AC21 to SRV-AC31), `session-review` (SRV-B12), `workflow-model` (what a gate declares), `run-events` (the record of a session) and `improvement-data` (the parameter). The engine names no workflow (ADR `the-engine-names-no-workflow`), so every behaviour is stated for any package and tested with an engine fixture.

A first run built the count; its notes are `plugins/tempergraph/docs/tasks/i169.triage.md`, `i169.handoff.md` and `i169.report.md`; this run writes its own plan and notes and leaves those as the record. An independent review then replayed the count over 144 recorded judge sessions of one machine. `judge_unread_pass` fired 0 times and `judge_partial_read` 3 times, all three true. The findings below are the work of this run:

1. `judge_unread_pass` cannot fire for a workflow whose steps write a notes file. The note is among the changed paths and the judge always opens it, so the read count is at least 1 (`improve/digest.py`: `changed_read` in the digest, the two rules in the findings). A quiet log does not say that judges read the change.
2. The same file hides judges that opened nothing else: a judge that opened only the step's note with up to four changed paths sits at exactly 25 percent, and the rule is a strict `<`. Four recorded sessions have this shape, and three more passed seven to nine changed files having opened only the note.
3. Generated and deleted paths count. The judge node (`run/nodes.py`) takes `changed_paths` of `git.py` (`git diff --name-only <base>`, no filter): files a command generated inflate the total, a deleted file is listed though no judge can open it, and a name git prints quoted (a non-ASCII or spaced name) never matches a read.
4. A base git no longer has gives an empty list, the same as "nothing changed" (`_entry_commit` in `run/nodes.py`), and nothing records which base a count used.
5. For a map, `passed` is read per unit and not per item (`judged_units` in `improve/record.py`): the last item's judgement stands for every item's judge.
6. SRV-AC22 is proved on a hand-written judge journal and not on a run: the stand-in executor (`tests/fixtures/standin_cli.py`) emits no read event.

Acceptance criteria:

1. A path that is a file artifact the workflow declares for the run (a `produces` key of kind `file` of any unit on the path, resolved to its path in the run's state) is left out of both counts of every judge, `changed_total` and `changed_read`. `judge-read-share` states it. A fixture unit whose step writes a declared notes file and three other files, judged by a session that opens only the notes file and passes every blocker, leaves `changed_total` 3 and `changed_read` 0 and yields `judge_unread_pass`.
2. A gate can declare paths its judge need not open, as a list of path patterns on the gate's judge; they are left out of both counts for that judge only. `workflow-model` states the field and what validation refuses (an absolute pattern, one that leaves the repository, a pattern on a gate with no judge), `judge-read-share` states the effect, and the judge's record holds how many paths the rule left out. A fixture gate that declares `generated/**` and whose step writes two files there and two elsewhere leaves `changed_total` 2.
3. The judge's count lists no deleted path and matches a path whose name git would quote: a fixture visit that deletes one file, adds one file with a space and one with a non-ASCII letter in its name, and whose judge opens the two added files, leaves `changed_total` 2 and `changed_read` 2. The change is made for the judge's count only: `changed_paths` as checks, git facts, the session's own record and the suites receive it still lists a deleted path, and a test pins that.
4. The session record of a judge holds the base commit its count was made from, or null with a reason from a fixed list when there is none (no entry commit recorded, the commit is unknown to git, the unit runs outside a repository). With a null base the digest carries no `changed_total` and neither finding is made; an empty list with a base still means that nothing changed. SRV-B34 states the fallback and what a dirty tree adds to the count. Fixtures: an entry commit that git no longer has gives null and no finding; a clean visit gives a base and `changed_total` 0.
5. `passed` and `gave` are keyed by unit and item. A fixture sequential map of two items, whose first item's judge passed having opened nothing and whose second item's judge failed a blocker, yields `judge_unread_pass` for the first item only; before the change it yields none. SRV-B12 or `judge-read-share` states the key.
6. The stand-in executor can emit a read event for a path its scenario names, in the form the digest reads from a real session. SRV-AC21, SRV-AC22 and the fixtures above are proved by a fixture run with that stand-in, and no test of this spec writes a judge journal by hand.
7. The thresholds are decided again on the review's shapes, as a test: a fixture of seven judge sessions, each a judge that gave a judgement and passed, of a fixture workflow whose step writes a declared notes file: four that opened only the notes file with two, three, three and four changed paths in all, and three that opened only the notes file with eight, ten and ten. After criterion 1 all seven yield `judge_unread_pass` and none yields `judge_partial_read`. A judge that opened one of five counted paths yields `judge_partial_read`, one that opened two of five yields none. `digest.judge_read_share` in `improve/params.py` holds the value the fixture fixes, with its source; if the value or the comparison changes, SRV-B31 and its scenarios say the new rule.
8. The digest fields a finding is made from are still names, counts and digests: no path of a run is in `loop.jsonl`, a finding or an issue body (the canary test of the digest gains a declared artifact path and a pattern).
9. The specs changed state what the code does without naming any workflow and stay within the spec budget (`session-review.spec.md` is at 30,119 of 30,720 bytes: new text goes to `judge-read-share.spec.md`); each new test carries the id of the spec criterion it proves; SRV-AC13, SRV-AC14 and SRV-AC21 to SRV-AC31 still pass, changed only where a criterion above changes the number they assert.
