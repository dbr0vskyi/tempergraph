Package tests run directly write the real machine index and stats: finish the change after its review (GitHub issue #144)

The engine's own test suite never touches the real home folder: `plugins/tempergraph/engine/tests/conftest.py` has an autouse fixture that points `TEMPERGRAPH_HOME` at a temporary folder and turns the improvement loop off. A workflow package's tests get that fixture only when the engine's suite runs them (`tests/test_workflow_packages.py`). Started from the package's own folder (`cd plugins/<package> && python -m pytest tests/...`), as a coding session of a run does and as a person does, they use the real home: on 2026-11-25 this left 106 pytest temporary folders in `~/.tempergraph/index.json` (107 roots in all), 110 test rows of 115 in `~/.tempergraph/stats/2026-11.jsonl`, and 34 threads `temperspec/P-1` in `tempergraph status --all-roots`. Specs: `test-suite` (TST-AC7) and `workspace-and-concurrency` (WSP-AC2) say no test touches the real home folder or a real state root; the machine index is in `central-run-stats` (CST-B8 never removes an entry). The area is the engine (`plugins/tempergraph`); the engine names no workflow (ADR `the-engine-names-no-workflow`), so the capability is stated for any package and tested with an engine fixture package.

A first run built this on the branch this run starts from: a pytest plugin registered as an entry point (`tempergraph.pytest_plugin`), the verb `stats forget`, behaviours TST-B7, TST-B8 and CST-B17 to CST-B21 with their criteria, and tests. Its plan and notes are `docs/plans/i144.plan.md` and `docs/tasks/i144.*`; this run writes its own plan and notes and leaves those as the record. The first run's code passed its gates. An independent review of it then found one defect that blocks its use and smaller ones; they are the work of this run:

Blocking:

1. The plugin is registered as a pytest entry point inside the engine's package (`pyproject.toml`, `tempergraph.pytest_plugin`). Pytest imports entry-point plugins before any `conftest.py`, so the name `tempergraph` is already bound to the installed copy of the engine when `tests/conftest.py` puts the `src` beside it first on the path. A suite run in one process (`-n 0`) in a worktree, with an environment whose installed engine is another checkout, then tests that other checkout's code and says nothing; workers are not affected, because they inherit the path. Reproduced in plain Python: after the plugin's import, `tempergraph.observe.forget` of the worktree was not found. Make loading the plugin leave the engine's package unimported (for example a plugin module outside the package that imports nothing of the engine), or make the suite's own `conftest.py` put the `src` beside it in force whatever was imported before it, and prove it with a test that runs a suite in one process against an environment where another copy is installed and registered.

Not blocking:

2. The fixture is function-scoped, so code that runs at import time and session, module or class fixtures still see the real home. Give the whole session a home of its own from its start, and each test its own inside it.
3. `stats forget` writes the index before it rewrites the stats: a failure between the two leaves rows that no later run of the verb can find. Rewrite the stats first.
4. `stats forget` checks the stats file's size and then replaces it; that is not a lock, and a row a live run appends in between is lost, though the docstring says otherwise. Take the lock the writers of that file take, or append-safe replace, and say in the docstring only what holds.
5. `stats forget --month <m>` is accepted and ignored; the verb touches the current month only. Refuse the option with a message, or honour it.
6. The spec `test-suite` does not say that the isolation holds where the engine is installed in the environment, nor how a person switches it off (`-p no:<plugin>`); state both.
7. In `plugins/tempergraph/docs/specs/central-run-stats.spec.md`, the scenario of CST-B8 that reads "THEN it shows `missing` and the entry stays" has no exception for the new verb: make it "THEN it shows `missing` and the entry stays until `stats forget` removes it (CST-B17)".
8. The tests name the plugin with `-p` every time; the entry-point route is checked only as text of `pyproject.toml`. Add one test that the route itself loads the plugin in an installed environment, or say in the report why the suite cannot hold one.

Acceptance criteria:

1. A suite run in one process (`-n 0`) from a checkout of the engine tests that checkout's own `src`, also in an environment where another copy of the engine is installed with the plugin's entry point registered, proved by a test.
2. A test that imports the engine and starts from any folder (a package's own folder included) runs with a home folder of its own and with the improvement loop off, with no fixture written in the package; code that runs at import time and session-scoped fixtures see that home too.
3. `stats forget` rewrites the stats before the index, loses no row a live run appends while it runs, and refuses `--month` with a message or honours it.
4. The spec `test-suite` states that the isolation holds where the engine is installed in the environment and how a person switches it off, and the scenario of CST-B8 reads "the entry stays until `stats forget` removes it (CST-B17)".
5. One test shows that the entry-point route itself loads the plugin in an installed environment, or the code report says why the suite cannot hold such a test.
