temperspec: discovery runs as two passes with a gate each (first half of GitHub issue #134)

`tempergraph audit plugins/temperspec-tgraph --layer definition` reports `oversized-step` for the `discovery` unit of the temperspec package (`plugins/temperspec-tgraph`): 13 blocker criteria where the rule warns above 8, and a prompt of about 8 KB. A retry of the step repeats all of its work for one failed criterion, and one prompt has to carry every rule the gate grades: it reads the gaps, extracts the rules, writes specs, decision records and research notes, and writes the hand-off. On the measured runs discovery is 40 to 48 percent of a run's cost.

Wanted: discovery as two passes with a gate each. The first pass extracts: for each gap of the triage note, which rule of which capability the gap is a case of, with its source. The second pass writes: the documents and the hand-off. No criterion is dropped or lowered; each moves to the gate of the pass that produces what it grades. The `code` unit has the same finding; it is the second half of the issue and is not part of this task.

This needs new units, an outcome revision and the package's own stamp. A live trial run is made by the operator after the merge and is not part of this task.

Acceptance criteria:

1. `tempergraph audit plugins/temperspec-tgraph --layer definition` reports no `oversized-step` finding for any unit that does discovery's work.
2. Every criterion of today's `discovery` unit is still graded, by the same verifier kind (check or judge) and at the same severity, at the gate of the pass that produces what it grades.
3. A retry after the write pass fails its gate runs the write pass again and not the extract pass.
4. The short discovery visit, a docs-only run and a return to discovery from a later gate still reach the same next step as before.
5. `tempergraph author verify plugins/temperspec-tgraph` passes its model-free rungs, and the package's README, overview spec and diagram describe the two passes.
