Step and judge sessions are offered no MCP server they do not declare (GitHub issue #21)

ECC-B16 of the engine's spec `executor-claude-code` stopped steps loading user-scope plugins, skills and settings (`--setting-sources project`). MCP servers were not checked. Issue #21 asked for a live probe of whether a step lists a user-scope MCP server, and for an ECC behaviour and a fix if servers leak. The probe has now been made, and servers leak. The area is the engine (`plugins/tempergraph`); the engine names no workflow (ADR `the-engine-names-no-workflow`).

Facts of the live probe, made by the operator on 2026-11-25 on macOS with `claude` 2.1.332, signed in to an account with eight claude.ai connectors, and with two user-scope MCP servers in the settings files. Each probe launched `claude -p --output-format stream-json --verbose --model sonnet --tools Read --setting-sources project --permission-mode default` with the extra words below and a prompt that makes Read calls; "context" is input plus cache-read plus cache-write tokens of a turn.

| Probe | Extra | Context per turn | USD |
|---|---|---|---|
| A | none (a step launch of today) | 8,800 then 174,123 | 0.713 |
| B | `--strict-mcp-config` (no `--mcp-config`) | 8,850 / 9,041 / 9,181 / 9,379 | 0.009 |
| C | `--disallowedTools "mcp__*"` | 8,850 / 10,496 / 10,636 / 10,834 | 0.037 |
| E | environment `ENABLE_CLAUDEAI_MCP_SERVERS=false` | as B | 0.007 |
| F | `--setting-sources "" --disallowedTools "mcp__*"` (a judge launch of today) | 4,592 / 5,937 / 6,530 / 6,728 | 0.019 |

| I | H and `--disallowedTools "mcp__*"` | the declared server connects and its tool is gone | 0.027 |

What they show:

- The account's connectors reach a step session: they are not in the `system/init` record (the servers connect after it), and from the second turn the session carries about 165,000 tokens of tool definitions and about 160 tools. In real runs of the same day a step session's first turn held about 174,000 tokens where a judge session held 10,000 to 14,000, and four step sessions of one run each wrote those tokens to the cache again; that was about half of the run's cost.
- The two user-scope servers of the settings files did not reach the session under `--setting-sources project`.
- `--strict-mcp-config` alone keeps every undeclared server out and needs no `--mcp-config`; with `--mcp-config` the declared server still works. Under it the CLI still fetches the connector list and connects none; the environment variable skips the fetch.
- A `mcp__*` deny removes the tool definitions but the connectors still connect (about 1,350 tokens stay), and it also removes a declared server's tools. A judge launch of today denies `mcp__*` and passes no `--strict-mcp-config` in its ordinary case, so it shows the same 1,350 tokens.
- `step_argv` passes `--strict-mcp-config` today only when tools are enforced and the step declares an MCP tool.

Acceptance criteria:

1. Every step launch, and every retry of one, passes `--strict-mcp-config`, with `--mcp-config` only when the step declares an MCP tool, so a session is offered no MCP server of the account, the user or the repository that its step does not declare.
2. A step that declares an MCP tool is still offered that server's tools.
3. Every judge launch passes `--strict-mcp-config` too, and a judge with MCP views still gets its views.
4. The environment of a step and a judge session carries `ENABLE_CLAUDEAI_MCP_SERVERS=false`.
5. The spec `executor-claude-code` states the behaviour as a rule of the launch, and its acceptance criteria are proved by argv and environment tests of a step, a retry and a judge launch.
6. The engine's live-checks runbook has a new probe row for this (a P-CC row), with the result of 2026-11-25 above recorded in its results table as the operator's live run.
