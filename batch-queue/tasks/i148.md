temperspec: a phase's gate grades the phase's own changes (GitHub issue #148)

On the `phases` arm of the temperspec workflow (`plugins/temperspec-tgraph`) each phase is coded by its own session and then graded at its own gate: a model-free check first, then a read-only judge. The phase check hands the judge the paths changed since the run's base. That list also holds what triage and discovery wrote before the plan (the triage note, the hand-off, specs). The judge cannot run git, so it cannot tell which step changed those paths. In run `temperspec/i21` of 2026-11-25 the judge of phase `p1` graded `ts-phs-scope` PARTIAL for that reason, and the judge of `p2` graded every criterion MET and still set a gap ("git was out of reach, so the scope grade rests on the step's account of which commits touched the three non-row files"). Both gates ended in a pause for a person (`unresolved_gap`), though each phase's own commits changed only files its rows name. Specs: `phase-coding`, `phase`, `judge-reading`.

Acceptance criteria:

1. The evidence the phase check hands its judge lists the paths the phase itself changed, counted from the commit at which the phase was entered, apart from the paths that only earlier steps changed.
2. Each path that only an earlier step changed is listed with the step that changed it.
3. `ts-phs-scope` is graded on the phase's own paths: a path that only an earlier step changed does not lower its grade and is not a gap.
4. The phase judge's brief tells the judge that the check has sorted the paths and that it takes that sorting as given.
5. A fixture run on the `phases` arm, in which an earlier step wrote a document and each phase changes only the files of its rows, passes each phase gate with no pause.
6. The join after the phases, when it is handed changed paths, is handed them sorted the same way.
