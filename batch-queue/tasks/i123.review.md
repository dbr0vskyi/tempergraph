Blocking:

1. "Files the run wrote" is empty for real runs, so a person's follow-up commit never makes an escape (criterion 3, second half; criterion 4, the writing units). `engine/src/tempergraph/improve/pr_later.py:75-87` (`_wrote`) reads `changed_paths` from `agent_run` records. The engine writes that field only on judge sessions (`run/nodes.py:1653-1655`), from `git status` with no base, which is empty once a step has committed; a step session's record holds none (`run/nodes.py:371`). Evidence: in three real runs, 64 judge records hold `changed_paths` of length 0 and 57 step records hold none; probe d, with records in the engine's real shape, gives `files == 0` and no escape for a person's commit on a file the run wrote. The tests pass because `tests/test_pr_later.py:64-67` and `tests/test_outcome_escape_finding.py:43` hand-write step records with `changed_paths`, a shape the engine never writes. Related: `improve/escape.py:62-77` (`_writers`) matches against the session digests' `_wrote`, which holds edit and write tool calls only: 8 of the 42 files this very run changed. Fix: take the run's files from git or from the code host (the files of the pull request's commits up to the recorded end commit are already fetched and dropped; or `git diff --name-only <base> <end>`), attribute a file to a unit from the commits or sessions of that unit, and prove it with a test that drives a real fixture run (steps that commit, a finalizer that returns a pull request url) into a read with a follow-up commit.

Not blocking:

2. A review followed by a fix commit never names the writing unit. `improve/escape.py:41-51` (`_is_new`) and `:92`: `record` returns unless the run became an escape at this read. The usual order is a `changes_requested` review at one read and the person's fix at the next; by then the run is an escape already. Probe a: the findings are `['outcome']` where SIL-B33 gives `['draft', 'outcome']`; the third scenario of SIL-B33 and the `held` check at `escape.py:97` assume a later read can add a unit. Fix: decide on "is an escape now, and this unit holds no finding", not on "became one at this read".
3. A failure or a race between the ledger row and the finding loses the signal for good. `improve/child.py:312-321`, `improve/pr_later.py:153-157`, `improve/escape.py:41-51`: `read` appends every `outcome_later` row first and the findings are written after, in one loop under one `try`; the next read sees an equal entry and returns nothing. Probe b: one exception in `escape.record` leaves no finding after a second clean read. Probe c: two loop children at two final exits (a batch) both append the same row, `_is_new` drops only the last, still sees an escape and records nothing; the ledger also holds the entry twice. Fix: derive "needs a finding" from the state (escape, no finding held), not from the append; serialise the read and append per workflow, or refuse an equal row at append time.
4. The cost of a read has no bound. `improve/codehost.py:213-232`: `pull_commits` makes one GET for each commit, those before the end commit included, whose files are never used, at every read, with no cache. `improve/child.py:126-127`: every clean final exit now starts a loop child while any recorded pull request is open. `improve/pr_later.py:139-140`: a pull request that cannot be read (404, a renamed repository, an unknown review state) is skipped with no `loop_skipped` record and read again at every exit for ever; one closed and reopened is never read again. Twenty open pull requests of 23 commits are about 540 calls per final exit; a batch of 20 exits passes 5,000 calls an hour, the limit that issue filing shares. Fix: fetch files only for commits after the end commit; skip a pull request whose head commit and update time are unchanged; a cap by age or count and a minimum interval; log each skip.
5. "A person" is any account that is not a bot. `improve/codehost.py:159-164`, `improve/pr_later.py:91-92`: on a public repository any user can submit a `changes_requested` review or a review comment, which makes a `met` run an escape, raises the escape rate that promotion reads, files an issue after three runs, and writes their text into the state root. A commit whose `author` is null counts as a person's. A merge commit that brings the base branch in ("Update branch") lists the base's files and can hit a file the run wrote. Fix: count only an author the host gives as `OWNER`, `MEMBER` or `COLLABORATOR`; do not count a commit with no account or with more than one parent; state it in OUT-B25.
6. The recorded code host is not used by the read, and its pattern admits credentials. `improve/pr_later.py:133-138` calls `gh` with the repository and number only, so a pull request recorded on another host is read from `gh`'s default host, where the same owner, name and number may be another pull request. `improve/proposals.py:672`: the host group `[^/\s]+` accepts `user:token@host`, which would then be in the ledger row and in harvest candidates. Fix: a hostname pattern; `--hostname`, or skip a host `gh` is not signed in to.
7. Review text is local by FBK-B15, and the carry filter would push it. `durability/carry.py:104-108` leaves out only `evidence/prompts`, so `evidence/pull_request.jsonl` goes to the state branch if a thread that holds it is pushed. No code reads the file today, so no model sees the text; the friction judge's working folder is the state root. Fix: never carry the file, and add the carried set to the canary test.
8. Specs disagree with the code. FIN-B11 and FIN-AC5 name the host, repository and number; the code also records `commit` (`run/finalize.py:89`), the test asserts it, and OUT-B24 depends on it. OUT-B26 and OUT-AC10 say a `met` run that was rerun; the code counts `met_with_open` for a rerun and `met` only for a review signal (`run/outcome_record.py:757-759`). OUT-B24 does not say that an end commit no longer among the pull request's commits (a force push, a squash) gives no follow-up commit (`improve/pr_later.py:95-103`). SIL-B10 says the outcome lens runs for the earlier run; the code writes one `loop_lens` line in the current thread's loop log and nothing else (`improve/child.py:314-316`), and that line is all the test asserts.
9. A watch-only ticket that finds an escape does a whole ticket's work for the clean thread. `improve/child.py:329`: a `loop` ledger row, a summary and a propose attempt under the clean thread, and the escape files with that thread's review categories. No model call was found; the comment on the line no longer holds.
10. Test ids. `tests/test_pr_reads.py:35-109` names six tests `prp_ac11`; PRP-AC11 is a proposal's unreadable pull request, and these prove the reads of OUT-AC8 and OUT-AC9. `tests/test_specs_name_no_workflow.py:15` carries a behaviour id. No test in the suite names DUR-AC7, before or after this change; the `finalizer` field of the status row is asserted only under FIN-AC1 (`tests/test_finalizer_outcomes.py`). A test of DUR-AC7 asserts, on `status --json` rows of fixture threads: a finalizer that returned manual steps gives `finalizer` equal to the `finalize` event's `outcome`, `reason` and `manual_steps`; one that raised gives `outcome` `error` and no steps; a published or quietly skipped run has no `finalizer` key; the row is schema version 1 and holds the other fields of DUR-B11 that apply; and `status` left the state root unchanged (DUR-AC3).

What the workflow's gates could have caught:

- Finding 1, by a deterministic check: a test fixture may not hand-write a run-log record with a field the engine's writer does not write for that session kind; or, at least one test per task criterion starts from a real fixture run. A judge reading plan rows against the diff does not catch it: the plan and the tests agree with each other, and both are wrong about the log.
- Findings 2 and 3 are faults of order and repetition. A review unit asked to replay the signals in the other order, twice, and with a failure between each pair of writes finds them; a checklist row for every "append, then derive" pair would ask for it.
- Findings 4, 5 and 6 need a reviewer asked about the world outside: who can write this input, how many calls an exit makes, which host. A count of host calls per read on the fake host, asserted against a bound, catches the cost.
- Findings 8 and 10 are mechanical: every field a test asserts on a record is in the spec line the test cites; a test's cited criterion lists the behaviour its module names. The trace gate found DUR-AC7.
- For the improvement loop: every gate passed because the fixtures and the code came from one author and one wrong assumption. Reading real run logs is what found it.
