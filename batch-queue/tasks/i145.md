Monitor: a live run's row shows a sign of life, and rows of other state roots are named and folded (GitHub issues #142 and #145)

Two defects of the monitor mod's run list (`plugins/tempergraph-monitor`), seen on 2026-11-25 with three live runs.

First (#142): during one long session the list looks frozen. The mod polls `status` every 5 s, but a row is built from the run's detail document, which the mod reads again only when the run log has grown, and a session writes no run-log record between `session_opened` and its end. A 15 minute session showed the same unit and the same cost for 15 minutes. The engine's detail document already holds `health.silent_s`, the stall flag and the running cost.

Second (#145): in `machine` scope the mod listed 34 runs of other state roots with one label, `repo/tg/temperspec/P-1·e09a`, and 72 separate `repo: missing (…)` lines. `refreshStatus` calls `summarise` without a repository, so `runLabel` falls back to the word `repo`, and the four hex characters are a hash of the thread id only. Rows of other roots are neither sorted nor folded. Monitor specs: MBA §2.1 (the label is `<repo>/<branch-or-worktree>·<4 hex>` with the real repository), MRV §2.3 (the list is grouped, older runs folded), `data-sources` MDS §2.1 and MDS-B4.

The mod's session tests (`tests/*.test.tsx`) run with `claude plugin test plugins/tempergraph-monitor`, which this repository declares as a verification command. Its model tests (`tests/*.spec.ts`) need `bun`, which is not installed here; a test that proves a criterion of this task is a session test.

Acceptance criteria:

1. A live run's row shows the time since its session last did something and changes at least every 10 s while the session works, with no new run-log record.
2. A live run's cost in the row is read again on a clock, at a rate the monitor's `data-sources` spec states.
3. A session the engine marks as a suspected stall is marked in its row.
4. A row of another state root carries that root's repository name, and two roots that hold the same thread id give two different labels.
5. Ended runs of other state roots are one folded line with their count, and missing roots are one line with their count.
6. The monitor's specs state each rule, and a session test of the mod covers each criterion.
