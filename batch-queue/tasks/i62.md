temperspec: a model-free drift check for pre-commit and CI (GitHub issue #62)

Specs go stale between runs: nothing checks them when a person or another tool changes the repository outside a temperspec run. Add a model-free script, reusing the format reader the workflow's own checks use (`specfmt`), that checks the specs of a repository: their format, their links, and that the acceptance criteria are carried by tests. It runs as a pre-commit hook and in CI, and the `setup` skill installs it. Contributors get a check they can run without a model. The area is temperspec (`plugins/temperspec-tgraph`) and this repository's CI. Source: research `next-features` section 5 row 4.

Acceptance criteria:

1. One command, with no model call and no network, checks every spec of a repository and exits 0 when each spec passes the spec rule's structure check, every id a document links to resolves to exactly one definition, and every acceptance criterion that a test is said to carry is carried by a test that is not skipped; it exits non-zero otherwise and prints one line for each finding with the file, the id and the reason.
2. The command reads the specs folders from the repository's real layout, as the workflow does, so it works on a repository that keeps its specs under a plugin's `docs/`.
3. The `setup` skill installs the command as a pre-commit hook when the person agrees, and the hook checks only when a commit touches a spec, a decision record or a test.
4. This repository's CI runs the command on every pull request, and it passes on the current tree.
5. A test in the package's suite runs the command on a fixture repository with one broken link, one malformed spec and one criterion no test carries, and finds each.
