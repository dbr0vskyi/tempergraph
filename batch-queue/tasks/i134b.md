temperspec: the code gate carries no more blocking criteria than one gate should (second half of GitHub issue #134)

`tempergraph audit plugins/temperspec-tgraph --layer definition` reports `oversized-step` for the `code` unit of the temperspec package (`plugins/temperspec-tgraph`): 17 blocker criteria where the rule warns above 8. A retry of the step repeats all of its work for one failed criterion. One prompt of about 6.4 KB serves three modes: the whole plan in one session, the join after the phases, and the quick lane.

Wanted: the join after the phases and the quick lane each get a prompt of their own, so each prompt states one procedure, and the criteria are spread so that no gate carries more than 8 blockers. No criterion is dropped or lowered; each moves to the gate of the pass that produces what it grades.

This needs new units, an outcome revision and the package's own stamp. A live trial run is made by the operator after the merge and is not part of this task.

Acceptance criteria:

1. `tempergraph audit plugins/temperspec-tgraph --layer definition` reports no `oversized-step` finding.
2. Every criterion of today's `code` unit is still graded, by the same verifier kind (check or judge) and at the same severity, at the gate of the pass that produces what it grades.
3. The session of the join after the phases and the session of the quick lane each get a prompt that states only its own procedure.
4. A run on each of the three lanes (quick, standard, full) still reaches the outcome gate through the same checks of its verification commands as before.
5. `tempergraph author verify plugins/temperspec-tgraph` passes its model-free rungs, and the package's README, overview spec and diagram describe the units.
