The independent reader is given the whole change of the run, or the review gate fails: first slice (GitHub issue #206)

The independent review unit (run i173, issue #173) gives a reader the run's diff and the task's numbered criteria. The reader's diff can be cut short or empty with no warning, and then the gate passes. The areas are the temperspec package (`plugins/temperspec-tgraph`, spec `independent-review`, IRV-B3) and one general engine capability it needs (`plugins/tempergraph`, spec `script-units-and-hybrid-steps`). The engine names no workflow (ADR `the-engine-names-no-workflow`): the engine part is stated for any script of any package and tested with an engine fixture.

What the code does today, on the trunk at `7fd52537`:

- `workflow/temperspec/review.py` (`run_base`) finds the run's base by reading commit subjects back from the tip and stops at the first subject that does not end `for <task>`. A commit made by hand in the run's branch hides every run commit before it; a task id that matches no subject gives no base.
- `_git` in the same file returns an empty text on a non-zero exit, and a timeout is not caught as a reason. `write_inputs` then writes an empty diff; the reader writes `None` and `ts-rev-form` passes.
- The engine gives the run's base to a check (`ctx.git.base`, used across `workflow/temperspec/checks.py`). A script unit is not given it, so `write_inputs` (called from `routing.py`) and `regeneration.py` both derive it from commit subjects.
- The reader gets one diff file and one criteria file. It gets no list of the changed files, and stamps and diagrams stand in the diff in the order git prints them.

Acceptance criteria:

1. A script unit is given the run's base commit, the same value a check of the same visit reads as its base. The engine spec states it without naming a workflow, and an engine fixture run proves a script and a check of one run read the same commit.
2. The reader's inputs are built from the base the engine gives, not from commit subjects. A package test with a commit made by hand between two run commits proves the diff holds the files of every run commit.
3. `review_check` fails `ts-rev-form` when the base the inputs were built from differs from the base the check is given, with a finding that names both commits.
4. `review_check` fails `ts-rev-form` when the diff given to the reader is empty while the run changed at least one path, with a finding that says the reader was given no change.
5. A git command that fails or times out while the inputs are built fails the attempt with a finding that names the command; no empty input is written in its place. A test proves each of the two cases with a replaced `git`.
6. A file list stands beside the diff: one row per changed file with its added and removed line counts, files a declared regeneration writes (stamps, diagrams) listed last and marked as generated.
7. The reader's brief names the file list, tells the reader to open it first, and tells it to read a large diff in pages; a test asserts the three sentences.
8. `independent-review.spec.md` states the behaviours of criteria 2 to 7 and its criteria list carries them; the package's own note of the engine need is written before the engine change, as the ADR asks.
9. The criteria above are numbered 1 to 9 with no gap and are the whole slice. Each new test carries the id of the spec criterion it proves, no test writes by hand a record in a shape the engine never writes, and the package's existing review tests still pass, changed only where a criterion above changes the fact they assert.
