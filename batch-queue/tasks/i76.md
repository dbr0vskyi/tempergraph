temperspec: repository setup runs as a sub-workflow (first part of GitHub issue #76)

Repository setup is today a conditional first part of the temperspec workflow (`plugins/temperspec-tgraph`): after `prepare`, the route `setup_route` sends a repository with no overview spec through `list_components`, one `read_component` session per component folder and `setup`, and every other run straight to `triage`. The package's overview spec says why: release 1 of the engine had no sub-workflows, and setup moves into one when the engine has them. The engine has them now (spec `subworkflow-unit`, SWF, built in release 3 track R3-T2): a sub-workflow unit runs another registered workflow, the child, in the parent's workspace, thread and cost cap, and the parent's later units read what the child's `produces` exposes. A child is a registered workflow, and a workflow package is one plugin named `<workflow name>-tgraph` with an entry in the marketplace catalog. Wanted (the owner's request of 2026-11-21, once backlog row B11 "Repository setup as a workflow of its own"): setup as a workflow of its own that the temperspec run uses as a sub-workflow. The issue names neither the new workflow nor its plugin, and asks for no change to what setup writes or to how it is graded. The area is temperspec (`plugins/temperspec-tgraph`) and the new package beside it.

Left out of this task: the docs-only workflow that the issue's title also names ("a second workflow built from the same sub-workflows"). The issue does not say which parts it is built from or what it is called, and it needs this task first. A live run is made by the operator after the merge and is not part of this task.

Acceptance criteria:

1. Repository setup is a workflow of its own: it is registered under its own name, and `tempergraph run` with that name starts it alone on a repository with no overview spec.
2. A temperspec run on a repository with no overview spec runs that workflow as a sub-workflow unit before `triage`.
3. A temperspec run on a repository that has an overview spec goes to `triage` without it.
