Workflow package tests run directly write the real machine index and stats (GitHub issue #144)

The engine's own test suite never touches the real home folder: `plugins/tempergraph/engine/tests/conftest.py` has an autouse fixture that points `TEMPERGRAPH_HOME` at a temporary folder and turns the improvement loop off. A workflow package's tests get that fixture only when the engine's suite runs them (`tests/test_workflow_packages.py`). Started from the package's own folder (`cd plugins/<package> && python -m pytest tests/...`), as a coding session of a run does and as a person does, they use the real home: on 2026-11-25 this left 106 pytest temporary folders in `~/.tempergraph/index.json` (107 roots in all), 110 test rows of 115 in `~/.tempergraph/stats/2026-11.jsonl`, and 34 threads `temperspec/P-1` in `tempergraph status --all-roots`. Specs: `test-suite` (TST-AC7) and `workspace-and-concurrency` (WSP-AC2) say no test touches the real home folder or a real state root; the machine index is in `central-run-stats` (CST-B8 never removes an entry). The area is the engine (`plugins/tempergraph`); the engine names no workflow (ADR `the-engine-names-no-workflow`), so the capability is stated for any package and tested with an engine fixture package.

Acceptance criteria:

1. A test that imports the engine and starts from any folder (a package's own folder included) runs with a home folder of its own and with the improvement loop off, with no fixture written in the package.
2. A test of the engine's suite starts a fixture package's tests from that package's folder and shows that no file of the real home folder and no entry of the real machine index changed.
3. A verb removes from the machine index every state root whose folder no longer exists, and from the month's stats the rows of those roots, printing what it removed; with `--check` it prints the same and changes nothing.
4. The engine's specs state both (the isolation and the verb) without naming a workflow.
