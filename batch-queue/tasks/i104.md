temperspec: security scanning at the code gate (GitHub issue #104)

The code gate checks correctness and style (the repository's declared verification commands, such as tests, lint and types) but nothing checks a change for known vulnerable dependencies or insecure code before the draft pull request opens. A security problem then reaches review, or is missed there. The code gate runs a security scan as well: a dependency audit and a static security scan for the repository's language, when the repository declares them. Verification commands come from the repository's `tempergraph.commands.json` (spec `repository-commands`). The area is temperspec (`plugins/temperspec-tgraph`).

Acceptance criteria:

1. A repository can declare its security scanners (for example `bandit`, `pip-audit`, `semgrep`) beside its verification commands, with the severity at or above which a finding fails.
2. The code gate runs each declared scanner on the head of the run's branch and fails on a finding at or above the declared severity, with the finding as the reason.
3. A run in a repository that declares no scanner says so in the pull request description and does not pass silently.
4. A scanner that is declared and cannot run (the program is missing) is reported as environmental and is not counted as a finding of the change.
5. Tests in the package's suite use one fixture repository that has a finding and one that has none.
