A `now` stop ends the open session: the run's stop request reaches everything the run launches, and a session a stop ended keeps its cost (GitHub issue #253)

`tempergraph stop <thread> --now` is taken within a second and then behaves as a drain: the open session runs to its end and the run stops at the next boundary. Seen on 2026-11-26 on a live thread: `session_opened` at 21:30:58Z, `stop --now` at 21:46:47Z and again at 21:52:42Z, `agent_run` with `ok: true` and `duration_s` 1611.6 at 21:57:47Z, and the only `stop_requested` record (mode `now`) at 21:57:48Z, at the boundary. The area is the engine (`plugins/tempergraph`): spec `run-control` (RCT-B2, RCT-B7, RCT-B11, RCT-AC1, RCT-AC2, RCT-AC3, RCT-AC6, RCT-AC11), `executor-interface` (EXI-B15, EXI-B23, EXI-AC10), `durability-and-resume` (DUR-B2), `budgets-and-failures` (BUD-B9) and the decision record `docs/adr/stop-verb-as-the-only-observer-control.adr.md`. The engine names no workflow (ADR `the-engine-names-no-workflow`), so every behaviour is stated for any package and tested with an engine fixture.

What the code does today, on the trunk at `790bd25c` (each reference of the issue read again; two have moved):

- `durability/control.py:91-97` (`StopWatcher.check`) takes `control/stop.json` and, for mode `now`, calls `self.session_stop.request("stop")`.
- That `StopRequest` is created at `run/runner.py:381`, given to `RunContext.stop` through `_context` (`run/runner.py:316-331`, the field at `run/nodes.py:109`) and to the watcher at `run/runner.py:443`. Nothing reads `ctx.stop`.
- The code that ends a session is `executors/launcher.py:250-251` (`if stop is not None and stop.is_set(): send_stop(stop.reason)`; the issue says 249-250). It gets `stop=self.stop` at `executors/claude.py:561` (the issue says 511), and `executors/registry.py:70` builds `ClaudeExecutor()` with no argument, so `stop` is always `None`. `run/check_worker.py:148` passes none. These are the only two calls of `launch` inside a run.
- Every session of a run (step, retry, judge, the judge's re-ask and audit, a council's sessions, a sub-workflow child's) is run by `_session` (`run/nodes.py:355`), from a `SessionRequest` (`contracts.py:669`) that has no field for a stop; a child's context is a copy of its parent's (`run/subrun.py:144`).
- `stop_requested` is written by `drain()` in `run/runner.py:319-326`, which only a node at a boundary calls, so the record appears when the session has ended. RCT-B7 already says "written within 2 seconds"; the code is false to it.
- From the review of run i205 (comment of 2026-11-26T10:06Z on #205, "Low"): the cost of a session a stop ended is dropped. `run/nodes.py:670-673` raises `Drain` after a partial session, before the attempt's write at `run/nodes.py:736` that adds the session's cost to the thread's; `run/runner.py:449-458` then reads the cost from the state. The same lines raise for any pending stop: a session its own timeout killed while a drain request waits (`executors/session.py:94`: `partial` is true for a timeout kill too) is dropped as if the stop had ended it, with no attempt recorded.
- With the stop wired, two paths that are dead today become live and are wrong: a judge session a stop ends is read as an unparsed answer and re-asked (`run/nodes.py:1814-1845`), and a check worker a stop ends is recorded as a failed check with the note `check_worker_limit` (`run/check_worker.py:149-151`, called at `run/nodes.py:1625`).

Why the tests miss it: `tests/test_control.py:57-71` and `tests/test_launcher.py:146-171` hand one `StopRequest` object to the watcher and to `launch` directly, and `tests/test_stop_resume.py:33-64` uses a scripted executor whose reply writes the request and returns a hand-built `SessionResult(ok=False, partial=True, usage=Usage())`, a result with no usage that no executor returns for a session it ran. RCT-AC1 and RCT-AC2 are not proven through a run.

The stand-in CLI (`tests/fixtures/standin_cli.py`, put on `PATH` as `claude` by `fake_claude` in `tests/fixtures/streams.py`) can already block: `hang`, a `{"sleep": n}` line, `ignore_term`, `graceful_exit`, and `grandchild` (it writes the grandchild's process id to a file). It reads one scenario for every launch, so a run whose later sessions must answer differently needs a scenario key (criterion 8).

Acceptance criteria:

1. The stop request of a run reaches every session the run launches: a `now` request taken while a step, a retry, a judge or a judge re-ask session is open sends that session the stop contract (EXI-B15: graceful stop, the grace period, then the kill of its process group). It is carried per session from the run's context (on the session request or as an argument of the executor's run; no executor object holds the stop of a run, so the registry's one executor serves two runs in one process without one stopping the other). `run-control` or `executor-interface` states it. A fixture run with the real Claude executor class over the stand-in CLI proves it for a step session and for a judge session, and a test with two contexts proves that a stop of one run leaves the other's session running.
2. A `now` request taken while a check worker runs ends the worker's process group by the same contract, no check result is recorded for it, and the run exits 4 with reason `stopped_by_request`; a plain `resume` runs the check again. A fixture whose check blocks proves it, and a worker that ends at its own time limit is still recorded as today (`check_worker_limit`).
3. `stop_requested` is written when the watcher takes the request file, once for a thread's segment and with the mode and the caller, also while a session writes no record (RCT-B7, RCT-B5): within 2 seconds of the file appearing, and before the `agent_run` record of the session a `now` stop ends. A drain request leaves the same one record at the same moment, and a second, stronger request (RCT-B8) is recorded once with mode `now`. A fixture run proves the order and the count of the records.
4. End to end, on POSIX: a fixture workflow run by `start` with a registry that holds the real `ClaudeExecutor` (a short grace period is allowed) over the stand-in CLI, whose step session has an open tool, a grandchild process and ignores the graceful stop; a `now` request written by `request_stop` or the `stop` verb into the real control file while the session is open. Within 15 seconds no process of the session's group is alive, the grandchild included (RCT-AC2); the run exits 4 with reason `stopped_by_request`; the log holds `stop_requested` with mode `now` and one `agent_run` for the session with `ok` false and its partial usage; no attempt is recorded as failed and no retry is charged. The same fixture with a session that ends at the graceful stop is not killed. The test carries RCT-AC1 and RCT-AC2.
5. After a `now` request is taken the run starts no new session and no new check: no `attempt_start` record follows `stop_requested` in the segment, also in a unit that runs several sessions at once (a concurrent map of two items: both open sessions get the stop and both process groups are gone). The plain resume of that concurrent thread is not asserted here (out of scope, #205 part 2).
6. The cost of a session a stop ended is in the thread's cost: the `cost` of the stopped segment's `run_exit` record and of its `run_segment` ledger row include it, the run cost cap (BUD-B9) counts it at the next boundary, and after a plain `resume` to the end the final `run_exit` cost equals the cost of the same fixture without the stop plus the cost of the ended session. A fixture run proves it for a step session and for a judge session, each with a stand-in that reports usage before it is stopped. `run-control` states it beside RCT-B2.
7. Only a session the run's stop request ended is taken back without a recorded attempt (RCT-B11). A session that ended for another reason while a stop request waits (its own timeout, the idle limit, an infrastructure failure) is recorded as that attempt with its flags and its cost, and the run then stops at the boundary; the session result or the launcher's outcome says which of the two it was. A fixture run with a drain request waiting and a step session that reaches its timeout proves an attempt with `timed_out` true, its cost in the thread's cost, and exit 4; the `now` case of criterion 4 proves the other side.
8. A plain `resume` after the `now` stop of criterion 4 runs the interrupted attempt again under the number it had, with the retry budget unspent, and ends with the exit the same fixture has without the stop (RCT-AC11, RCT-AC3), through the real executor class and the stand-in: the stand-in fixture gains a scenario key only if this needs it (a reply chosen per launch or per session kind), and the key is described in the fixture's docstring. A judge session a `now` stop ended is not re-asked and records no verdict; the resume runs the judge again for the same attempt and no second step session.
9. `tests/test_stop_resume.py` no longer rests on a hand-built result of a shape no executor returns: its `now` cases take the result of a stopped stand-in session or assert through the fixture of criterion 4, and its drain cases stay. `tests/test_control.py` and `tests/test_launcher.py` keep their unit cases; the id RCT-AC2 moves to the test that proves it through a run.
10. The specs state what the code does without naming any workflow: `run-control.spec.md` (8.4 KB) takes the new and changed behaviours and criteria in place (the stop reaching every session and the check worker, the moment of `stop_requested`, the cost, which session is taken back) with the `## Depends on` rows for every spec its changed lines link (`executor-interface.spec.md` for EXI-B15, `budgets-and-failures.spec.md` for BUD-B9 if it is linked); `executor-interface.spec.md` changes only if a behaviour of the executor contract changes, with its own row. `self-improvement.spec.md` and `session-review.spec.md` get no text. If the run takes a decision of structure (how the stop is carried to a session), its record uses the ten-section form of `.claude/rules/temperspec/decision.rule.md`; otherwise none is written.
11. The criteria above are numbered 1 to 11 with no gap and are the whole slice: the run adds no criterion of another issue. For each criterion at least one test drives a real fixture run, no test writes by hand a record or a session result in a shape the engine never emits, each new test carries the id of the spec criterion it proves, and `python -m pytest`, `ruff check src tests` and `mypy` pass in `plugins/tempergraph/engine/`.
