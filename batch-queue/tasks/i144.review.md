An independent review of the finished change found one defect that blocks its use, and smaller ones. The acceptance criteria of the task are unchanged. For each numbered point below, either build it with a test, or say in the code report why it is not built.

Blocking:

1. The plugin is registered as a pytest entry point inside the engine's package (`pyproject.toml`, `tempergraph.pytest_plugin`). Pytest imports entry-point plugins before any `conftest.py`, so the name `tempergraph` is already bound to the installed copy of the engine when `tests/conftest.py` puts the `src` beside it first on the path. A suite run in one process (`-n 0`) in a worktree, with an environment whose installed engine is another checkout, then tests that other checkout's code and says nothing; workers are not affected, because they inherit the path. Reproduced in plain Python: after the plugin's import, `tempergraph.observe.forget` of the worktree was not found. Make loading the plugin leave the engine's package unimported (for example a plugin module outside the package that imports nothing of the engine), or make the suite's own `conftest.py` put the `src` beside it in force whatever was imported before it, and prove it with a test that runs a suite in one process against an environment where another copy is installed and registered.

Not blocking:

2. The fixture is function-scoped, so code that runs at import time and session, module or class fixtures still see the real home. Give the whole session a home of its own from its start, and each test its own inside it.
3. `stats forget` writes the index before it rewrites the stats: a failure between the two leaves rows that no later run of the verb can find. Rewrite the stats first.
4. `stats forget` checks the stats file's size and then replaces it; that is not a lock, and a row a live run appends in between is lost, though the docstring says otherwise. Take the lock the writers of that file take, or append-safe replace, and say in the docstring only what holds.
5. `stats forget --month <m>` is accepted and ignored; the verb touches the current month only. Refuse the option with a message, or honour it.
6. The spec `test-suite` does not say that the isolation holds where the engine is installed in the environment, nor how a person switches it off (`-p no:<plugin>`); state both.
7. In `plugins/tempergraph/docs/specs/central-run-stats.spec.md`, the scenario of CST-B8 that reads "THEN it shows `missing` and the entry stays" has no exception for the new verb: make it "THEN it shows `missing` and the entry stays until `stats forget` removes it (CST-B17)".
8. The tests name the plugin with `-p` every time; the entry-point route is checked only as text of `pyproject.toml`. Add one test that the route itself loads the plugin in an installed environment, or say in the report why the suite cannot hold one.
