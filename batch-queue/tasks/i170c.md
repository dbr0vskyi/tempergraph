The loop's filing does not act on what it only recorded, and an operator can say why a pause was answered: finish the change after its review, second of two runs (GitHub issue #170)

Since merge `fba4993c` every final exit of a thread hands the loop the findings of the thread's earlier segments that ended in a pause and that no loop of the thread was handed (SIL-B28), and the friction judge is told for each what answered the pause (SIL-B37); no text of a run reaches the judge or `loop.jsonl` (SIL-B38). The area is the engine (`plugins/tempergraph`): specs `runs-without-a-final-exit` (SIL-B28, SIL-B37), `self-improvement` (SIL-B2, SIL-B19, SIL-B38), `loop-issues` (ISS-B3, ISS-B7), `improvement-data` (the loop parameters), `engine-cli` and the guide `docs/guides/improving-workflows.guide.md`. The engine names no workflow (ADR `the-engine-names-no-workflow`), so every behaviour is stated for any package and tested with an engine fixture.

A first run built the hand-off (plan and notes `plugins/tempergraph/docs/plans/i170.plan.md` and `plugins/tempergraph/docs/tasks/i170.triage.md`, `i170.handoff.md`, `i170.report.md`). An independent review (`batch-queue/tasks/i170.review.md`) replayed the engine's functions over one machine's real threads and found the work of two runs. The first of them, `batch-queue/tasks/i170b.md` (the judge's facts), is merged before this run starts: this run starts from a batch head that holds it, and with it runs i172 (`batch-queue/tasks/i172.md`, the cause codes) and i171b (`batch-queue/tasks/i171b.md`, the pattern rule made safe). This run writes its own plan and notes and does not rebuild what those three cover:

- From i170b it takes as given: the facts row of a pause finding (one row per finding, bound to the pause that ended its segment, with reason, decision, caller, feedback, ruling, touch class, workspace and next gate), the judge's brief with its sentences on pauses, and `agent_decided:<kind>` classed `designed` when the supervising caller decided.
- From i171b it takes as given: the majority of recorded answers for filing by the count and its `answers[]` records, the bound on "seen again" comments (`comment_capped`), the reasons of a finding that does not file, a cause muted by an issue closed as `not_planned` or `duplicate`, the machine-wide hold and `resume --dry-run`. Where a criterion below names one of these, it uses the name i171b gave it.
- From i172 it takes as given the cause codes; none is added here.

The findings below are the work of this run:

1. The filing outbox is redelivered blindly. `improve/filing.py` (`Outbox`, `file`) sends every payload a code host did not take first at the next filing that is not a dry run, with no fresh look at the open issues and at any age. On the review's machine it holds five creates and one comment queued while filing was held, among them a create for `agent_decided:escalation`; lifting the hold sends all six. No command shows or empties it.
2. "Handed" is not "judged" (review finding 9). `improve/record.py` (`unjudged_pause_findings`) takes any `loop_started` record that names a fingerprint as final. A ticket that only recorded (autonomy `record`, a dry run, the daily cap, a failed judge session) uses the pause findings up: they are not handed again when the hold lifts. And `loop_started` is written by the detached child, so a second final exit of the thread before the child starts hands the same findings twice.
3. The loop cannot see why an operator answered a pause. The judge is told "feedback given" and never the text (SIL-B38), so a false check finding from an engine defect, a judge that did not read, an environmental failure and a plan row a session cannot do look alike: on the review's threads all four were answered `proceed` or `retry` with feedback.

Acceptance criteria:

1. A waiting outbox entry is checked at delivery against the open issues read at that filing: a create whose fingerprint or cause an open issue holds becomes a comment within i171b's bound, and a create whose cause is muted is dropped with a `loop_result` record that holds the fingerprint and no text. An entry older than `outbox.max_age_days` (a loop parameter in `improve/params.py` with its source) is dropped with a record and not sent. `loop-issues` or `self-improvement` states the three behaviours, and a test proves each with the memory code host.
2. `tempergraph` has a verb that lists the outbox (op, repository, title or issue number, fingerprint, age; no body) and one that clears it, whole or by fingerprint. `engine-cli` states them, `--help` shows them, the guide names them in its section on holding filing, and a test runs both on a fixture outbox and finds the cleared entries gone and the others kept.
3. A pause finding handed to a ticket that filed nothing because the ticket only recorded (autonomy `record`, a dry run, the daily cap, a failed judge session) is handed again at the thread's next final exit. A finding with a recorded judge answer is not sent to the judge a second time: its recorded answer is used, so a thread adds one answer per fingerprint to the counts of i171b's criterion 1. A waiting or claimed ticket of the thread covers its fingerprints, so two final exits before the first child starts hand them once. SIL-B28 states all three, and says that a thread whose last exit was under a hold has no later exit and its pause findings stay recorded only. A fixture proves each: a thread stopped under `record`, re-opened and finished without it files once and asks the judge once; two exits with the first ticket still waiting give one judgement.
4. A decision may carry one reason from `engine_defect`, `judge_error`, `environment`, `plan`, `request`, `other`, given on `resume` with an option; any other value is refused with exit 2 and no free text is accepted. The reason is on the decision's ledger row and in the facts row the judge reads ("operator reason `<word>`", or "operator reason not given"), and the judge's brief says that a reason other than `plan` or `request` points away from the workflow's step. `engine-cli` and SIL-B37 state it, `resume --help` shows it, and a fixture proves the row, the fact, the brief's sentence and the refusal.
5. The specs changed by this run state what the code does without naming any workflow, stay within the spec budget, every new parameter is in `improve/params.py` with its source, and each new test carries the id of the spec criterion it proves; the tests of i170b, i171b and i172 still pass, changed only where a criterion above changes the fact they assert.

Out of scope, each to be filed as a follow-up issue and named in the report unless the report of i170b already filed it:

- The id of a failing check is not in `check_fail:<unit>`; a `blocked` pause caused by a capability the session lacks is class `designed` and never judged; a judge verdict that flips with the workspace unchanged has no cause code.
- A stop by request is a final exit that judges and files though the thread goes on; it has no cause code.
- No lock around "read the open list, then create" (finding 6 of the i171 review); it holds for an outbox delivery as for a new filing.
- `pause_fingerprints` do not reach the loop's proposer (finding 10 of the i170 review).
