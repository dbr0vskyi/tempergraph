- Why this design: the unit record gets its own `UnitSpec` field, because `_release` refuses `extra` and every field of SWF-B7 must be recorded. One new engine module reads a child from the registry and holds every check that needs a child, so `validate`, the start and `run --check` share it (WFM-AC2). `validate` reads the child only when the workflow has a sub-workflow unit, so every other workflow validates as before and never touches the registry. `needs_git` and the interim stop (SWF-B11) are start-time, after every other refusal, as the hand-off decided; the interim stop is not a finding of `validate`, so a valid parent still passes validation.
- Open question taken at its default (hand-off Option A): the builder reads each `inputs` value into `request`, `<unit>.<key>` or a quoted literal, and a value of any other form fails when the declaration is built; validation adds no refusal beyond SWF-B6's list.
- Order of the interim stop in the run path (hand-off): after validation findings, settings, executor preflight, `needs_git` and the carry check, before `ensure_state_root`.
