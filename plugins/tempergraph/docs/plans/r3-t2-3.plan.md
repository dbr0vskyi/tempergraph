## 2. Phases

### Phase 1: The child's own judges

Goal: a child gate and a parent gate of one name each judge on their own bindings and calibration cases (R1), proved on a fixture parent and child whose parameters (`issue_repository`, calibration cases, judge alias, an effort ladder on the `work` step) the shared module `tests/fixtures/subworkflows.py` takes and later phases reuse; the code reads a gate's observed binding and production grade by the child path of its owner in `improve/calibration.py`, `improve/reliability.py`, `run/subrun.py` and `run/nodes.py`.
Weight: medium

### Phase 2: Findings filed to the child

Goal: a friction finding on a child unit is recorded and filed under the child's workflow name, version and `issue_repository` with `sides: [workflow]`, naming the parent (R2), proved on the loop's inline run with a stand-in code host; the code is in `improve/causes.py`, `improve/record.py`, `improve/filing.py` and `improve/child.py`.
Weight: medium

### Phase 3: Measures and the promotion window

Goal: the child's outcome record from inside a parent counts in `outcome show <child> --runs` with `origin: subworkflow:<parent>`, adds no `run_segment` row and no folder under `runs/`, and stays outside the child's promotion window (R3, R4); the code is in `run/outcome_record.py`, `run/runner.py` and `improve/promotion.py`.
Weight: medium

### Phase 4: The parent's upgrade reads the child's change notes

Goal: `upgrade <parent> --check` reads a child's `changes/<version>.json` and plans a `rename_field` item at the parent's reference to a renamed produced key, and `upgrade` applies it by a transform that renames a produced key in the parent's templates and declarations (R5); the code is in `package/transforms.py`, `package/changelog.py` and `package/upgrade.py`.
Weight: medium

### Phase 5: Spec 63's criteria are named by tests

Goal: WUP-AC1, WUP-AC4 and WUP-AC7 are each named by tests that prove them (R9): a new test of `--check` against `upgrade-check` with the hash of the source, the state root and the package before and after; the two WUP-B8 tests of `test_upgrade.py` carry WUP-AC4; and the tests of an assisted edit gated by rules and a judge (`test_upgrade_workflow.py`), an owner pause (`test_upgrade.py` and `test_upgrade_workflow.py`), a sub-workflow's rename (`test_subworkflow_upgrade.py`), authoring's re-approval exception (`test_audit.py`) and `--no-assist` (`test_upgrade.py`) carry WUP-AC7. These tests prove behaviours spec 63 already states; a test that fails there is a defect of the code, and the code step reports it.
Weight: medium

### Phase 6: Carrying a parent paused inside its child

Goal: a parent carried on a branch, paused inside its child, resumes on a second state root and finishes, the child continuing where it paused (R6), on the two-state-root `World` pattern of `tests/test_carry.py` with the child registered in both homes.
Weight: light

### Phase 7: Documents and release record

Goal: the documents say what is built: spec 99 loses its Open questions section, spec 63 loses the clause about a sub-workflow's change notes, the release 3 plan records R3-T2.3 and track R3-T2 as built, and `tests/test_subworkflow_docs.py` follows; the offline suite, lint and types pass (R7, R8).
Weight: light
