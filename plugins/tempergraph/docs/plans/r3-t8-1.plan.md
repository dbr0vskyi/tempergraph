## 2. Phases

### Phase 1: Script cache

Goal: a script with `cache: thread` hits, restores and misses as SCR-B9 and SCR-B3 say, and validation no longer refuses it.
Weight: medium

### Phase 2: Audit judge and its settings

Goal: with `audit_rate` and `audit_executor` accepted, a second judge runs on a sampled gate's subject and leaves every verdict, route, counter and budget as in the run without audit (JDG-AC7).
Weight: medium

### Phase 3: Judge view catalog

Goal: a judge's MCP views come from the constant catalog and never from a step's own tool, with GRD-AC6 passing before `judge_mcp` is set.
Weight: light

### Phase 4: Filtering proxy and private configuration

Goal: a `claude` judge launch with catalogued MCP views carries `--tools` of the built-in views, a private strict MCP config with one filtering proxy per viewed server, and mode `dontAsk` (ECC-AC7), tested against a stand-in MCP server.
Weight: heavy (many-tests)

### Phase 5: Deferral and the `judge_mcp` flag

Goal: a view of a server that cannot be proxied is deferred before the judge prompt is rendered and its criterion cannot be MET (ECC-AC8), and `judge_mcp` is true on `claude` (ECC-AC9) with the tests that pinned the old outcome updated.
Weight: medium

### Phase 6: Documents and release gate

Goal: the specs' "Not built yet" lines name only what is left, the release 3 plan and the live checks record this phase, and the offline suite, `ruff` and `mypy` pass.
Weight: light
