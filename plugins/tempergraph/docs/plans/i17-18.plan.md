## 2. Phases

### Phase 1: A writing map is refused outside git

Goal: a workflow whose concurrent map's step declares `write` or `edit`, started in a folder outside git, is refused `needs_git` naming the map before any session starts and before anything is created, `run --check` reports the same refusal, and a read-only concurrent map adds none (R1, R2). The reason joins the writer-branch reason in `unit_reasons` of `model/subworkflow.py` (the start in `run/runner.py` and `run --check` in `cli/main.py` both read it, and so does a child tree), the tests are in `tests/test_outside_git.py` and carry WSP-AC21 to WSP-AC23 and `AC 1`.
Weight: light

### Phase 2: A later visit's item names and cut

Goal: `writer_names` and `cut_writers` in `workspace.py` take the visit of a map as a keyword (default 1) and, for items of a map's visit above 1, name the folder and branch `--i<n>-<item>` (the first visit's `--i-<item>` unchanged, the shortened name's digest told apart by visit), cut them from the run branch's head, record each child with a `visit` key (a first-visit child keeps its present keys), reuse a child only of the same slot and the same visit, and keep the children of other visits in the record when it cuts (R3, R4). The tests are in `tests/test_workspace.py`, beside the cases of lines 119 to 159 that stay as they are, and carry WTR-AC13 and MAP-AC13.
Weight: light

### Phase 3: The second visit runs and merges its own items

Goal: in `run/nodes.py` a writing map entered again cuts its items for the visit it is in, an item node finds its worktree by slot and visit, and the join merges the children of the visit it ends and no other (R3, R4, R5): `map_move` and `_enter_writer_map` pass the visit to `cut_writers`, `_writer_child` and `_child_of` match the child of the map's current visit (a contest slot and a writer branch keep visit 1), `_merge_items` and `_merge_children` take the visit, and `_map_finish` passes it. An offline test file with scripted executors and a scratch git repository covers a trip back into a writing concurrent map by a join gate (the planning step writing a second list, the items writing different files in the second visit): each second-visit item runs in a worktree and on a branch the first visit did not make, starting at the head the run branch held before the visit's first item session and holding the rewritten list file and the first visit's merged files, the first visit's branches and worktrees stay as they were and the record lists both, the run branch gains one merge commit per second-visit item in list order with that item's second-visit branch as second parent, and a second visit paused on a spent budget and resumed with `retry` reruns the item in its second-visit worktree. The tests carry MAP-AC10 to MAP-AC14, WTR-AC13 and `AC 3`; no existing test pins a signature changed here (`_child_of`, `_merge_children`, `_merge_items` and `_enter_writer_map` are called by no test).
Weight: medium
