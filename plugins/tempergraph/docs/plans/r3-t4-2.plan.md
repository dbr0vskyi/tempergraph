A session that works from this plan starts from the hand-off's reading list and opens another file only for what the list does not answer.
- Why this design: a contest is a map whose items are slots, so it follows the concurrent map where it can: the per-slot state views of `compiler/state.py`, the reservation width of `_hold`, and for a writer contest `cut_writers` (with a third `kind`, names `--s-<slot>`), `fork` and `_merge_writers`. A contest compiles to the unit's four nodes (CMP-AC6) and is drawn as one unit with its slot count (CMP-B16). The work is ordered so each phase is testable alone: declaration and refusals, then slots with their check, judges and pick (the heavy phase, shared helpers of the map change), then the attempt cap and reservations, the settings keys, the retries and failures, the writer contest, the run detail, and last the audit rule and the documents.
- Choices taken from the hand-off's Open questions, none of which blocks planning; the code report names each: (1) preflight shows no projected cost range for a contest, as the open question of spec 72 says until the owner answers; (2) a slot of a `writes: false` contest that changes the run's worktree fails like a read-only branch or map item (`branch_changed_the_workspace`, WSP-B11); (3) the fixtures of CTS-AC4 cover a writer merge on one attempt, and a second attempt of a writer contest ends blocked rather than overwrite an existing slot branch.
