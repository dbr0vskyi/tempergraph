## 2. Phases

### Phase 1: The cap counts what repeats

Goal: a forward-only run of any number of units, map items, council members and child units is never stopped by the cap, and a loop or a repeated failure still is, at the count CMP-B19 states.
Weight: medium

### Phase 2: The exit at the cap says what repeated

Goal: the `run_exit` record and the JSON `payload` of an exit with reason `attempt_cap` hold `attempts_counted`, `trips_back` and `repeated`, equal in both.
Weight: light

### Phase 3: A thread stopped by request resumes with no decision

Goal: for each of the modes `drain` and `now`, a plain `resume` of a thread stopped by request goes on from the interrupted or due attempt and ends as the same run without the stop, leaving no request file and no budget charged; each defect the fixtures show is fixed where it arises.
Weight: medium

### Phase 4: A refused re-open names its stop, status gives the command

Goal: a `resume` refused on a stopped thread names the unit and the reason of the stop, and `status` gives an unfinished thread the plain `resume` command, with the stale-request and stronger-mode cases proven unchanged.
Weight: light
