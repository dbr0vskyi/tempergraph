- Why this design: the tick is one module of pure decisions plus injected edges (clock, run launcher, process-group starter, credential resolver), so every test runs with a fake clock and a scripted launcher and starts no model. The order follows the dependencies: the person-only rule and the token (written at `add`) first, then the credential check that `add` and the fire both call, then the ledger the tick appends to, then the tick, `fire` through the tick's path, the run-side records, the triggers that call the tick, the export, the skill, and the documents last. `schedule loop` and the `host` adapter come before the `os` adapter because the loop is the default trigger and the `os` entry only starts it.
- Spec edits this task makes necessary, reported as the documents rule asks: SCH-B33 and SCH-AC12 of spec 83 say `fire`, `tick`, `loop`, `trigger`, `runs` and `export` are refused `not_in_release`; once built that is false, so both narrow to `schedule add --orchestration` (and SCH-B27's WHEN clause drops the carve-out of the six verbs). The open questions "Not built yet" of specs 83 and 84 are rewritten. No other behaviour or criterion of a spec changes.
- Orchestration (TCK-B9 and the `orchestrate` parts of TCK-B16 and TCK-B17) is release 4 by ADR-0132: no orchestration target can be saved (`add --orchestration` stays `not_in_release`), so the tick has no orchestration path to run and no test claims one.
