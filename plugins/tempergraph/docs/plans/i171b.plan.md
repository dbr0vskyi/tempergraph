## 2. Phases

### Phase 1: The decision

Goal: `decide` in `improve/filing.py` files a friction finding below the floor by the count only on the majority of FFD-B1 and gives each finding that does not file exactly one of `not_judged`, `not_attributed`, `few_answers` or `below_count`. `Candidate` gains `earlier_answers`, the attributed flags of the answers already recorded for its fingerprint inside the window, and `decide` adds this exit's answer; a finding at or above the floor still files, with reason `pattern_met` and its counts when the rule is met and `fault` and no counts otherwise. `Decision` gains `counted`, the runs, requests and machines for every judged friction finding of class `fault`, kept apart from `counts`, which alone reaches an issue body. `_pattern` counts a request once per thread, by the first digest the thread recorded for the fingerprint in the window, and the exit's run counts by its own digest, for both lenses. A new function of the module reads the `loop_judged` records of the workflow's runs in a state root into the answers per fingerprint inside the window, by the record's time. The tests that pinned `below_floor` and the histories with no recorded answers are changed in the same phase.
Weight: medium

### Phase 2: The loop child's records and the judge's brief

Goal: `improve/child.py` reads the recorded answers before its own judge writes `loop_judged`, passes them to each friction candidate, and writes the decisions' records: each `loop_result` for a judged friction finding of class `fault` holds `runs`, `requests` and `machines` as numbers, and each `issue_filed` and `issue_commented` record holds the decision's reason and, for a comment, the issue's number and repository. `BRIEF` says that an answer `attributed: true` can file a finding by the count whatever its confidence. The tests of `test_loop_child.py` that named `below_floor` name the new reasons, and each reason of FFD-B2 and FFD-B3 and of SIL-B35 is named once by a test that reads the records of a fixture loop child.
Weight: medium

### Phase 3: Duplicate close and the comment bound

Goal: `file` in `improve/filing.py` mutes a cause for `mute.days` when the issue closed most recently was closed as a duplicate, as it does for not planned, and takes the number of "seen again" comments each issue got today from the `issue_commented` records the child reads and passes in, in the workflow's runs of the state root, by UTC day. A comment over `seen_again.max_per_issue_per_day` is not sent, no issue opens in its place, and it leaves one result with op `comment_capped`, the issue's number and no text. The parameter `seen_again.max_per_issue_per_day` (1, `default_no_data`, source ISS-B13) is added to `improve/params.py`. The test that expected a duplicate close unmuted now expects `muted`, and the cases for not planned, completed, no reason and a reason not read keep their results.
Weight: medium

### Phase 4: The operator's hold by a setting

Goal: the catalog of `settings.py` holds the run key `loop_autonomy` (`record`, `file`, `propose` or `trial`, no default) beside `loop_model`; `improve/proposals.py` `autonomy` returns the lowest of the declared level, `TEMPERGRAPH_AUTONOMY` and the setting; and the value comes from the thread's snapshot resolved again against the settings files at the final exit, in the way `durability/status.py` resolves a snapshot, passed through `hand_to_loop` in `run/runner.py` to `hand_off` in `improve/child.py`. The exit of a run, the stop's exit and the exit recorded for a lost runner (`improve/lost.py`, which has the snapshot in the thread's values and no settings) all take it. A test starts a thread, pauses it, writes `record` to a settings file, resumes it to its final exit and finds no issue, no comment and the reason `autonomy_record` on each finding; a second case lets `trial` leave a workflow declared at `record`, and a third removes the setting before the exit. The check that every catalog key resolves from each layer (RST-AC1) covers the new key.
Weight: medium

### Phase 5: `--dry-run` on `resume`

Goal: `cli/main.py` adds `--dry-run` to the parser of `resume`, lists it in `resume --help`, and builds the run settings of a resume with `dry_run` set when it is given, so the thread's final exit hands its findings to a loop that makes no call and records `would_file`; the hold lasts for the later segments of the thread as it does for `run`. A test resumes a paused fixture thread with it and finds no issue, no comment and a `would_file` record, and reads `resume --help`.
Weight: light

### Phase 6: The guide and the replay

Goal: a test reads `plugins/tempergraph/docs/guides/improving-workflows.guide.md` and holds its section "Hold filing" against the built CLI and catalog: the three holds, the key `loop_autonomy`, `--dry-run` on `run` and on `resume`, `TEMPERGRAPH_AUTONOMY=record`, `tempergraph config paths`, and the mute by a close as not planned or as a duplicate for `mute.days`; the guide is edited only where the code differs from it. A replay test in a new file of the engine's tests, with a scripted judge and the memory code host, runs five runs with five requests of a fixture workflow whose findings hold, in each of at least three runs, a pause answered by an agent (`agent_decided:escalation`), a check failure at a step whose check ran the repository's suite and failed for the environment, and `retries_spent` after a usage limit, with the judge attributing each in one run only; it finds no issue and no comment for any of the three causes at any exit, and one issue at the third exit and comments within the bound for a fourth cause the judge attributes in every run. The new parameter, the specs this run changed and the new tests are checked against the twelfth criterion: no workflow named in the specs, a source on every parameter record, a criterion id on every new test.
Weight: medium
