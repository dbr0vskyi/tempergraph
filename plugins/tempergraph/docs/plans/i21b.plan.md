The hand-off's reading list was the start; its other entries (EXI-B1, EXI-B17, TSA-B12, RST-B29, `audit/tools.py`) were not opened again because the list's own notes answer what the plan needs from them.
- Extra files opened, each for what the list does not answer: `engine/src/tempergraph/run/runner.py` (lines 720-760) and `engine/src/tempergraph/cli/main.py` (lines 480-500), to see that preflight is called from six places with no working folder; `engine/src/tempergraph/contracts.py` (lines 590-600, 693-733), for the fields of `SessionResult` and `ProbeReport`; `engine/src/tempergraph/executors/standins.py`, to see that a stand-in executor has no MCP method, so a preflight check that asks the executor for one leaves stand-ins alone; `tempergraph.commands.json`, for the commands a verification line may start with.
- Why this design: the spec states each rule, so the plan only follows it. The flag refusal lives in the `claude` probe (ECC-B21) and reaches preflight through the probe's existing reason word `probe_failed`, with the flag named from the probe's facts, so `ProbeReport` and `ProbeWord` keep their shape and no test that pins them changes. The undefined-server refusal is asked of the executor through an optional method that preflight looks up by name, as `run/nodes.py` already does for `unreachable_views`, so the engine's preflight names no executor. The launch refusal (ECC-B23) is the same check made again at launch, because a configuration can change after preflight and preflight reads the folder the command runs from, not the run's worktree.
- The live test is skipped without `TEMPERGRAPH_LIVE=1`, and the gate accepts a proof only from a test that is not skipped. The proof of AC 1 is therefore an offline test of the helper that reads a session's turns, fed with streams shaped like the operator's measurements; the live test calls the same helper.
- Preflight covers a step, a map item and a contest slot, which all declare their tools in `u.step`. A council member is not a step in ECC-B22, so its declared server is checked at launch only (ECC-B23); the plan adds no preflight rule for councils.
- The spec `executor-claude-code.spec.md` is 30,149 of 30,720 bytes: no row may edit it, and none needs to (the spec already states the rules for AC 3, 4 and 6). A later change to it must first split the MCP isolation capability out.
- Open question of the hand-off, taken with its default `a`: the data fix widens `range` to `>=2.1.329,<=2.1.332` and lists 2.1.329 and 2.1.332 in `recorded`, so 2.1.330 and 2.1.331 also read as recorded.
- ECC-B13's sentence is over 500 characters (reported by discovery as it was before the task); the plan changes no spec.
