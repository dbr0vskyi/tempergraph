The read, the finding and the filing sit in the loop child beside the proposal read (PRP-B26, PRP-B28), so they inherit its conditions: autonomy `file` or above, no dry run, a host that cannot be reached changes nothing.
- Detail that serves OUT-B24 and adds no behaviour: "the commits the run's branch did not hold when it ended" needs the commit the branch held at the run's end, so the pull request record on the ledger row also holds that commit id (no text); "the files the run wrote" and "the units that wrote them" come from the run log's `agent_run` records, which name the paths each session changed.
- Tests use fixture workflows from `tests/fixtures/`; none names a shipped workflow (`tests/test_source_rules.py`).

Files opened beyond the hand-off's list for this: `plugins/tempergraph/engine/src/tempergraph/run/finalize.py` and `durability/status.py` (FIN-B8 says a `skipped` outcome with manual steps and an `error` outcome write one line to standard error and show the steps in the status document, and no code does either: `manual_steps` is read nowhere beyond the `finalize` event, so FIN-AC1 cannot hold without code rows), `improve/lenses.py` (`decide`, `STABLE_FRICTION`), `improve/record.py` (`record_exit`, where `outcome_unmet:<id>` is made), `run/outcome_record.py` (`measures`) and the tests `test_improve.py`, `test_outcome_record.py`, `test_outcome_escapes.py`, `conftest.py`.
