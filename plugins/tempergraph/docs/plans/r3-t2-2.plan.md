The behaviours of other specs that spec `subworkflow-unit` cites (BUD, OBS, CMP-B17, MIG-B15, OUT-B18, RST-B22) are used only as spec `subworkflow-unit` states them; none changes.
- Started from the hand-off's reading list. Opened beyond it, each for what the list does not answer:
  - `plugins/temperspec-tgraph/rules/plan.rule.md`: the plan format.
  - `plugins/tempergraph/engine/src/tempergraph/model/subworkflow.py`: the child reader of phase R3-T2.1 that this task builds on (`read_child`, `Child`, `exposed_keys`, `stop_message`).
  - `plugins/tempergraph/engine/src/tempergraph/compiler/graph.py` and `compiler/state.py`: the graph has four nodes per unit and no handling of a `subworkflow` kind; run state is one `RunState` whose channels are keyed by unit name.
  - `plugins/tempergraph/engine/src/tempergraph/run/nodes.py`: `EngineNodes` and `RunContext` are bound to one spec (`ctx.spec`); `step` dispatches on the unit kind, `_boundary` reads the run cost cap from `ctx.spec` and the cost from state, `_session` and `step` write session keys, the gate funnel (`gate`, `human`) is per spec.
  - `plugins/tempergraph/engine/src/tempergraph/run/runner.py`: `_drive` writes `run_started`, the engine record and `workflow_changed`; `_start` holds the interim stop (`subworkflow_stop`); `_resume` compiles the thread with inert nodes, checks the decision with the parent spec and breaks on a changed version.
  - `plugins/tempergraph/engine/src/tempergraph/durability/checkpoint.py`: `snapshot` reads a pause from the parent's tasks, so a child's pause surfaces as the parent's.
  - `plugins/tempergraph/engine/src/tempergraph/run/log.py`: `RunLog.write` is the one writer of `run.jsonl`; the unit of a record is split from its `session_key` when absent.
  - `plugins/tempergraph/engine/src/tempergraph/run/gate.py` (names only), `run/outcome.py` (`with_outcome`), `run/outcome_record.py` (`build`), `engine/tests/fixtures/subworkflows.py` (the fixture parents and children of phase R3-T2.1).
- Why this design: the child runs as a LangGraph subgraph that the sub-workflow unit's step node invokes, so it shares the parent's checkpointer, thread, workspace and lock (ADR `a-sub-workflow-runs-inside-its-parents-thread-workspace-and-cap`). It gets its own compiled graph, its own `EngineNodes` and its own run state, because `EngineNodes` and every state channel are keyed to one spec's unit names and a child's `work` must not meet the parent's `work`. The child's context shares the parent's log, registry, state root, drain check and run cost cap, and starts from the parent's cost so the one cap holds; its log writer adds `child: <unit>` and its session keys are prefixed `<unit>/`. The unit's step node hands back only what `produces` exposes (artifacts and values under the unit's name), the cost the child added and the child's outcome verdict, so the parent's existing gate, judge and template reading work unchanged. The step node never calls the child's finalizer. The checks of each phase settle how the child's pause payload, checkpoint namespace and per-child engine record are named.
- Tests pinned to what this task removes, which the expand step gives rows: `engine/tests/test_subworkflow_start.py` (the `not_in_release` refusal of `run` and `run --check`), `engine/tests/test_subworkflow_docs.py` (the Open questions line of spec `subworkflow-unit` and the R3-T2.1 status line). `engine/tests/test_blueprint.py` and `author/blueprint.py` keep refusing `kind: "subworkflow"` (SCF-B9); they stay.
- Scope: SWF-B9 and SWF-AC3 are not built here (task). No behaviour outside spec `subworkflow-unit` is added; the refusals of SWF-B6 and the declaration of SWF-B7 stay as they are.
