- Why this design: the launcher already owns the one place a child's environment is built (EXI-B22, EXI-B23), so it learns a general, per-launch way to drop names by prefix and keep exact exceptions, and the `claude` executor asks for it on every step, retry and judge launch with ECC-B14's constants. The overlay is laid after the filter, so the engine's own names and a judge's credentials always arrive; the model-free probes keep today's environment, because ECC-B14 says nothing about them. `--tools` becomes unconditional in `step_argv`; enforcement keeps its other effects (strict MCP config, preflight refusal). Open questions 1 and 2 of the hand-off are read as option (a) in both cases ("Until answered"): the task's list of kept names, and no MCP change.
