- Why this design: the engine owns the base run (`run(cmd, at_base=True)`, one launcher with CHK-B12's limits, one reuse store, nothing left in the repository), and the package owns what a base result means (the same exit code, or no changed path in the output). The plan follows the hand-off's decisions; the five acceptance criteria are `AC 1` to `AC 5` of the triage note.
- Complexity: `complex`. The bytes of the files and specs the rows will name are over 200,000 (estimated from line counts, with no shell here: package `checks.py` 950 lines, `test_temperspec.py` 996, `outcome.json` 1,159, four engine files of 145 to 242 lines, two specs, the README). Three phases and three verification commands; the expand step counts the rows.
- Assumptions, each from a spec, a decision record or the hand-off:
  - Criterion 1 is read as the package decision record reads it (a base failure with another exit code and a changed path in the output is retried); the engine's editable-install question stays as the spec has it: the base run has the workspace's environment.
  - The base checkout is `git clone --shared --no-checkout` of the workspace and a detached checkout of `git.base`, made through the git reader inside a folder the engine process allots (a `tempfile` folder outside the workspace and the main checkout) before the worker starts and removes after the worker ends, and the check also removes it when it returns or raises. The engine's decision record lets the plan pick another way with the same observable result.
  - A commit that is not a full commit id is refused, and the run is `not_started`.
  - The base reuse key is argv, the resolved program path, the command's folder, the base commit, the unit and the visit (the folder is in the workspace key's code as well).
  - A base run asks for `min_start_s` equal to the gate run's duration, so a base run that cannot finish in the time left is `not_started` and the command is retried as before (ts-code-nobase). The check's limit stays 1800 s.
  - A base run's `tail` and `program_path` show both the workspace and the base checkout as `<workdir>` (CHK-B12, CHK-AC4), because a command at the base can print a path of either.
  - An environmental command is a `fail` finding when no other kind of finding fails (the result is then marked `environmental`), and a `maybe` finding otherwise, so the retry lists only what the step can fix (ts-code-mixed). Its line leads the evidence, so the log's 200-character clip keeps the command, both exits and the reason.
  - The outcome gate's own `_verify` call keeps its behaviour: the comparison is a parameter that only the code gate passes (the task names the code check).
  - The step's `tests_passed: no` no longer ends the code check before a command runs; no test pins the shortcut (searched `tests_passed` in both test folders and the evals).
  - Tests carry the ids the outcome gate's `ts-traced` asks for: CHK-AC8 to CHK-AC11, and CHK-AC1, CHK-AC2, CHK-AC4, CHK-AC5 and CHK-AC7 on a test that asserts the part of that criterion this run changed.

## 2. Phases

### Phase 1: The engine runs a command at the run's base

Goal: a check's `run(cmd, at_base=True)` runs the command in a checkout of `git.base` that the engine makes and removes, reuses the result for the rest of the visit, starts nothing when the base cannot be had, and an environmental FAIL with both runs escalates with no judge and no retry; the source scan of launch sites still passes.
Weight: medium

### Phase 2: The code check compares a failing command with the base

Goal: the code check runs every verification command, asks for the base result of each command that failed at the gate, and returns an environmental result, a retry, or a mixed failure with evidence that names each command, its exits and the reason; the outcome gate's run of the commands is as before.
Weight: medium

### Phase 3: The package's criteria and README match

Goal: `outcome.json` holds the seven new rows of the package spec with their verifiers, a test holds them to the spec, and the README says the code gate compares a failing command with the base.
Weight: light
