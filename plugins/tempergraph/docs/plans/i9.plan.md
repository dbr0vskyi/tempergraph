- Extra files opened beyond the hand-off's list: `plugins/tempergraph/engine/src/tempergraph/run/log.py` (`Ledger.append` stamps every row with `ts`, which the merge boundary compares); `plugins/tempergraph/engine/tests/test_loop_issues.py` by search (two tests call `MemoryCodeHost.reopen` on a host that is up, so a `down` check added to it breaks neither); `plugins/tempergraph/engine/tests/test_loop_child.py` lines 384-398 (the quiet-exit hand-off test that must keep returning no ticket when there is no proposal to watch). `params.py` and `trials.py` were not opened: the hand-off's lines name the parameters (`trial.after_release_runs`, `trial.guard_cost`, `measure.quality_drop`) and the plan reads them by name
- Why this design: spec 40 says the loop reads the pull request at every final exit of a workflow with an `opened` proposal (PRP-B26), including a clean exit, and the child is started only when a ticket is written (`hand_off`, `child.py`). So `hand_off` writes a `watch_only` ticket for a final exit outside a dry run and a trial, at autonomy `file` or above, when the workflow has a proposal to watch (`opened`, or `merged` with no `regressed_after_release` or `held_after_release`); `process` reads the state first, then runs the post-release comparison, and a `watch_only` ticket ends there. SIL-B1 says when the engine SHALL write a ticket and not that it writes one only then, so SIL-B1 is not edited. The comparison lives in a new module `improve/release.py`, because `measure.py` imports no writer (a source test, `test_measurement_writes_nothing_but_one_comment`, enforces it) and only gets the pure window figures. The module is not named `watch.py`: `audit/owned.py` imports `tempergraph.improve.watch.prompt_moved_gates` when such a module exists
- Decisions of the hand-off kept: a pull request closed without a merge records `pr_state` `closed` and the proposal stays `opened`; "worse" is the four figures of SIL-B5 with `trial.guard_cost` (cost per run up more than 15 %) and `measure.quality_drop` (gate first-try pass rate or met share of outcomes down more than 5 points), a figure counting only when both windows have it, repeat share reported and never deciding; the boundary is the merge time the host reports; the pull request is read with a GET of the pull request, never the merge endpoint, and the new method is named `pull_state` (PRP-AC2: `test_no_code_path_merges` in `tests/test_proposals.py` rejects a string constant equal to `merge`, containing `/merge` or starting with `merge `, and a `merge`, `merge_pr` or `merge_pull_request` attribute of `MemoryCodeHost`, so tests set a stand-in pull request merged by editing its dict in `host.pulls`, with no new method)
- Not changed: `loop_report.py` keeps printing `merged` and `held after release` as not derived (wiring them is outside this change); `LIVE_STATES` in `autonomy.py` already leaves out `merged`; `improve show` stays read-only (PRP-B22)
