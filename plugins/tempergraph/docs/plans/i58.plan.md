- Assumptions, to be repeated in the code report: (1) the closed-issue read runs only after the open-issue search succeeded and found no match; when the open search failed twice the finding files as it does today, with its `search_failed` note. (2) `filing.file` takes an optional `now` so a test sets the age of a close without waiting. (3) New text in `filing.py` and `codehost.py` holds no lowercase `evidence`, because `test_filing.py` line 77 searches both files for it; the heading `## Evidence` is capitalised. (4) A `muted` result is not counted as filed: `loop_summary.FILED_OPS` stays `filed` and `commented`. (5) The comment on a trial names the cluster's issues by the URLs of the loop's own records (`proposals._issues`), and only issues of the repository whose `issue_repository` the workflow declares get `Closes #<n>` (PRP-B24).
- Trip back (reason: "SIL-AC3 is named by no test"): `SIL-AC3` (spec 16, reworded by discovery to "one open issue ... never a second open issue") appeared in no test comment; the one test that exercises it, `test_dedup_retry_dry_run_and_outbox` in `test_filing.py`, carries `AC-3`, which is not the criterion id.
