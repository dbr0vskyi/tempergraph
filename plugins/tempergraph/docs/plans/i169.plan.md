## 0. Hand-off

- Triage note: `plugins/tempergraph/docs/tasks/i169.triage.md`

- Extra files opened beyond the hand-off's reading list, each for what the list does not answer: `tempergraph.commands.json` (the commands the verification may start with); `plugins/tempergraph/engine/src/tempergraph/improve/record.py` lines 205-275 (how a run's exit writes the digests and the findings that the fixtures read back); `plugins/tempergraph/engine/src/tempergraph/run/log.py` lines 300-314 (the run-log reader `last_record`); `plugins/tempergraph/engine/src/tempergraph/run/events.py` lines 52-55 (`records`, which reads every record in order); `plugins/tempergraph/engine/src/tempergraph/contracts.py` (`ToolCall` has no capability field); `plugins/tempergraph/engine/tests/test_improve.py`, `test_map.py` and `test_session_review.py` (helpers and names to reuse).
- Why this design: the specs already state the rule (SRV-B34 to SRV-B36) and the specs are not changed by this plan. A visit's entry commit is already in the run log as the `unit_entered` record (EVT-B12) for every unit kind, so the judge's launch reads the first record of its unit and visit and gives `git.changed_paths` that commit as its base. An item of a map has no record of its own, so its attempt record carries the commit read when its first attempt of the visit started, and a retry carries it on from the earlier attempt. `git.changed_paths` already takes a base and covers committed and uncommitted paths, so `git.py`, `improve/digest.py` and `improve/review.py` do not change: the digest and the citation check already read the counts.
- Not planned, by the hand-off's open questions taken at their defaults: the judge prompt's own count of changed files (`run/nodes.py` line 1658) stays as it is; a workspace outside git and a contest slot's judge are not changed beyond what SRV-B34 states.
- Tests pin no signature this plan changes: a search of `plugins/tempergraph/engine/tests/` for `_script_failed` and `_judge_session` finds none, so no existing test needs a row.
