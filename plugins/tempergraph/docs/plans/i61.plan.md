- Why this design: one parameter, `digest.judge_read_share` (0.25, `default_no_data`, SRV-B29), is read by the citation check and by the new cause, so the two cannot disagree about a judge that read too little. The new cause `judge_partial_read` sits beside `judge_unread_pass`, which keeps its zero-read, pass-only rule and its two assertions (`test_session_review.py` 99, 100). A judge "gave a judgement" when its `judgement` record's `confidence_source` is not `engine_placeholder`, matched to the judge's digest by unit and attempt; `record.py` builds that fact into the `judged` map as a new key `gave` (the attempts with a real judgement) and does not reuse `passed`, which reads a placeholder as a pass.
- Assumptions recorded: "grader side" in SRV-B12 and SRV-B29 means the fault is fixed in the judge's brief, criterion or model, which the cause table records as side `workflow` (the one value that fits a workflow's own judge); the code keeps `workflow` and the spec's words change (the table's vocabulary has no `grader`); the default 0.25 is the discovery step's choice (open question of the hand-off, recommended option a); "under the share" is strict, so 3 of 12 is not under it; a gate with several judge items in one attempt counts as having given a judgement when any of its records for that attempt is not a placeholder; a `judged` entry without `gave` (as in the two existing assertions) means no judgement is known, so no `judge_partial_read`.
