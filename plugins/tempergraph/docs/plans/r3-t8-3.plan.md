- Files opened beyond the triage note's list, and why: `plugins/temperspec-tgraph/rules/plan.rule.md` (the machine-wide rule path is outside this working directory, the plugin ships the same file); `plugins/tempergraph/engine/src/tempergraph/audit/__init__.py`, `audit/catalog.py`, `audit/report.py`, `audit/prompts.py`, `cli/audit.py` (where the layer is refused today and where rules are registered); `executors/capabilities.py` (the four executors' tool maps that TSA-B3 reads); `executors/summary.py`, `executors/session.py`, `improve/digest.py` and `run/log.py` (what a run records: `session_started.tools`, `tool_started.input_summary`, denied names, activity journals); `improve/lenses.py` (the cost lens that ARC-B1 renders); `plugins/tempergraph/docs/plans/third-release.plan.md` (the Status line to write); `plugins/tempergraph/docs/guides/authoring-workflows.guide.md` (the only guide that names the audit: line 122, `tempergraph audit <workflow>`, stays true, so it gets no docs row; the code step reads the guides again at the end).
- Why this design: the audit gains a history reader that turns the workflow's local run records (run log, activity journals, digests) in `--window` and `--version` into per-unit facts, and every history rule reads those facts only; the tool surface is built once per session from the executors' tool maps, the manifest and (when present) the same facts, and both the C4 rules and the `audit tools` matrix read that one surface, so the matrix and the findings cannot disagree. Rules join the catalog with their `min_n` and `built` release; a rule whose input is missing is listed as skipped with its reason, never as passed (ARC-B7).
- Scope note: the catalog's history rules of ARC-B15 for `council` and `contest` units (`council-rounds-no-gain`, `council-conformity`, `contest-no-gain`) belong to the units of R3-T4, which the engine does not build yet (`model/` has no such unit kind); they stay listed as skipped with their `min_n` and a reason that says the kind is not built, which ARC-B7 states for a rule whose input is missing. Every other history rule of the catalog is built and has a fixture.

## 2. Phases

### Phase 1: History reader and layer wiring

Goal: `--layer history` and a bare `audit` read the workflow's runs in the window and version, skip with `no runs in window` or `n=<runs> of <min>`, count unreadable runs in the header, and `cli/audit.py` no longer refuses the layer (R1, R2).
Weight: medium

### Phase 2: History rules of C1, C2 and C3

Goal: the history rules of ARC-B9, ARC-B10 and ARC-B11 fire on their fixtures and stay quiet on their clean ones, with hot spots per unit and the highest-weight cause (R3).
Weight: heavy (many-tests)

### Phase 3: History rules of C5 to C8 and owned renders

Goal: the history rules of ARC-B12 to ARC-B15 and the rendered owned rules fire on their fixtures, calling the owning components (R4).
Weight: heavy (many-tests)

### Phase 4: Session surface and refusal classes

Goal: one session surface per step and judge, and the refusal classes of TSA-B7, built from tool names, tool maps and scrubbed input summaries only, with the need read by prompt lint's name reader (R5).
Weight: medium

### Phase 5: C4 rules and widening marks

Goal: every rule of TSA-B9 to TSA-B12 fires on its fixture and stays quiet on its clean one, and each widening remedy is marked (R6, R8).
Weight: heavy (many-tests)

### Phase 6: The `audit tools` verb

Goal: `audit tools <workflow>` prints the matrix, the same on every executor but for tool names, with `—` and skipped history rules when there is no history (R7).
Weight: medium

### Phase 7: Prompts, read-only proof, documents and verification

Goal: `audit prompts` reads `changed` from history, the read-only and model-free tests cover the new layers, spec 55, the release 3 plan and the guides are true, and the three verification commands pass (R9, R10, R11).
Weight: light
