- Why this design: the parallel block already has a fork node that starts every branch and a join step node that runs once every branch has passed, so the checkpoint commit and the writer worktrees belong to the fork (WSP-B19, WSP-B11) and the merge to the join's step body. A writer branch's path is looked up from `workspace.children`, which the fork writes (the `workspace` channel has a `replace` reducer and only the fork writes it in that superstep). A conflict is an `escalate` cause on the join's attempt, so the existing judge placeholder and gate give ESCALATE with no session (JDG-B1), and the conflicting paths travel as the judgement's `blockers` into the pause.
- Extra files opened beyond the hand-off's reading list: none for code. One search over `plugins/` for `parallel-writer-branch` and "read-only branch" to find documents the change makes false; it found the four documents under section 4, and docstrings in `run/reserve.py`, `tests/test_reservations.py` and `tests/test_parallel.py` that say read-only, which the code rows touch only where they are in a file a row already changes.
- Design notes the rows follow (code step reads these before the rows):
  - Writer branch = a parallel branch whose step declares `write` or `edit` (the test `validate.py` applied at `_parallel`); `shell` alone does not make one. `flow.block_of` finds the block of a branch; add a helper in `model/flow.py` that names a block's writer branches in the order its parallel unit names them, used by validation, the fork, the join, `_workdir` and `unit_reasons`.
  - Writer name: `workspace.py` derives the worktree flat name `<workflow>--<task_id>--w-<branch>` and the branch `<prefix>/<workflow>/<task part>--w-<branch>` (WTR-B20, never a child path of the run branch), through the same `flat_part` rules; the path sits in the run's sibling root. A flat name never holds `--` inside a part (`flat_part` collapses runs of `-`), so a writer's worktree is the one whose name holds `--w-` after the first `--`; `list_worktrees` marks such rows so `worktree path` returns the run's row (WTR-AC11).
  - Cut: after the checkpoint commit, `git worktree add -b <writer branch> <path> <run branch head>` under the repository lock, `git worktree lock --reason "tempergraph <thread>"`, then the bootstrap (WSP-B2); a failed bootstrap removes the new worktree and branch with the start path's `_remove_new`. Each writer is appended to `WorkspaceRecord.children` as `{name, path, branch, state}` and written back through the fork node's `workspace` channel update. A second entry into the same block is outside this task (hand-off open question); the code report names it under Deviations. How a failed writer bootstrap ends the run: the fork raises `WorkspaceRefused` with the failing step, and the code step uses the path the runner already takes for an engine fault (it reads how `Drain` and engine errors leave the graph), reporting the choice under Deviations.
  - Git calls go through `git.git` only, put `--end-of-options` before every ref or path, and never use `worktree remove --force`, `branch -D` or `branch -d` (WTR-AC5). New helpers in `git.py`: commit all changes with new files, merge without fast-forward, reset hard to a commit, list conflicted paths.
  - Join: in the join's step body, merge each writer branch in declared order into the run worktree with `--no-ff`; on a conflict, `git merge --abort` if needed, `git reset --hard` to the head recorded before the first merge, record the conflicting paths on the join's attempt with `escalate: merge_conflict`, add `merge_conflict` to `ESCALATE_CAUSES` in `run/gate.py`, and let `_judge` put those paths into the placeholder judgement's `blockers` (the pause lists `judged.get("blockers")`, `pause_payload`). No model session starts for the join.
  - A read-only branch keeps `_workdir` of the run and the fingerprint rule at `nodes.py` line 451; the rule must not fire for a writer branch, whose fingerprint is taken in its own worktree.
  - The reservation `_hold` needs no change (a session of any branch of a block reserves).
- Test fixtures: `tests/test_parallel.py` helpers (`ByUnit`, `wf`, `go`) are the base; its stand-in writes under `.git`, a file in a linked worktree, so the writer tests use a stand-in that writes a named file under `req.workdir` and records the `workdir` each session got. Offline tests use the engine's own fixture workflows only (ADR-0129).

## 2. Phases

### Phase 1: Validation, resolution and the outside-git refusal

Goal: a writer branch validates, a workflow with one resolves to a worktree, an explicit `in_place` start or a `workspace: in_place` declaration is refused with its own code, and a writer branch outside git is refused `needs_git` before anything is created.
Weight: light

### Phase 2: The checkpoint, the writer worktrees and their workdir

Goal: entering a block with a writer branch commits the run worktree, cuts one sibling worktree per writer branch into the run's record, gives each writer's step, judge, check and script that path while a read-only branch keeps the run worktree, and lists the writer worktrees without letting `worktree path` return one.
Weight: medium

### Phase 3: The merge at the join and the conflict block

Goal: the join merges the writer branches without fast-forward in declared order, and a conflict resets the run branch and blocks the join's step with the conflicting paths and no model call.
Weight: medium

### Phase 4: Documents and the release record

Goal: every document the change made false is true again, and the release 3 plan records R3-T3.1 as built.
Weight: light
