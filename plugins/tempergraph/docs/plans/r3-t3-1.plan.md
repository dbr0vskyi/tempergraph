- Design notes the rows follow (the code step reads these before the rows):
  - Writer branch = a parallel branch whose step declares `write` or `edit` (the test `validate.py` applied at `_parallel`); `shell` alone does not make one. `flow.block_of` finds the block of a branch; a helper in `model/flow.py` names a block's writer branches in the order its parallel unit names them, used by validation, the fork, the join, `_workdir` and `unit_reasons`.
  - Writer name: `workspace.py` derives the worktree flat name `<workflow>--<task_id>--w-<branch>` and the branch `<prefix>/<workflow>/<task part>--w-<branch>` (WTR-B20, never a child path of the run branch), through the same `flat_part` rules; the path sits in the run's sibling root. `list_worktrees` marks a writer's row so `worktree path` returns the run's row (WTR-AC11).
  - Cut: after the checkpoint commit, `git worktree add -b <writer branch> <path> <run branch head>` under the repository lock, `git worktree lock --reason "tempergraph <thread>"`, then the bootstrap (WSP-B2); a failed bootstrap removes the new worktree and branch. Each writer is appended to `WorkspaceRecord.children` and written back through the fork node's `workspace` channel update. A second entry into the same block is outside the task's criteria (hand-off open question); the code report names it under Deviations. A failed writer bootstrap stops the run through the runner's engine-fault path; the report names the choice.
  - Git calls go through `git.git` only, put `--end-of-options` before every ref or path where git accepts it, and never use `worktree remove --force`, `branch -D` or `branch -d` (WTR-AC5).
  - Join: in the join's step body, merge each writer branch in declared order into the run worktree with `--no-ff`; on a conflict, reset hard to the head recorded before the first merge, record the conflicting paths on the join's attempt with `escalate: merge_conflict`, and let `_judge` put those paths into the placeholder judgement's `blockers` (the pause lists them). No model session starts for the join.
  - A read-only branch keeps the run's workdir and the fingerprint rule in `run/nodes.py`; the rule must not fire for a writer branch. The reservation `_hold` needs no change.
  - Phase 5 adds no behaviour and edits no spec: for each of the twelve criteria the row finds the existing test that proves it and adds the criterion's id to the test's name or to a comment on it; where no existing test proves the criterion the row writes one. ## 2. Phases

### Phase 1: Validation, resolution and the outside-git refusal

Goal: a writer branch validates, a workflow with one resolves to a worktree, an explicit `in_place` start or a `workspace: in_place` declaration is refused with its own code, and a writer branch outside git is refused `needs_git` before anything is created.
Weight: light

### Phase 2: The checkpoint, the writer worktrees and their workdir

Goal: entering a block with a writer branch commits the run worktree, cuts one sibling worktree per writer branch into the run's record, gives each writer's step, judge, check and script that path while a read-only branch keeps the run worktree, and lists the writer worktrees without letting `worktree path` return one.
Weight: medium

### Phase 3: The merge at the join and the conflict block

Goal: the join merges the writer branches without fast-forward in declared order, and a conflict resets the run branch and blocks the join's step with the conflicting paths and no model call.
Weight: medium

### Phase 4: Documents and the release record

Goal: every document the change made false is true again, and the release 3 plan records R3-T3.1 as built.
Weight: light

### Phase 5: Every criterion of an edited spec has a test that carries its id

Goal: each of BUD-AC1, BUD-AC4, CMP-AC2 to CMP-AC10 and WFM-AC2 is carried, in a test's name or a comment on it, by a test that proves it; a criterion with no proving test gets a new offline test, and no spec, code behaviour or other criterion changes.
Weight: medium
