A writer branch's path is looked up from `workspace.children`, which the fork writes (the `workspace` channel has a `replace` reducer and only the fork writes it in that superstep). A conflict is an `escalate` cause on the join's attempt, so the existing judge placeholder and gate give ESCALATE with no session (JDG-B1), and the conflicting paths travel as the judgement's `blockers` into the pause.

For the re-run I read the acceptance criteria of spec `compiler-and-flow` and spec `budgets-and-failures`, searched `plugins/tempergraph/engine/tests` for the ids, and read the code report; no other file.
- Design notes the rows follow (the code step reads these before the rows):
  - Writer branch = a parallel branch whose step declares `write` or `edit`; `shell` alone does not make one. `flow.block_of` finds a branch's block; a helper in `model/flow.py` names a block's writer branches in the order the parallel unit names them, used by validation, the fork, the join, `_workdir` and `unit_reasons`.
  - Writer name: `workspace.py` derives the flat name `<workflow>--<task_id>--w-<branch>` and the branch `<prefix>/<workflow>/<task part>--w-<branch>` (WTR-B20, never a child path of the run branch), through the same `flat_part` rules, in the run's sibling root. `list_worktrees` marks a writer's row so `worktree path` returns the run's row (WTR-AC11).
  - Cut: after the checkpoint commit, `git worktree add -b <writer branch> <path> <run branch head>` under the repository lock, `git worktree lock --reason "tempergraph <thread>"`, then the bootstrap (WSP-B2); a failed bootstrap removes the new worktree and branch. Each writer is appended to `WorkspaceRecord.children` through the fork node's `workspace` channel update. A second entry into the same block is outside the criteria (hand-off open question); the code report names it under Deviations. A failed writer bootstrap stops the run through the runner's engine-fault path.
  - Git calls go through `git.git` only, with `--end-of-options` before every ref or path where git accepts it, and never `worktree remove --force`, `branch -D` or `branch -d` (WTR-AC5).
  - Join: in the join's step body, merge each writer branch in declared order into the run worktree with `--no-ff`; on a conflict, reset hard to the head recorded before the first merge, record the conflicting paths on the join's attempt with `escalate: merge_conflict`, and let `_judge` put those paths into the placeholder judgement's `blockers`. No model session starts for the join.
  - A read-only branch keeps the run's workdir and the fingerprint rule in `run/nodes.py`; the rule must not fire for a writer branch. The reservation `_hold` needs no change.
  - Phase 5 adds no behaviour and edits no spec: for each of its ten criteria the row finds the existing test that proves it and adds the id to the test's name or a comment; where none proves it the row writes a test. Candidates are in `tests/test_conformance.py`, `test_compiler.py`, `test_scaffold.py`, `test_routing.py`, `test_run.py`, `test_measured_switches.py`, `test_validate.py`; the row reads each against the criterion before adding an id.
- Test fixtures: `tests/test_parallel.py` helpers (`ByUnit`, `wf`, `go`) are the base for the writer tests. Offline tests use the engine's own fixture workflows only (ADR `the-engine-names-no-workflow`).
