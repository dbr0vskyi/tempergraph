- Why this design: the parallel block already has a fork node that starts every branch and a join step node that runs once every branch has passed, so the checkpoint commit and the writer worktrees belong to the fork (WSP-B19, WSP-B11) and the merge to the join's step body. A writer branch's path is looked up from `workspace.children`, which the fork writes (the `workspace` channel has a `replace` reducer and only the fork writes it in that superstep). A conflict is an `escalate` cause on the join's attempt, so the existing judge placeholder and gate give ESCALATE with no session (JDG-B1), and the conflicting paths travel as the judgement's `blockers` into the pause.
- Extra files opened beyond the hand-off's reading list: none for code in the first pass; one search over `plugins/` for `parallel-writer-branch` and "read-only branch" found the four documents under section 4. For the re-run I opened the acceptance criteria of spec 03 (lines 128 to 139) and spec 08 (lines 115 to 124) to read the twelve criteria, and searched `plugins/tempergraph/engine/tests` for the ids and for candidate proving tests, because the hand-off lists no test for them.
- Design notes the rows follow (the code step reads these before the rows):
  - Writer branch = a parallel branch whose step declares `write` or `edit` (the test `validate.py` applied at `_parallel`); `shell` alone does not make one. `flow.block_of` finds the block of a branch; a helper in `model/flow.py` names a block's writer branches in the order its parallel unit names them, used by validation, the fork, the join, `_workdir` and `unit_reasons`.
  - Writer name: `workspace.py` derives the worktree flat name `<workflow>--<task_id>--w-<branch>` and the branch `<prefix>/<workflow>/<task part>--w-<branch>` (WTR-B20, never a child path of the run branch), through the same `flat_part` rules; the path sits in the run's sibling root. `list_worktrees` marks a writer's row so `worktree path` returns the run's row (WTR-AC11).
  - Cut: after the checkpoint commit, `git worktree add -b <writer branch> <path> <run branch head>` under the repository lock, `git worktree lock --reason "tempergraph <thread>"`, then the bootstrap (WSP-B2); a failed bootstrap removes the new worktree and branch. Each writer is appended to `WorkspaceRecord.children` and written back through the fork node's `workspace` channel update. A second entry into the same block is outside the task's criteria (hand-off open question); the code report names it under Deviations. A failed writer bootstrap stops the run through the runner's engine-fault path; the report names the choice.
  - Git calls go through `git.git` only, put `--end-of-options` before every ref or path where git accepts it, and never use `worktree remove --force`, `branch -D` or `branch -d` (WTR-AC5).
  - Join: in the join's step body, merge each writer branch in declared order into the run worktree with `--no-ff`; on a conflict, reset hard to the head recorded before the first merge, record the conflicting paths on the join's attempt with `escalate: merge_conflict`, and let `_judge` put those paths into the placeholder judgement's `blockers` (the pause lists them). No model session starts for the join.
  - A read-only branch keeps the run's workdir and the fingerprint rule in `run/nodes.py`; the rule must not fire for a writer branch. The reservation `_hold` needs no change.
  - Phase 5 adds no behaviour and edits no spec: for each of the twelve criteria the row finds the existing test that proves it and adds the criterion's id to the test's name or to a comment on it; where no existing test proves the criterion the row writes one. The search found candidates, not proof: `tests/test_compiler.py` (four nodes per unit, diagram equals graph, escalation and resume, reducers), `tests/test_scaffold.py` (`test_diagram_currency_by_digest`), `tests/test_conformance.py` (executor causes, timeouts), `tests/test_routing.py`, `tests/test_run.py`, `tests/test_measured_switches.py` (`test_an_operator_picks_the_arm`, CMP-B7), `tests/test_validate.py`, `tests/test_durability.py` (`test_paused_resume_continues`). The row reads each candidate against the criterion's behaviour before it adds an id.
- Test fixtures: `tests/test_parallel.py` helpers (`ByUnit`, `wf`, `go`) are the base for the writer tests; their stand-in writes a named file under `req.workdir` and records the `workdir` each session got. Offline tests use the engine's own fixture workflows only (ADR-0129).
