- State of the tree: phases 1 to 4 were built by an earlier code step (`docs/tasks/i59.report.md`: suite, ruff and mypy green). The outcome check sent the run back because three criteria of specs this change edited are carried by no test: CLI-AC5, OVR-AC5, RCT-AC5. Phase 5 adds them. The expand step writes rows for all five phases; a row whose change is already in its file is marked by the code step after its phase's tests pass.
- Why this design: the specs make a stop at a pause and a lost runner two more final exits that feed the existing recorder (`record_exit`) and hand-off (`hand_off`), so the plan adds only what no code had: a stop that records before it returns, a catch-up of earlier pauses' findings that no loop judged (so `loop_started` names the fingerprints it covered), and a hand-off of a lost segment by the three verbs.
- The lost-runner hand-off is its own function (`improve/lost.py`, `settle`) called by `cmd_status`, `cmd_stop` and `cmd_attention` inside a guard. `durability.status.status()`, `observe.attention.items()` and `observe.detail.detail()` stay pure reads, so DUR-AC3 and RDD-B6 hold and `status --detail` keeps `health.orphaned` true (SIL-B29, RDD-B14). The claim is the thread's run lock taken without waiting (DUR-B10). A lost segment is recorded when the ledger holds no `runner_lost` row after its `run_started` (SIL-B30); the loop starts once per thread and trigger `runner_lost` (SIL-B31). No `run_exit` is written for it.
- Design notes for the expand step, by phase. Phase 1: `lost_runner.window_days` = 7 in `improve/params.py` (provenance `default_no_data`, source `SIL-B29`); `improve/child.py::process` writes `fingerprints` in `loop_started`. Phase 2: `runner.resume` at the breakpoint stop writes the ledger row (exit 4, reason `person`), calls `record_exit` (new keyword `seg`) and `hand_to_loop`; `record.py::unjudged_pause_findings` feeds earlier pauses' findings to `lenses.decide` and the summary. Phase 3: `hand_off` takes `trigger`; `child.started_for`; `_loop` becomes `hand_to_loop`; `improve/lost.py`; guarded calls in `cli/main.py` (`cmd_status` without `--detail`, `cmd_stop`) and `cli/observe_cli.py` (`cmd_attention`). Tests that pin what changes: `test_improve.py::test_every_threshold_is_a_parameter`, `test_fallback_breakpoint.py` lines 132 to 141, `test_detail.py::test_orphaned_thread`, `test_durability.py::test_observers_create_nothing`, `test_cli.py::test_stop_needs_a_live_run`.
- Design notes, phase 5, one test row each (a test carries its criterion by id in its name or a comment, and runs, never skipped): RCT-AC5 in `tests/test_cli.py` (`test_stop_needs_a_live_run` gains the comment `RCT-AC5` and asserts no stop request file exists after the exit 2) and in `tests/test_lost_runner.py` (`test_attention_and_stop_find_the_same_lost_runner` carries `RCT-AC5` for a killed runner: exit 2, no request file). CLI-AC5 in `tests/test_reports.py` (`test_attention_lists_each_pause_once_oldest_first` carries `CLI-AC5` and, after its hash check, resumes the first item's thread with the `stop` decision from its `decisions` list and asserts the verb accepts it, not a usage exit) and in `tests/test_lost_runner.py` (a new test with a paused thread and a killed one: `attention --json` lists the pause exactly once and the paused thread's run folder is unchanged beside the hand-off). OVR-AC5 in a new `tests/test_read_only_contract.py`: one test for OVR-B15 (`status`, `attention` and `stop` on a state root with no lost runner start no session, the stand-in executor has no calls, and the state root and the home folder hash the same) and one that reads the owner criteria of that contract (CLI-AC1, CLI-AC5, RCT-AC5, DUR-AC3, SIL-AC22 to SIL-AC28) and asserts each is carried by a test that runs, using the matcher of `test_loop_fixes_coverage.py` (`carriers`), with no other id written in a comment of the new file.
- Assumptions, taken from the hand-off's defaults and recorded in the specs' open questions: once per trigger and thread, not once per end; 7 days as the window; a lost runner is no stable-mode signal of its own; `resume` and `wait` do not find a lost runner; a thread resumed with `proceed` after a pause and then finished is unchanged. The monitor's documents (`plugins/tempergraph-monitor/docs/adr/0002-poll-files-and-read-only-verbs.adr.md`, `plugins/tempergraph-monitor/docs/specs/01-data-sources.spec.md`) call `status` read-only; the hand-off leaves them to the monitor's owner and the final report names them.
- "Not built yet": spec 16 has no such line, and the one in spec 44 is about corroboration (SRV-B7), which this task does not touch. Nothing is removed.
