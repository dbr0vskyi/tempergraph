# Plan: Reservations for parallel read-only branches

## 0. Hand-off

- Triage note: `plugins/tempergraph/docs/tasks/r3-t1-1b.triage.md`
- Hand-off: `plugins/tempergraph/docs/tasks/r3-t1-1b.handoff.md`
- Specs read: `plugins/tempergraph/docs/specs/08-budgets-and-failures.spec.md` (BUD-B9, BUD-B12 to BUD-B15, BUD-AC2, BUD-AC5 to BUD-AC7), `plugins/tempergraph/docs/specs/15-observability-and-cost.spec.md` (OBS-B7), `plugins/tempergraph/docs/specs/34-central-run-stats.spec.md` (CST-B9, CST-B15, read only)
- Why this design: the engine's parallel block runs its branches in LangGraph's thread pool, and a branch's cost reaches the run state only when the superstep ends, so the cost check in `_boundary` cannot see a sibling branch. A thread-safe ledger of what each running session holds, kept for the run's process, makes the check count what is in flight; a branch whose reservation does not fit blocks on that ledger until a running session ends. The ledger also adds the real cost of sessions that ended in the same superstep, because the state a sibling read at its start does not hold it yet; sessions of one superstep are told apart by the session count of the state they read.
- The reserving sessions: every session started for a unit that is a branch of a parallel block (step, retry, judge and judge re-ask, each infra try), in a run that has `run_cost_cap_usd`. Units outside a block run one session at a time and keep the BUD-B9 check alone. Maps, contests and councils are not built (the task says so); they reuse the ledger later.
- The `projection` source (BUD-B12 second tier): the central run stats hold no per-unit projection (CST-B15 projects per workflow and per run; hand-off open question, reading (a)). No row builds one; a reservation takes the per-session cap, else the share. The code report lists the tier that never applied under Deviations, and the "Not built yet" line of BUD says so (row 2.3).
- "Over the cap" is strictly more than the cap, compared after rounding to 6 places as `CostTotals.figure` does (hand-off Decisions).
