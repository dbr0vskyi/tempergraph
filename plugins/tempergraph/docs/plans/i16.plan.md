# Plan: a retry of a writing contest runs in worktrees of its own

## 0. Hand-off

- Triage note: `plugins/tempergraph/docs/tasks/i16.triage.md`
- Hand-off: `plugins/tempergraph/docs/tasks/i16.handoff.md`
- Specs read: `plugins/tempergraph/docs/specs/72-contest-unit.spec.md` (CTS-B11 to CTS-B13, CTS-AC7 to CTS-AC11, CTS-B5, CTS-B7, CTS-B8), `plugins/tempergraph/docs/specs/82-worktree-mode.spec.md` (WTR-B20, WTR-AC14), `plugins/tempergraph/docs/specs/13-workspace-and-concurrency.spec.md` (WSP-B19, linked by CTS-B11). The rules `plan.rule.md` and `documents.rule.md` were opened from `.claude/rules/temperspec/`.
- Files opened beyond the hand-off's reading list: none. The code on the list was read again for this plan: `run/nodes.py` (lines 165-290 and 700-900), `workspace.py` (lines 360-430) and the contest spec (lines 15-110).
- Why this design: the map already keys a child of the workspace record by a `visit` number (`_child_of`, `_merge_children`, `cut_writers` and `writer_names` take it) and names a later visit `--i<n>-<item>`. A contest takes the same device with its own attempt number, so the names are `--s<n>-<slot>` (WTR-B20) and a child, a merge and a discard are each found by slot and attempt. No signature changes: `visit` is already a keyword of `cut_writers` and `writer_names`; `cut_writers` already records `visit` for a value above 1 and already refuses a second cut of one slot in one visit. Only `writer_names` gives a contest slot no attempt part (its tag is `kind`, not `s<visit>`).
- The attempt number is the one `_contest_step` computes (the unit's previous attempt plus 1, `run/nodes.py` line 741; a BACK keeps the unit's attempt record). The step writes it into the unit's `maps` record (`attempt`) before the slots start, so `_writer_child` (step, check and judge of a slot, read from the slot's view of the state, which keeps `maps`) finds the child of that attempt; a record with none reads as 1.
- A retry cuts worktrees only for the slots it runs (`contestmod.retry_slots`); a BACK's first run is a new visit with an attempt above 1 and takes the same cut (CTS-B11, CTS-AC9). The head a later attempt starts from already holds the first attempt's winner, because the judge merges a writer winner at the pick whatever its verdict.
- The pick merges only children of its own attempt, and its discard is limited to children of its own attempt, so an earlier attempt's records keep the state they had (CTS-B12). Nothing is deleted (WTR-B23).
- Tests that pin what changes: `tests/test_workspace.py` lines 136-159 call `cut_writers(..., kind="s")` and `writer_names` with no attempt, and `tests/test_map_revisit_writers.py` lines 75-104 call them with `kind="i"`; the new tag is taken only for `kind="s"` with `visit` above 1, so none of them breaks. `_enter_writer_contest` is called by no test. The test that pins the refusal in `tests/test_contest_writers.py` (`test_a_second_attempt_of_a_writer_contest_ends_blocked_rather_than_overwrite_a_slot_branch_CTS_AC4`) is replaced by the regression tests of phase 2.
- Why `complex`: the files the rows will name (`run/nodes.py`, `workspace.py`, the contest tests and the specs they cite) read together pass the 200,000-byte limit of a `simple` plan. Phase 2 holds that reading set and is marked `heavy (large-context)`; the expand step writes the rows.
- Left as it is: a stop between an attempt's cut and the end of its step node (the hand-off's open question, option b). Spec 77 (MAP) and the map's code paths are not touched; edits stay on the contest's lines of `run/nodes.py`.

## 2. Phases

### Phase 1: Names of a later attempt's slot worktrees

Goal: a contest slot's worktree and branch for attempt n above 1 are named `--s<n>-<slot>` by `writer_names` and `cut_writers` in `workspace.py`, cut from the run branch's head beside the first attempt's, which keep their names and stay untouched; a first attempt keeps `--s-<slot>` and a second cut of one slot in one attempt is refused.
Weight: light

### Phase 2: A later attempt runs and merges in its own worktrees

Goal: a retry of a writing contest, under either scope, and the first run after a BACK cut fresh slot worktrees for their attempt in `run/nodes.py` (`_contest_step`, `_enter_writer_contest`, `_writer_child`, `_contest_judge`), run the slots there, merge only the winner's branch of that attempt, and leave every earlier attempt's branches, worktrees and records as they are; the test that pinned the refusal is replaced by the regression tests.
Weight: heavy (large-context)
