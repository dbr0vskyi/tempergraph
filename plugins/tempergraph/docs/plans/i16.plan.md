- Files opened beyond the hand-off's reading list: `plugins/tempergraph/engine/src/tempergraph/run/mapping.py` (only `record` and `item_in_hand`, to know what a slot's view of the state holds) and `plugins/tempergraph/engine/tests/test_writer_branches.py` (lines 1-70, for the `git` and `worktrees_root` helpers that `test_contest_writers.py` imports). `test_map_revisit_writers.py` and `test_contest_retry.py` were read for the shape of the tests, as the list says.
- Why this design: the map already keys a child of the workspace record by a `visit` number (`_child_of`, `_merge_children`, `cut_writers`, `writer_names` take it) and names a later visit `--i<n>-<item>`. A contest takes the same device with its own attempt number as that number, so the names are `--s<n>-<slot>` (WTR-B20) and a child, a merge and a discard are each found by slot and attempt. No signature changes: `visit` is already a keyword of `cut_writers` and `writer_names`, and the tests that pin them (`tests/test_workspace.py` lines 136-159, `tests/test_map_revisit_writers.py` lines 70-104) call them with no attempt or with `kind="i"`, so none breaks.
- Design the phases follow, read in the code:
  - The attempt number is the one `_contest_step` computes (`prev attempt + 1`, `run/nodes.py` line 741) and writes in the `contest` run record. It moves above the first-run and retry branches and is written into the unit's `maps` record (`attempt`) before the slots start, so that `_writer_child` (slot step, check and judge) and `_contest_judge` read the same number; a record with none reads as 1.
  - The retry branch (lines 733-738) stops refusing: it runs the same checkpoint and cut as a first run (`_enter_writer_contest`, with the attempt), for the slots the retry runs (`contestmod.retry_slots`). A BACK's first run is a new visit with attempt above 1 and takes the same cut.
  - The pick merges `_merge_children(..., attempt)`, so only a child of this attempt can be the winner's; the discard of the other slots' records (line 883) is limited to children of this attempt, so an earlier attempt's records keep the state they had (CTS-B12). Earlier branches and worktrees are never touched; nothing is deleted (WTR-B23).
  - A first attempt keeps `--s-<slot>` and a record with no `visit` key; a second cut of the same slot in the same attempt is still refused (`name_collision`).
- The plan is `complex` by one measured sign: the files the rows will name, `run/nodes.py` (1,884 lines) with `workspace.py` (806) and the three test files, hold more than 200,000 bytes. Phases, rows and files are within the other limits.
- Left as it is: a stop between an attempt's cut and the end of its step node (open question of the hand-off, option b). Spec 77 (MAP) and the map code paths are not touched; the in-flight map change edits the same two source files, so edits are kept to the contest's lines.

## 2. Phases

### Phase 1: Names of a later attempt's slot worktrees

Goal: a contest slot's worktree and branch for attempt n above 1 are named `--s<n>-<slot>`, cut from the run branch's head beside the first attempt's, which keep their names and stay untouched.
Weight: light

### Phase 2: A later attempt runs and merges in its own worktrees

Goal: a retry of a writing contest, under either scope, and the first run after a BACK cut fresh slot worktrees for their attempt, run the slots there, merge only the winner's branch of that attempt, and leave every earlier attempt's branches, worktrees and records as they are.
Weight: medium

### Phase 3: Whole-suite gate

Goal: the engine suite, lint and types pass with the refusal gone and its pinning test replaced.
Weight: light
