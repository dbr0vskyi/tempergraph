A search of `plugins/` for "second attempt of a writ" and "ends blocked" found only the refusal in `run/nodes.py` and its pinning test, so no other document or test says a second attempt ends blocked.
- Why this design: the map already keys a child of the workspace record by a `visit` number (`_child_of`, `_merge_children`, `cut_writers`, `writer_names` take it) and names a later visit `--i<n>-<item>`. A contest takes the same device with its own attempt number, so the names are `--s<n>-<slot>` (WTR-B20) and a child, a merge and a discard are each found by slot and attempt. No signature changes: `visit` is already a keyword of `cut_writers` and `writer_names`.
- Why `complex`: the three files the rows will name (`run/nodes.py`, `workspace.py`, `tests/test_contest_writers.py`) with the specs read come to 224,220 bytes by the gate's count, over the 200,000 of `simple`. The other signs are within `simple`; the expand step writes the rows.
- Design the phases follow, read in the code:
  - The attempt number is the one `_contest_step` computes (previous attempt plus 1, `run/nodes.py` near line 741) and writes in the unit's `attempts` record. It moves above the first-run and retry branches and is written into the unit's `maps` record (`attempt`) before the slots start, so that `_writer_child` (slot step, check and judge) reads it from the state it is given; a record with none reads as 1.
  - The retry branch stops refusing and runs the checkpoint and the cut a first run does (`_enter_writer_contest`, given the attempt), for the slots the retry runs (`contestmod.retry_slots`). A BACK's first run is a new visit with an attempt above 1 and takes the same cut.
  - The pick merges `_merge_children(..., attempt)`, so only a child of this attempt can be the winner's; the discard of the other slots' records is limited to children of this attempt, so an earlier attempt's records keep the state they had (CTS-B12). Earlier branches and worktrees are never touched; nothing is deleted (WTR-B23).
  - A first attempt keeps `--s-<slot>` and a record with no `visit` key; a second cut of the same slot in the same attempt is still refused (`name_collision`).
- Tests the rows must cover, all in `plugins/tempergraph/engine/tests/test_contest_writers.py` (the names are proved there, not from `test_workspace.py`):
  - Names and cut: `writer_names(..., kind="s")` with no attempt gives `--s-s1`, with `visit=2` gives `--s2-s1`, on folder and branch, different after shortening, valid for `git check-ref-format --branch`; `cut_writers` with `visit=2` leaves the first child unchanged and records a second child with `visit` 2; a second `visit=2` cut of one slot raises `WorkspaceRefused` (`name_collision`) and removes nothing (WTR-AC14).
  - Retry scope `best`: `Writes` takes a list per slot (the k-th step session writes the k-th entry) and records every step session's key, working directory and head; the test that pinned the refusal (`test_a_second_attempt_of_a_writer_contest_ends_blocked_rather_than_overwrite_a_slot_branch_CTS_AC4`) is replaced by a gate RETRY run that finishes with no `workspace_refused` record, runs the retry in `demo--C-1--s2-s1` from the head after the first merge, merges first `RUN--s-s1` and then `RUN--s2-s1` and nothing else, leaves the first attempt's branches and folders as they were and lists `--s-s1` active, `--s-s2` discarded, `--s2-s1` active (CTS-AC7, CTS-AC10, CTS-AC11).
  - Retry scope `all`: both slots run in `--s2-` worktrees from the head after the first merge, and only the second attempt's winner is merged (CTS-AC8, CTS-AC10, CTS-AC11).
  - First run after a BACK: runs in `--s2-` worktrees, ends with no `workspace_refused`, and no merge after the BACK has a first-attempt branch as second parent (CTS-AC9).
- Tests that pin what changes: `tests/test_workspace.py` lines 136-159 call `cut_writers(..., kind="s")` and `writer_names` with no attempt, and `tests/test_map_revisit_writers.py` lines 75-104 call them with `kind="i"`; the new tag is taken only for `kind="s"` with `visit` above 1, so none of them breaks and none gets a row. `_enter_writer_contest` has no test that calls it.
- Left as it is: a stop between an attempt's cut and the end of its step node (open question of the hand-off, option b). Spec 77 (MAP) and the map code paths are not touched; the in-flight map change edits the same two source files, so edits are kept to the contest's lines.

## 2. Phases

### Phase 1: Names of a later attempt's slot worktrees

Goal: a contest slot's worktree and branch for attempt n above 1 are named `--s<n>-<slot>` in `workspace.py` (`writer_names`, `cut_writers`), cut from the run branch's head beside the first attempt's, which keep their names and stay untouched; a first attempt keeps `--s-<slot>` and a second cut of one slot in one attempt is refused.
Weight: light

### Phase 2: A later attempt runs and merges in its own worktrees

Goal: a retry of a writing contest, under either scope, and the first run after a BACK cut fresh slot worktrees for their attempt in `run/nodes.py` (`_contest_step`, `_enter_writer_contest`, `_writer_child`, `_contest_judge`), run the slots there, merge only the winner's branch of that attempt, and leave every earlier attempt's branches, worktrees and records as they are; the test that pinned the refusal is replaced by the regression tests.
Weight: medium
