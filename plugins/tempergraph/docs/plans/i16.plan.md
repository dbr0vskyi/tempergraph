A search of `plugins/` for "second attempt of a writ" and "ends blocked" found only the refusal in `run/nodes.py` and its pinning test, so no other document or test says a second attempt ends blocked.
- Why this design: the map already keys a child of the workspace record by a `visit` number (`_child_of`, `_merge_children`, `cut_writers`, `writer_names` take it) and names a later visit `--i<n>-<item>`. A contest takes the same device with its own attempt number, so the names are `--s<n>-<slot>` (WTR-B20) and a child, a merge and a discard are each found by slot and attempt. No signature changes: `visit` is already a keyword of `cut_writers` and `writer_names`.
- Design the phases follow, read in the code:
  - The attempt number is the one `_contest_step` computes (`prev attempt + 1`, `run/nodes.py` line 741) and writes in the unit's `attempts` record. It moves above the first-run and retry branches and is written into the unit's `maps` record (`attempt`) before the slots start, so that `_writer_child` (slot step, check and judge) reads it from the state it is given; a record with none reads as 1. After the step the record holds it already (`round_` at the end of `_contest_step`).
  - The retry branch stops refusing and runs the checkpoint and the cut a first run does (`_enter_writer_contest`, given the attempt), for the slots the retry runs (`contestmod.retry_slots`). A BACK's first run is a new visit with an attempt above 1 and takes the same cut.
  - The pick merges `_merge_children(..., attempt)`, so only a child of this attempt can be the winner's; the discard of the other slots' records is limited to children of this attempt, so an earlier attempt's records keep the state they had (CTS-B12). Earlier branches and worktrees are never touched; nothing is deleted (WTR-B23).
  - A first attempt keeps `--s-<slot>` and a record with no `visit` key; a second cut of the same slot in the same attempt is still refused (`name_collision`).
- Tests that pin what changes: `tests/test_workspace.py` lines 136-159 call `cut_writers(..., kind="s")` and `writer_names` with no attempt, and `tests/test_map_revisit_writers.py` lines 75-104 call them with `kind="i"`; the new tag is taken only for `kind="s"` with `visit` above 1, so none of them breaks and none gets a row. The test that pins the refusal, `tests/test_contest_writers.py` line 125, asserts the opposite of CTS-B11 and is replaced (row 2.1). `_enter_writer_contest` has no test that calls it.
- Size, measured: three files are named by the rows. `run/nodes.py` (1,884 lines; counted by line length, about 118,000 bytes), `workspace.py` (806 lines, about 37,000 bytes) and `tests/test_contest_writers.py` (133 lines, about 8,000 bytes) come to about 165,000 bytes, under the 200,000 of `simple`. No other file is named: the names are proved from `test_contest_writers.py`, not from `test_workspace.py`. Two phases, eight rows, four test rows, three verification commands, no heavy phase.
- Left as it is: a stop between an attempt's cut and the end of its step node (open question of the hand-off, option b). Spec 77 (MAP) and the map code paths are not touched; the in-flight map change edits the same two source files, so edits are kept to the contest's lines.
