# Review: i196

## Findings

1. `plugins/tempergraph/engine/src/tempergraph/improve/child.py:528` blocking: the day bound of comments on a target is counted by `filing.comments_by_day(root, wf, ...)`, which reads only `runs/<wf>/*/loop.jsonl` of the one workflow being filed. Criterion 4 says the bound counts "over every cause bound to" the target. Two causes of two different workflows bound to the same person's issue each see a count of zero and each send a comment on the same UTC day, so the target gets more than `seen_again.max_per_issue_per_day`. Every test uses causes of the one workflow `demo`, so none covers this.
2. `plugins/tempergraph/engine/src/tempergraph/improve/filing.py:574` not blocking: when the binding of a waiting create cannot be read (`got.state == "unreadable"`), the entry goes back to the outbox and no `loop_result` record with op `binding_unreadable` is written. BND-B6 says the loop writes one such record whenever the read fails twice. `file()` does write it at line 670, so the two paths differ.
3. `plugins/tempergraph/engine/tests/test_cause_bindings_run.py:383` not blocking: the replay assertion on comments is `<= {1, 2, before + 1}`, which allows any subset, including no comments at all. The line above it only checks that no target gets two comments on one UTC day. Criterion 8 also says the fourth cause is `muted`. The test only checks that `muted` appears in the outcomes of exits 4 and 5, not that it is that cause's result or that the first three causes still comment on day 2.
