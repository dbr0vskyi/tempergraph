## Deviations

- **A spec edit beyond row 5.2: SWF-B8's checkpoint namespace.** The spec said namespace `<unit>`; the child's graph runs under `<unit>.<visit>.<attempt>`. Under a namespace taken from the parent's task id, a resume lost the child's state: the runner updates the paused parent's state before it resumes, which gives the interrupted node a new task id, and the child started again from its first unit (seen in a test). The visit and attempt keep the namespace the same across a resume and new for a retry or a trip back. The previous review found the code and the spec disagreeing, and the spec ranks above the code, so SWF-B8 is rewritten to the namespace in use: `<unit>.<visit>.<attempt>` (`<unit>[<item>].<visit>.<attempt>` in a map, the form kept as it was; a sub-workflow over items is FLX-B7 and not built here). No other line of the spec changed. Row 1.8 of the plan still says `<unit>`; the plan is edited only in its marks.
- **Two files carry the new ask and wait tests**: `tests/fixtures/subworkflows.py` (row 1.1) gains the option `person` (`ask` puts an `Ask` unit `details` with the question `ticket` before `work`; `wait` a `Wait` unit `signoff` for the event `approved`), and `tests/test_subworkflow_pause.py` (row 3.1) has two new tests: a child `ask` pauses the parent with `unit` `setup/details`, an incomplete `proceed` and an unknown name are refused, answers release it and the child's `work` runs before `review`, with the answers file stored; a child `wait` pauses the parent with `unit` `setup/signoff`, no word and no wrong event releases it, and `event:approved=yes` does. Both carry SWF-AC1. They passed on their first run, with no source change.

A resume never runs a node, so it reads what it needs without them: `subrun.locate` gives the child's spec and unit for a pause path, `subrun.applied` gives the child's spec as the run executes it, and `subrun.child_states` reads the child's kept state from the checkpoint. The pause payload with `unit` as `<unit>/<child unit>` is carried as the row says (`ChildNodes.gate`, and `checkpoint._gate_node` for the snapshot).
- **The child's spec takes the parent's workflow name** at run time, so the child's session folders, check folders and evidence land in the parent's run folder and there is no `runs/<child>/` folder (SWF-AC2: one `run.jsonl`, one thread). The child keeps its own version, texts and package.
