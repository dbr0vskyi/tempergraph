# Hand-off: i170

## Problem

At a thread's final exit the loop reads the findings of earlier segments that ended in a pause only when the exit is a person's stop (exit 4, reason `person`). A thread that pauses, is resumed and ends with exit 0 or 5 never brings its pauses to a loop, and a pause finding that reached the friction judge would come without what answered the pause. The specs now state the rule for every final exit, once per thread, with the six facts for the judge and the rule that no text of a run reaches the judge or `loop.jsonl`.

## Decisions

- Owner decisions of the triage note: none are listed (`## Owner decisions` is `None`), so none is answered or defaulted
- SIL-B28 is widened in place, so a stop is one case of the rule and SIL-AC19 to SIL-AC21 stay as they were (criterion 7). No second behaviour restates it
- "A rerun" in criterion 2 has no case of its own: a rerun starts a new linked thread `<task>~r<n>` with its own run folder and findings document ([RRN-B17](../specs/reruns-and-feedback.spec.md)), so the findings of the source thread never reach its exits. A resume (a stopped thread continued, or a rewind) is the case that has later final exits of one thread, and SIL-AC40 covers it
- The decision that answered a pause is told as its word (`proceed`, `retry`, `back`, `rewind`, `stop`, `event`, `answer`) with the target unit where there is one, never an answer's value, which is a person's text
- Out of scope, as the task says: when a judged finding files (#171), new cause codes (#172), the review of the paused segments' sessions, and a thread with no final exit (SIL-B29 to SIL-B31)
- Not edited, and still true: `plugins/tempergraph/docs/specs/overview.spec.md` line 116 (the summary of the spec), SIL-B9, SIL-B10 and SIL-B17. The code change edits the two places the new rule makes stale: the guide `plugins/tempergraph/docs/guides/improving-workflows.guide.md` (line 11, "a thread you stop ... also judges the findings of the thread's earlier pauses") and the docstring of `decide` in `improve/lenses.py` (line 58, "at a person's stop of a paused thread")

## Open questions

- Where does the "workspace changed" fact come from? Today only a worktree run records a change on resume (`external_change`), and `attach_workspace` reports it whenever the worktree has uncommitted changes at resume (`workspace.py` lines 492 to 500), which includes work the run left itself. Options: (a) the judge is told `not recorded` for a run in place and the resume's `external_change` for a worktree run, as SIL-B37 says; (b) record the workspace's head and status at each pause and `workspace_changed` on the `human` record for every run, which would also feed the audit rule `empty-pauses` (ARC-B12), whose reader at `audit/history.py` line 337 finds that key never written. Until answered: (a)
- A loop whose judge failed or was skipped by the daily cap has been handed its findings, so a later exit leaves them out and they stay recorded `not_judged` (SIL-B35); no test pins it. Options: (a) keep it; (b) offer a finding to a later exit until a judge has answered for it. Until answered: (a)
- The judge's prompt reads the record kinds of the last segment only (`child.py` line 224), so for a finding of an earlier pause that section describes the exit's segment, not the paused one. Options: (a) leave the section as it is, since SIL-B37 asks for the six facts only; (b) add the paused segment's record kinds. Until answered: (a)
