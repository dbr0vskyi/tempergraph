# Hand-off: i21b

## Problem

The `claude` executor's spec said nothing about refusing a CLI that lacks `--strict-mcp-config`, about a step whose declared MCP server the operator's configuration does not define, or about the observation point of the MCP isolation probe (P-CC-13); the code launches such a step strict with no config and no record, and its live probe reads only the start record of the session. The executor compatibility table names a version as confirmed that its `recorded` and `range` do not hold. The specs now state each rule; the code, the tests, the data and the runbook rows follow in the plan.

## Decisions

- The triage note lists no owner decision (`Owner decisions: None`), so none was answered or defaulted.
- Criterion 3 allows a refusal at preflight or a launch recorded with the reason. The spec takes the refusal (ECC-B22), because OVR-B17 says a workflow asking for what its executor cannot give is refused before spend and never downgraded silently, and EXI-B1 refuses at the first miss before any session. A launch that still reaches a missing server (the configuration changed after preflight, or no scratch folder) fails by itself (ECC-B23); that needs no new session-result field.
- The refusal of a CLI without `--strict-mcp-config` uses reason `probe_failed`, a word of the closed set in EXI-B17 and of `ProbeWord` (`engine/src/tempergraph/contracts.py:721`); no new reason word.
- The `range` decides whether a version reads as recorded or outside, as LIF-B10 says and `executor_compat.py:40-47` does; `recorded` lists the versions inside it. LIF-B17 therefore asks for the confirmed version in both, and the data fix (`data/executor_compat.json`) moves `recorded` and `range` together, as the task's own account of the defect has it ("its `recorded` and `range` stay at 2.1.329").
- The observation point of P-CC-13 is the second turn: the operator's probe by hand on `claude` 2.1.332 (2026-11-25), as the task gives it, measured 8,800 tokens at the first turn and 174,123 at the second with no extra word, and about 9,000 at every turn with `--strict-mcp-config`; the connectors are not in `system/init`.
- A server defined only in the repository's own `.mcp.json` counts as undefined for a step, as in ECC-B18, ECC-B19 and SEC-B3: a step that declares one is refused at preflight. The message therefore tells the operator to define the server in their own MCP configuration.

## Inferred behaviours

- ECC-B23: the task asks that a step is "never launched silently without the tools it declared"; the launch-level rule is the reading of that sentence for the paths preflight cannot see. Read in `engine/src/tempergraph/executors/claude.py` (lines 436-446: `kept` empty or `base` none gives a strict launch with no config) and tested by the silent-launch tests (`engine/tests/test_claude_executor.py` lines 488-501), which change with it.
- ECC-B22, the clause "a configuration that cannot be read defines none": read in `engine/src/tempergraph/executors/mcpconfig.py` (lines 45-51, `operator_servers` returns no server for an unreadable file); criterion 3 says "no definition the engine can read".
- ECC-B21, the reason word and the message: the flag is in `PROBED_FLAGS` (`claude.py` lines 59-60) and recorded in the probe's flags (line 406) but never enforced (the probe fails only at lines 398, 403, 416); the word comes from EXI-B17 (`executor-interface.spec.md` line 18).
- ECC-B24, "second turn": from the task's account of the operator's probe; the criterion itself says only "a turn after the servers had time to connect".
- LIF-B17, "inside `range`" beside "in `recorded`": read in `engine/src/tempergraph/executor_compat.py` (lines 40-56: `range` alone decides `recorded`, `outside` and the `executor-version-untested` finding); the criterion asks only for the `recorded` list.
- ECC-B19: lists every declared server instead of the declared and defined ones, a consequence of ECC-B22 and ECC-B23.
