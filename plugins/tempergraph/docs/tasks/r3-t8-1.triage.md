## Assumptions recorded by discovery

Criterion 3 asks for these to be written here; the decision and its options are in `plugins/tempergraph/docs/adr/a-judge-reaches-an-mcp-server-only-through-the-engines-filtering-proxy.adr.md`.

- `judge_mcp` becomes true on `claude` in the change that builds the proxy and passes its offline tests (ECC-AC7 to ECC-AC9). A stand-in MCP server is a short stdio script and the engine's stand-in `claude` already records argv, so the offline test can be built.
- The proxy fronts only a local server that the operator's own MCP configuration defines. A server found only in a repository, a server not configured on the machine, a remote server and a server whose proxy fails to start stay deferred and out of reach (ECC-B15, SEC-B3, the open question in spec `executor-interface`).
- A judge's MCP views come from the view catalog and never from a step's own tool (GRD-AC6). Today `run/guard.py` (`view_set`) gives a judge the step's own `mcp:` tool once `judge_mcp` is true, so the catalog must exist before the flag is set.
