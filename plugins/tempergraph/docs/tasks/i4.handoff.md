# Hand-off: i4

## Problem

The session review's citation check keeps a `judge_unread` or `judge_trusts_report` observation only when the judge opened none of the changed paths, and it drops `judge_shallow` naming `judge_model` on its remedy class alone, so a correct observation at 0.9 about a judge that read 1 of many files was rated `unsupported` (R-160 F8, issue 4). No model-free finding names a judge that graded after reading only part of the change, so the loop sees it only when a review runs (R-160 F7, issue 5). Spec 44 now states one read share with a default for both, the catalog change and the new finding. Every gap was a spec update; no decision record or research note was needed.

## Decisions

- One share, one parameter, for the check and for the finding: `digest.judge_read_share`, 0.25, provenance `default_no_data`. Both issues name "the share", so the check and the finding cannot disagree about what a judge that read too little is. No data fits a value (ADR-0116 says digest thresholds have none and sets this provenance). A quarter is above the two examples the issues give (1 of 12 is 0.08, 1 of 10 is 0.10), under half, and issue 4 says "a small share". "Under" is strict: 3 of 12 is exactly a quarter and is not under it, so the finding can fire only for a change of 5 changed paths or more (1 of 4 is already a quarter). A change of the value is a configuration change reviewed like any other (IMD-B23)
- The check's fact for `judge_unread` and `judge_trusts_report` is the digest's two counts, as SRV-B12 already uses them. The old words "the judge's `reads[]` before its verdict" named no measurable fact; the code tests `changed_read == 0` (`review.py` 535). A judge that opened none still keeps them
- `judge_model` joins the remedies of `judge_shallow`. It is a grader class the other two judge categories already allow (`GRADER`, `review.py` 39), so the producer and grader split of ADR-0031 holds: a step session's observation naming it stays `unsupported`. "Passes the check" means `kept`; the observation is `corroborated` only when a finding corroborates it (ADR-0119)
- The finding is a new cause and `judge_unread_pass` is not widened. The zero-read cause has no threshold to guess and keeps the precision SRV-B12 gave it; the share has no data, so the cause that rests on it can be tuned or ignored alone. The two never name one judge: `judge_partial_read` starts at one path opened, and the third scenario of SRV-B31 pins that a pass with none opened carries `judge_unread_pass` only. That keeps the two assertions of `test_session_review.py` (99, 100) true
- The finding takes any verdict, where `judge_unread_pass` takes a pass only. Issue 5 says "graded", and the judge R-160 F7 cites escalated
- "Gave a judgement" is not "has a `judgement` record". The record is also written for a judge that timed out, whose answer stayed unparsed or whose judgement the guard discarded (`nodes.py` 1620-1662): `derive(None)` gives such a judge a placeholder with no blockers and source `engine_placeholder` (`judging.py` 251-253). So a judge gave a judgement when its record's `confidence_source` is not `engine_placeholder`, matched to the judge's digest by unit and attempt (the digest holds both, `parse_key`); the fourth scenario of SRV-B31 pins it. The plan must not reuse `passed` (`record.py` 185) for the finding: it reads every record without blockers as a pass, a placeholder included. A judge that failed on an infrastructure error writes no record (`nodes.py` 1616-1619). A re-ask session carries no changed paths (`nodes.py` 1625-1630), so its digest has `changed_total` 0 and no finding
- "The judge's own session record" is the judge session's digest (SRV-B11): `changed_read` and `changed_total`, names and numbers only, no model call
- Class and side are those of `judge_unread_pass`: "fault, grader side" in SRV-B12, held in the cause table as fault with side `workflow` (`causes.py` 70). SIL-B10 and SIL-B11 take digest causes by name from SRV, so SIL is not edited. A suggested remedy text for the cause table: "The judge graded after opening only part of the change: tell it what to read, or give it a stronger model"
- A judge that opened none and did not pass carries no finding. Settled from the code and its test: `judge_unread_pass` needs a pass (SRV-B12), `judge_partial_read` needs at least one path opened, and `test_session_review.py` line 100 asserts no cause at all for that judge. Covering it would change that assertion, and R-160 shows no such judge (F7 and F8 show a judge that opened one file of many and escalated)
- `judge_partial_read` is not a review signal: the signal list of SRV-B16 is not edited, so a stable-mode `signals` plan does not read a judge for it. Issue 5 asks for a finding "even when no session review runs", and a signal would also spend review money in stable mode within the cap of 3 sessions a run
- SRV-AC1, which says fixtures reproduce "every digest cause", is not edited: SRV-AC14 carries the new one
- No "Not built yet" line of spec 44 concerns these issues (its one line is about corroboration and the proposer's reading of observations), so none was removed or edited. The engine backlog rows E3 and E4 the issues name are no longer a file; scope lives in the issues
- Checked against what spec 44 links and what links it: IMD-B23 (a parameter with provenance `default_no_data`), SIL-B10, SIL-B11, SRV-B11, SRV-B12, SRV-B16, SRV-B20, ADR-0031, ADR-0116 and ADR-0119. No behaviour contradicts; no other spec was edited

## Open questions

- Is a quarter the right default share? No data fits a value, so the documents use 0.25 and say so (`default_no_data`); it does not block planning. Options: (a) 0.25 (the default used); (b) 0.5, more findings and more noise on judges that grade from a diff they ran in the shell; (c) 0.1, only the extremes the issues give. Recommended: (a), and a fit once live reviews show how often it fires
