# Hand-off: i169

## Problem

A gate's judge is given the paths that are uncommitted in the workspace when it starts. When a script of the unit commits the step's work before the judge, that list is empty, so the judge's digest holds `changed_total` 0 and `changed_read` 0 and the causes `judge_unread_pass` and `judge_partial_read` and the citation check of `judge_unread` and `judge_trusts_report` cannot fire. The specs name the two counts and none says which change they cover. Discovery states it: the paths that differ from the commit recorded when the judged visit was entered, committed or not; for an item of a map the visit is entered at the item's own first attempt, and for a unit with no step session it is that unit's own entry.

## Open questions

- A gate whose unit has no step session (a sub-workflow, a council, the outcome gate): SRV-B36 counts from the unit's own entry, so the outcome gate, entered after earlier units committed all their work, lists nothing and `judge_unread_pass` cannot fire for it. Options: a) the unit's own entry; b) nothing for these gates; c) for the outcome gate, everything the run changed since its start. Until answered: option a
- The judge's prompt is given a count of changed files taken with no base (`run/nodes.py` line 1658, JDG-B11), so for a visit whose script committed its work the prompt can say 0 files changed where the digest counts 2. Options: a) leave the prompt as it is; b) give the prompt the same list. Until answered: option a
- Outside git the entry record holds no commit and `git status` prints nothing, so a judge's list is empty (read in `git.py` lines 254-267; no test pins it); a check outside git gets a manifest-based list (WSP-B17). SRV-B34 and SRV-B35 are scoped to git workspaces and say nothing of it. Options: a) leave it unstated; b) state that the list is empty outside git; c) give a judge the manifest-based list. Until answered: option a
- A contest's slots: SRV-B34 counts a slot's judge from the contest's own entry, so a writing slot's list holds the work the engine's checkpoint commit took in before the slots were cut, as well as the slot's own; SRV-B35 names maps only. Options: a) from the contest's own entry (as written); b) count a slot like an item (SRV-B35), from the slot's first attempt in the contest's visit; c) leave slots as they were (uncommitted paths only). Until answered: option a
