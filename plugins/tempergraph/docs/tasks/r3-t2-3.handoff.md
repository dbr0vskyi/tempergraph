# Hand-off: r3-t2-3

## Problem

A sub-workflow child must be learned from and measured as its own workflow (SWF-B9), and a parent run carried on a branch and paused inside its child must resume on a second state root (SWF-AC3). The short visit checked each gap's cited behaviour; four answer their gap, and one (G3) leaves a limit of the acceptance criteria undecided.

## Gaps closed

- G1: SWF-B9 (with SWF-AC1). Keeps the child's judges on the child's own bindings and cases (JCL), which is the event and result criterion 1 names.
- G2: SWF-B9 (with SWF-AC1). Files a finding about a child unit to the child workflow with `sides: [workflow]`, `workflow: <child>` and the parent named (SIL); its scenario is the friction finding of criterion 2.
- G3: SWF-B9 (with SWF-AC1). Not covered: SWF-B9 counts the child's outcome record in the child's promotion window "only when that window says so", but the window rule PRO-B8 (`95-promotion-check.spec.md`, line 53) names no `subworkflow:<parent>` origin. It leaves out only runs with origin `trial`, `scenario` or `evals`, so as written a child record would count by default, which contradicts "only when". Which rule says so, and whether the record counts, is undecided. SWF-B9 has no scenario for the measures or the window either.
- G4: SWF-B9 (with SWF-AC1), VER-B17, WUP-B6. SWF-B9 has the parent's `upgrade` read the child's change notes; VER-B17 (`61-version-metadata.spec.md`, line 94) defines the notes and the parent reading them; WUP-B6 (`63-workflow-upgrade.spec.md`, line 130) gives the `rename_field` item for a renamed output key.
- G5: SWF-B8 (with SWF-AC3). SWF-B8 makes a resume continue the child where it paused (checkpoint namespace per unit, visit and attempt) and refuses a resume whose child was removed; SWF-AC3 states the carried resume on a second state root and points to CAR-AC1, whose two-state-root cases hold for any thread.

## Open questions

- Does a child's outcome record (origin `subworkflow:<parent>`) count in the child's promotion window? Options: (a) it counts like any finished run, so PRO-B8 stays as it is and SWF-B9 loses "only when that window says so"; (b) it is left out unless the window says otherwise, so PRO-B8 adds `subworkflow:<parent>` to the left-out origins; (c) it counts only for runs whose parent finished. The full discovery closes this with a spec edit or a decision record.
- SWF-AC1 names SWF-B9 in its brackets, but its statement speaks only of SWF-B1 to SWF-B6; the full discovery may need to state what an observer verifies for SWF-B9.
