# Triage: r3-t5-2

## Task

Task R3-T5.2 of the release 3 plan (`plugins/tempergraph/docs/plans/third-release.plan.md`, track R3-T5 Schedules): build ticks and unattended fires from spec `plugins/tempergraph/docs/specs/schedule-ticks-and-unattended-fires.spec.md` (TCK), on top of the schedule command phase R3-T5.1 built (`tempergraph/schedule/`, spec `schedules` SCH). Owner's rules: OS agnostic, deterministic, model-free; the tick calls no model and answers no gate; every pause of a scheduled run waits for a person. Everything with an injectable clock and a scripted run launcher, so tests never start a real model session.

## Acceptance criteria

1. `schedule tick` (TCK-B16, TCK-B2, TCK-B12): the lock, the heartbeat `schedules/tick.json`, settling started fires from their thread's status, deciding due slots through the R3-T5.1 policy functions, launching `run` detached with the fire token, `--schedule <fire_id>` and a hand-off ticket, at most 4 runs and 20 s per tick with `deferred`; `repo_missing`
2. `schedule fire <id>` through the tick's path (SCH-B26 manual fire id) and `schedule runs` with the machine-wide ledger `~/.tempergraph/schedules/runs.jsonl` (TCK-B13, TCK-B23), honouring TEMPERGRAPH_HOME
3. The fire token and caller kind `scheduler` (TCK-B17) in the run's caller classification (provenance.py), `schedule_token_invalid` and `schedule_reserved`; the token in no record, argv or step environment
4. Unattended credential kinds and the per-executor credential check at add, edit and each fire (TCK-B18, TCK-B19, TCK-B5, TCK-B6), as an executor capability, never a model call
5. Who may create a schedule (TCK-B22, TCK-B10): `schedule_not_by_person`, `--relayed`
6. What a scheduled run adds elsewhere (TCK-B24, SCH-B28, SCH-AC7): `origin: schedule` and the schedule block in the status document, `run_started` and the stats row; `report --by schedule`; the attention items `schedule_missed`, `schedule_paused`, `schedule_budget`, `schedule_refused`, `blocking_schedule` and `trigger_stale` (TCK-B7); the `schedule_paused` hook event
7. Triggers (TCK-B14, TCK-B15, TCK-B1, TCK-B3, TCK-B8): the portable `schedule loop [--detach|--stop]` (sleep until the earlier of the next slot and 60 s, a wall-clock jump ends the sleep), the `host` adapter (the plugin's SessionStart hook starts the loop when `schedule.loop_autostart` is on), `schedule trigger install|status|remove` with the `os` adapter (LaunchAgent, systemd user unit, Task Scheduler, crontab fallback, `no_os_scheduler`), entries written as files checked against golden files and never installed for real in tests
8. `schedule export <id> --for github-actions|gitlab-ci|crontab` (TCK-B20, TCK-B11)
9. The `tempergraph:schedule` skill (TCK-B21) under `plugins/tempergraph/skills/`, with eval cases as the other skills have
10. Orchestration targets (TCK-B9) stay refused, since ADR-0132 moves orchestration to release 4
11. Probes P-SCH-1 to P-SCH-4 are listed in `plugins/tempergraph/docs/plans/live-checks.plan.md`, never faked
12. Tests in `plugins/tempergraph/engine/tests/` for every TCK criterion that can be met offline, and SCH-AC5 and SCH-AC7 end to end with scripted runs
13. Spec `schedule-ticks-and-unattended-fires`'s and spec `schedules`'s "Not built yet" open questions and the release 3 plan status are updated
14. The engine names no workflow package (ADR-0129)
15. Checks pass, run from `plugins/tempergraph/engine/`: `python3 -m pytest`, `ruff check src tests`, `mypy`
