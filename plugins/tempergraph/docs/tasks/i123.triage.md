# Triage: i123

## Task

`batch-queue/tasks/i123.md` (GitHub issue #123): the improvement loop reads the person's review of a run's pull request (review state, review comments, requested changes, follow-up commits) as a later outcome signal. Engine area; the engine names no workflow.

## Acceptance criteria

1. A run records the pull request it opened or pushed to (its number and code host), with no text of the pull request.
2. A later command, or the loop, reads that pull request's review state, review comments and follow-up commits by a person through the code host, and appends a `later[]` entry with counts and kinds only; comment text stays in local evidence.
3. A `met` run with changes requested, or with a person's follow-up commits that change files the run wrote, counts as an escape in `outcome show` and fires the outcome lens in stable mode.
4. An escape is a harvest candidate (`evals harvest outcome`) and a corroborating finding for review observations on the units that wrote those files.
5. Nothing in a filed issue or a ledger row carries review comment text, proved by a canary test.
6. The specs `run-outcome`, `feedback-and-judge-reliability` and `self-improvement` state this without naming any workflow.
