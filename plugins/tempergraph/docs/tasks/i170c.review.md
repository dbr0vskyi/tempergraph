# Review: i170c

## Findings

1. `plugins/tempergraph/engine/src/tempergraph/improve/child.py:451` not blocking: `recorded_judgements` is applied to every fault of the ticket, not only to pause findings. A fault with the same fingerprint that recurs in a later segment of the thread (a new finding) is never put to the judge again and takes the thread's first answer.
2. `plugins/tempergraph/engine/src/tempergraph/improve/filing.py:510` not blocking: when the read of open issues fails twice, a waiting create is sent as queued with no mute, cause or fingerprint check. ISS-B16 and ISS-B17 do not say what happens then, and no test covers it.
3. `plugins/tempergraph/engine/src/tempergraph/improve/filing.py:520` not blocking: a waiting `comment` entry is delivered without adding to `sent_now`, so a later create turned into a comment on the same issue in the same call can exceed `seen_again.max_per_issue_per_day`.
4. `plugins/tempergraph/engine/src/tempergraph/improve/issue_context.py:141` not blocking: for a segment with exit code 3 and no `pause` record, `pause_reason` returns `-` and replaces the exit record's reason, so the body shows `-` where it showed the exit reason before.
5. `plugins/tempergraph/docs/specs/gate-and-human.spec.md:94` not blocking: HUM-B6 lists the fields of the intervention ledger row, and the row now also carries `operator_reason`, which only CLI-B24 states.
6. `plugins/tempergraph/engine/src/tempergraph/improve/record.py:204` not blocking: a claimed ticket left behind by a killed child keeps its fingerprints held for good (`held_by_tickets` reads `*.claimed`). The ADR names this as undecided, and no test or revisit trigger covers it.

## Earlier review

1. `plugins/tempergraph/docs/specs/runs-without-a-final-exit.spec.md:18` not blocking: criterion 3 asks that SIL-B28 state all three behaviours (a recorded-only finding is handed again, a recorded judge answer is used, a waiting or claimed ticket covers its fingerprints) and that a thread whose last exit was held keeps its pause findings recorded only; SIL-B28 only points to SIL-B47, SIL-B48 and SIL-B49, which hold the statements and the hold-at-last-exit scenario
2. `plugins/tempergraph/engine/src/tempergraph/improve/child.py:452` not blocking: `recorded_judgements` is applied to every fault of the ticket, not only to the pause findings handed on, so a fault of the final segment whose fingerprint an earlier loop of the same thread answered is decided on that old answer and the judge is not asked about the new occurrence; SIL-B49 can be read this way, but the criterion speaks of pause findings only and no test shows this case
3. `plugins/tempergraph/engine/src/tempergraph/improve/issue_context.py:141` not blocking: for a segment with exit code 3 that holds no `pause` record, `pause_reason` gives `-` and the exit record's reason, which the body showed before, is no longer used as a fallback
4. `plugins/tempergraph/engine/src/tempergraph/improve/filing.py:391` not blocking: `Outbox.remove` reads the file and writes the kept lines back without a lock, so an entry that a detached loop child adds between the read and the write is lost; the window is small and `take` has the same shape
