## Earlier review

1. `plugins/tempergraph/engine/src/tempergraph/improve/child.py:507` blocking: a recorded judge answer is counted twice towards the majority of FFD-B1, against criterion 5 ("a thread adds one answer per fingerprint to the counts") and SIL-B49. `earlier = filing.recorded_answers(root, wf)` (line 444) reads every `loop.jsonl` of the workflow in the window, and that includes this thread's own earlier `loop_judged` record. The same answer is then also put into `judged` by `recorded_judgements` (line 453). `decide` builds `answers = [*c.earlier_answers, True]` (`filing.py:159`), so a finding decided on its one recorded attributed answer gets `[True, True]`. A finding that confidence alone would not file can then pass the `met and majority` test, and `few_answers` can never come out. The test `test_a_recorded_answer_is_used_without_a_second_judgement` (`tests/test_pause_hand_on.py`) hides this. It writes the recorded answer with `ts` 2000-01-01, which is outside `pattern_rule.window_days`, so `earlier` is empty in the test and not in a real thread. Visit: built
2. `plugins/tempergraph/engine/src/tempergraph/improve/filing.py:503` blocking: moving `listed` and `sent_now` ahead of the outbox redelivery makes the open-issue list stale for the rest of the call. A waiting create that is sent as a new issue at line 536 is not in the cached `listed[(repo, "open")]`. A fresh finding of the same cause in the same `file()` call then finds no open issue (line 572 reuses the cache) and opens a second issue, or a second waiting create of that cause does the same. Before the change the open issues were read after the redelivery. This breaks the one-issue-per-cause rule (SIL-B2, ISS-B7) when an outbox entry and a new finding share a cause, and no test covers it. Visit: built
3. `plugins/tempergraph/engine/src/tempergraph/improve/child.py:202` not blocking: `recorded_judgements` takes the thread's answers with no time window, so a stale answer of the same thread is reused for a recurring fingerprint however old it is. SIL-B49 does not say whether `pattern_rule.window_days` applies, and `filing.recorded_answers` applies it.
