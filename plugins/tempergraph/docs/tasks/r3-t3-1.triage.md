## Task

Source: engine release 3 plan (`plugins/tempergraph/docs/plans/third-release.plan.md`), phase R3-T3.1 "Writer branches". A parallel branch that declares `write` or `edit` runs in its own sibling worktree and the join merges the branches; validation stops refusing it with `parallel-writer-branch`. The concurrent map (R3-T3.2) is out of scope.

## Acceptance criteria

1. A parallel branch that declares `write` or `edit` validates; it runs in its own sibling worktree, named by WTR-B20 and cut from the run's branch after a checkpoint commit, and its step and judge sessions get that worktree as their workdir.
2. At the join, the writer branches are merged into the run branch without fast-forward in their declared order; read-only branches of the same block still run in the run worktree and still fail when they change it (WSP-B11).
3. A merge conflict at the join resets the run branch to its state before the merge and ends the join's step blocked with the conflicting paths, with no model call (WSP-B12).
4. A writer branch outside git is refused `needs_git` before anything is created (WSP-B15 family); writer worktrees are listed with the run's other worktrees and kept or removed by the existing cleanup rules.
5. Offline tests in scratch git repositories prove 1 to 4 and carry the criterion ids of WSP and WTR that state them (add a criterion to WSP when none states the writer branch end to end); the `parallel-writer-branch` refusal is gone from code and specs; the release 3 plan records R3-T3.1 as built; the offline suite, `ruff check src tests` and `mypy` pass.
