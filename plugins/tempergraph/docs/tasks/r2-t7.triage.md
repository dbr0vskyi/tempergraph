Release 2 track R2-T7 of the [second-release plan](../plans/second-release.plan.md): the node features a person-facing workflow needs (ask unit, event wait, deadlines, fallback target, operator breakpoints, parallel read-only branches, the check preview) and lifecycle hooks, plus the three gaps the first authored workflow found (I2-26). Owner's go of 2026-11-21.

## Acceptance criteria

1. An ask unit pauses with kind `input`, validates answers by kind, keeps partial answers across resumes and hands the answers to later steps as an artifact (ASK-AC1 to AC-3)
2. A wait unit pauses with kind `event_wait` and passes only on an event its pure check accepts (HUM-B4, WFM-B4)
3. A deadline marks a wait or ask overdue and is applied only by `resume --apply-deadline` (FLX-B3)
4. A gate's fallback target takes the run forward with `degraded: true` (FLX-B4, FLX-AC4)
5. `--pause-before` pauses before a unit with no session and no attempt record (FLX-B5, FLX-AC3)
6. A parallel block runs read-only branches and joins only when every branch has passed (CMP-B4); two pending gates are answered by unit (HUM-B3)
7. A step with `self_check` can preview its gate's check, with a limit and no state change (CHK-B7, CHK-AC6)
8. A deliverable is required only on a path that produces it, a repository can declare its own commands, and `GitFacts.pushed` is set (I2-26)
9. `hooks add|list|remove|test` register commands the engine starts detached on run events, and a hook's failure never changes a run (HOK-B1 to HOK-B6)
