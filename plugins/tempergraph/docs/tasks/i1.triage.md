# Triage: i1

## Task

GitHub issue #1: Self-improvement loop: track findings and proposals as GitHub issues end to end. The loop files issues with the repository's triage labels and a fixed body, reads close reasons back (not planned mutes, completed means a regression link), and ties proposals and trials to their issue (`Closes #<n>`, one trial comment).

## Acceptance criteria

1. SIL (spec 16) and PRP (spec 40) state behaviours 1 to 3 of the Summary as general engine behaviour, with no workflow named (ADR-0129): filing uses the `issue_labels` setting (default `["tempergraph-loop", "needs-triage"]` plus `side:*`) and a body with the sections Summary, Evidence, Fingerprint and Suggested remedy; a fingerprint whose issue was closed as not planned is muted for a set number of days (no new issue, no "seen again" comment); a fingerprint whose issue was closed as completed opens a new issue that links the old one as a possible regression; `improve open` writes `Closes #<n>` for the issue its cluster came from, and a trial result is posted as one comment on that issue in the agent comment format of CONTRIBUTING.md. Open questions carry `Until answered:` defaults.
2. A decision record covers the mute period and how close reasons map to the loop's actions.
3. Offline tests drive a fake code host for each behaviour.
4. Out of scope: behaviour 4 of the Summary (#6, an owner decision) and the live check L-17 (#40), which needs the owner's machine with a signed-in `gh`; the runbook row is extended with a closed-as-not-planned case but not run.
