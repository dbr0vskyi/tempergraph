# Hand-off: i123b

## Problem

The first run built the loop's read of a run's pull request, and an independent review found that it never sees the files a run wrote: the engine records them on judge sessions only, from `git status`, which is empty once a step has committed. The review also found a finding lost when a read fails or two reads overlap, one request to the code host for each commit, any non-bot account counted as a person, review text that a carried thread would push, and spec lines that disagree with the code. The specs now state the mechanism the task names for the run's files and the writing unit, the cost and failure rules of a read, who counts as a person, and the lines that disagreed with the code.
