- Row 5.5 puts the server check "through `mcpconfig`" in `run/nodes.py`. The engine's run code is executor-neutral and the stand-in executors have no MCP servers, so `_reachable_views` asks the judge executor for `unreachable_views(views, workdir)` when it has one, and `ClaudeExecutor.unreachable_views` (in `executors/claude.py`, a file row 4.8 names) delegates to `mcpconfig.unreachable`. An executor without the method is not asked. Not in the plan's wording; no spec says otherwise.
- Row 5.5 says the deferral is "recorded". There is no run-log record kind for it, so the `judgement` record gains a `deferred` list (capability and reason) when the view set holds any deferred view, and no key otherwise. A reason of a server with no proxy is `mcp_missing`, `mcp_remote` or `mcp_start_failed`.
- Row 4.8: `run_judge` writes the private configuration only when the viewed server is proxiable and a state-root `scratch` folder is found above `req.session_dir` (WSP-B5). With either missing, it launches the read-only judge with `--disallowedTools "mcp__*"` and no MCP tool, as before. The path of the configuration is replaced by `<private>` in the `argv` of the returned `SessionResult`; the launched process itself is told the path, as the CLI needs it.

The plan says only "relays `initialize`, answers `tools/list`, refuses other tools"; this is the narrower reading of "offering only the viewed tools".
