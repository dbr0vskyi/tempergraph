# Hand-off: i61

## Problem

The session review's citation check keeps a `judge_unread` or `judge_trusts_report` observation only when the judge opened none of the changed paths, and it drops `judge_shallow` naming `judge_model` on its remedy class alone, so a correct observation at 0.9 about a judge that read 1 of many files was rated `unsupported` (R-160 F8, issue 61). No model-free finding names a judge that graded after reading only part of the change, so the loop sees it only when a review runs (R-160 F7, issue 62). Spec 44 now states one read share with a default for both, the catalog change and the new finding. Every gap was a spec update; no decision record or research note was needed.

SRV-B19 gives `judge_unread` and `judge_trusts_report` the fact "`changed_read` under that share of `changed_total`, `changed_total` above 0", so a judge that opened none, or 1 of 12, keeps them and a judge that opened 3 of 12 does not. ## Decisions

- One share, one parameter, for the check and for the finding: `digest.judge_read_share`, 0.25, provenance `default_no_data`. Both issues name "the share", so the check and the finding cannot disagree about what a judge that read too little is. No data fits a value (ADR-0116 says digest thresholds have none and sets this provenance). A quarter is above the examples the issues give (1 of 12 is 0.08, 1 of 10 is 0.10), below half, and issue 61 says "a small share". "Under" is strict: 3 of 12 is exactly a quarter and is not under it. The finding can only fire for a change of 5 changed paths or more, since 1 of 4 is already a quarter
- The check's fact for `judge_unread` and `judge_trusts_report` is the digest's two counts, as SRV-B12 already uses them. The old words "the judge's `reads[]` before its verdict" named no measurable fact; the code tested `changed_read == 0` (`review.py` 535). A judge that opened none still passes the check
- `judge_model` joins the remedies of `judge_shallow`. It is a grader class the other two judge categories already allow (`GRADER`, `review.py` 39), so the split of ADR-0031 holds: a step session's observation naming it stays `unsupported`. "Passes the check" means `kept`; the observation is `corroborated` only when a finding corroborates it (ADR-0119)
- The finding is a new cause and `judge_unread_pass` is not widened. The zero-read cause has no threshold to guess and keeps the precision SRV-B12 gave it; the share has no data, so the cause that rests on it can be tuned, filed or ignored alone. The two never name one judge: `judge_partial_read` starts at one path opened, and the third scenario of SRV-B29 pins that a pass with none opened carries `judge_unread_pass` only. That keeps the existing assertions of `test_session_review.py` (99, 100) true
- The finding takes any verdict, where `judge_unread_pass` takes a pass only. Issue 62 says "graded", and the judge R-160 F7 cites escalated. It needs a judgement the judge gave (a `judgement` record of the segment): a session that timed out or went unparsed gave none. A re-ask session carries no changed paths (`nodes.py` 1630), so its digest has `changed_total` 0 and no finding
- "The judge's own session record" is the judge session's digest (SRV-B11): `changed_read` and `changed_total`, names and numbers only, no model call
- Class and side are those of `judge_unread_pass`: "fault, grader side" in SRV-B12, held in the cause table as fault with side `workflow` (`causes.py` 70). SIL-B10 and SIL-B11 take digest causes by name from SRV, so SIL is not edited. A suggested remedy text for the cause table: "The judge graded after opening only part of the change: tell it what to read, or give it a stronger model"
- No "Not built yet" line of spec 44 concerns these issues (its one line is about corroboration and the proposer's reading of observations), so none was removed or edited. The engine backlog rows E3 and E4 the issues name are no longer a file; scope lives in the issues
- Not edited on purpose: the signal list of SRV-B16, because `judge_partial_read` is not a signal and a stable-mode `signals` plan does not read a judge for it (open question 2); and SRV-AC1, which says fixtures reproduce "every digest cause", because SRV-AC13 carries the new one
- Checked against what spec 44 links and what links it: IMD-B23 (a parameter with provenance `default_no_data`), SIL-B10, SIL-B11, SRV-B11, SRV-B12, SRV-B16, SRV-B20, ADR-0031, ADR-0116 and ADR-0119. No behaviour contradicts; no other spec was edited

## Open questions

None blocks planning; each has the default the documents now use.

- Should a judge that opened none and did not pass carry a finding? Today neither cause names it: `judge_unread_pass` needs a pass (SRV-B12) and `judge_partial_read` needs at least one path opened; `test_session_review.py` line 100 pins no cause for it. Options: (a) no, unchanged (the default, written in SRV-B29); (b) `judge_partial_read` covers every judge under the share, none included, except the pass that `judge_unread_pass` names: SRV-B29's "above 0" goes, one scenario changes and line 100 of the test changes. Recommended: (a) until a run shows a judge that read nothing and failed a change without grounds
- Should `judge_partial_read` be a signal that reads the judge whole in a stable-mode plan, as `judge_unread_pass` is (SRV-B16)? Options: (a) no (the default; issue 62 asks for a finding "even when no session review runs"); (b) yes: SRV-B16's judge clause names it, `RANK` and `_reads` in `review.py` (lines 145-151, 261-263) gain it and one fixture plan proves it, which costs about 60 bytes of spec 44 and more reviews in stable mode within the cap of 3 sessions a run. Recommended: (a) now; revisit when runs show how often it fires
- Is a quarter the right default share? Options: (a) 0.25 (the default); (b) 0.5, more findings and more noise on judges that grade from a diff they ran in the shell; (c) 0.1, only the extremes the issues give. A change of the value is a configuration change reviewed like any other (IMD-B23). Recommended: (a)
