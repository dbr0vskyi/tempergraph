- Complexity: `complex` because the bytes of the files and specs the rows name pass 200,000. - Plan choices on points the specs leave open, each a value or format and no new behaviour, and each to be written into the rows by the expand step:
  1. A marking commit never comes from a planning step. KMK-B4 says a mark that no commit of the run wrote is refused; the commit that hands the plan over is the plan or expand step's own, so it cannot be the one that wrote the mark. The history check leaves out commits whose subject names the plan or expand step (`plan for`, `expand for`) and takes the earliest of the others in which the row's id carries the mark the plan now carries. With no base commit, or no such commit, the mark is refused (today's behaviour, so the fixtures `row-already-marked` keep failing).
  2. Rows read the same when their kind, requirements, file, proof and change are equal after whitespace is collapsed; the phase heading and the Completed cell are not compared. A renumbered row is a changed row (hand-off, open question 2: option a). The check accepts a kept mark and does not require it (open question 1: option a).
  3. The signature stays valid for the plan rule test: `mark_problems(plan, done, kept=None)`, where `kept` maps the id of each marked row to `""` (history backs the mark) or to the reason it does not; with `kept` `None`, or a marked row absent from it, the mark is refused as having no commit that wrote it. Search of the tests: only `tests/test_temperspec.py` line 136 calls `mark_problems` (`done=False` on an unmarked plan), and it stays valid.
  4. `stamp.json` is not edited by hand: rung 10 stamps the docs digest and the outcome revision again, and takes revision 11 as a newer revision, so the pull request must say that the owner was away. The code report says whether `tempergraph author verify plugins/temperspec-tgraph` was run, as the i112 report did.

## 2. Phases

### Phase 1: The marks against the run's history

Goal: the plan check and the expand check accept the mark of a kept row, refuse a mark on a changed row, a row whose file changed since, or a row no commit wrote, and the code check accepts a kept row whose file an earlier visit changed.
Weight: medium

### Phase 2: The briefings

Goal: the plan, expand and code prompts and the plan rule tell the sessions to keep the mark of a row they leave, to empty the mark of a row they change or add, and to build only the rows without a mark.
Weight: light

### Phase 3: The outcome mirror

Goal: `outcome.json` states the three reworded criteria as the specs do, with revision 11 in its list.
Weight: light
