- Extra files opened beyond the hand-off's reading list, each for what the list does not answer: `plugins/temperspec-tgraph/tests/test_outcome_routing_run.py` (lines 1-90, the stand-in run the fixture rows copy), `plugins/temperspec-tgraph/tests/conftest.py`, `plugins/temperspec-tgraph/tests/test_code_mode.py` (lines 198-222, 332-366, 560-631: the tests that pin `code_join` as a script unit and the rule that a complex plan with no rows marks one heavy phase), `plugins/temperspec-tgraph/diagram/workflow.md` (the generated picture), `plugins/tempergraph/engine/src/tempergraph/run/checks.py` (lines 73-98, what a check is given: `visit`, `facts`, `git`, `session`), `plugins/temperspec-tgraph/docs/plans/i148.plan.md` (lines 1-40 and the verification commands, the form of a plan of this repository), and `tempergraph.commands.json` (the declared commands). This plan is written in `plugins/temperspec-tgraph/docs/plans/` because the package keeps its specs, tasks and plans under its own `docs/`.
- Open questions of the hand-off, each taken by its default: the bound is the quick lane; a first review's findings carry the whole visit's result; the pause holds under every conversation value; the rule files list no `.review.md` note; a blocking finding a person lets through is not listed in the description.
- Why this design:
  - One new unit, `independent_review`, a step placed after `code_join` in `order`, so that the package test that asks for one spec file named after each unit (`tests/test_code_mode.py` lines 578-579) passes with the spec that exists. `code_join` becomes a route unit with the targets `independent_review` and `finalizer`: a run whose `route` value is `quick` goes to `finalizer`, where the outcome gate runs first (CMP-B15), every other run goes to the review (IRV-B1, IRV-B2). The engine's check of `joins_at` names no unit kind (`model/validate.py` lines 696-707). The tests that pin `code_join` as a script (`tests/test_code_mode.py` lines 213, 332-335 and the lists at 346, 366, 450, 510) are rewritten to read a route unit. `code_join` has no judge, so no unmet warning reaches the reader's prompt.
  - The reader is a step with the tools read, search, list and write, no shell and no reads of any run artifact. A `before` script of the step finds the run's base commit itself (the engine's scripts get none, as the decision on independence says) and writes two files in the run's own folder `.tempergraph/review/`, never committed: the change (the diff since the base without the hand-over documents and without the files that `prepare` wrote or changed) and the task's numbered criteria (nothing else of the triage note). The prompt names those two files and the one draft file the reader writes, `.tempergraph/review/findings.md`, and nothing else of the run. The reader writes the draft with the write tool and never reads a findings document.
  - An `after` script, before the step's commit, builds the committed document: it writes the draft's findings under `Findings` in `<task id>.review.md` in the folder of the triage note (RVF-B1); when the document at the branch head already holds a review (a trip back happened) it keeps that review's findings under `Earlier review` and ends each blocking one with `Visit: built` or `Visit: refused` (RVF-B6, RVF-B7; one result for the whole visit, as the decision on independence says).
  - The gate has a model-free check and a judge. The check applies RVF-B2 to RVF-B5 (form, file exists, line inside it, mark, numbering, `None`), IRV-B6 and IRV-B7 on the session record (the reader opened none of the plan, hand-off, code report, triage note, setup note or findings document, and wrote nothing but the draft; not applicable with no record, as SRC-B8 says), commit state, and it records in a finding the step a blocking finding goes back to by IRV-B9 and IRV-B10 (a file the change touches: the code step; any other file: the plan step, whatever the other findings name) and, when the branch holds an earlier review, the step the first trip went to, read from the run's commit subjects. The judge file asks one blocker criterion, "no blocking finding is left", whose `defect_in` is `plan` or `code_report` as the check's finding says, and whose evidence lists each blocking finding by number, file, line and text in the order of the document and no finding that is not blocking (IRV-B11, IRV-B13).
  - The engine counts trips back for each target, not for the gate. The gate declares the `back_targets` `plan` and `code` with `loop_budget` 1, and on a review that follows a trip the judge names the step the first trip used, so the engine's budget for it is spent and the gate pauses with its default `on_budget_spent` (`ask`, kind `budget`) and the judge's blockers in the payload (IRV-B12, IRV-B13). A review with no blocking finding passes with no trip and no pause (IRV-B14).
  - The last stage's description builder reads the committed findings document and lists each finding marked not blocking, from both sections, under `Review findings that block nothing` after `Read these` (PRD-B9). The criteria PRD-AC1 to PRD-AC8 are new in `pull-request-description.spec.md`, so the existing description tests carry those ids.
  - A changed or new criterion is a new revision of `outcome.json` (the file's `revision` follows its last entry; `tests/test_spec_budget_and_moved_ids.py`). `tempergraph author verify plugins/temperspec-tgraph` is not a declared command of this repository, so the code step runs it by hand and reports its result, and the tests of phase 3 prove what they can read: the revision, the unit in the README, the overview and the diagram.
  - No engine change is built. The three needs of the decision on independence (refused paths of a session, the base commit in a script's context, a per-point result of a visit's reason) are in the package's docs already; the code report says that none is built.

## 2. Phases

### Phase 1: The findings document and the unit's model-free parts

Goal: the findings document is parsed, checked and built, the reader's change and criteria are produced, the step a blocking finding goes back to is chosen, and the session-record checks run, each proved by a test of the new test file before its code.
Weight: light

### Phase 2: The unit in the workflow

Goal: `code_join` routes a run to `independent_review` or to the outcome gate, the step, its prompt, its judge, its gate with one trip back and its pause exist in the loaded workflow with their sizing, and fixture runs show a planted defect sent back, a clean change passed, a second blocking review paused and a quick-lane run skipped.
Weight: heavy (large-context)

### Phase 3: The description, the criteria and the documents

Goal: the description lists the findings that block nothing, the existing description tests carry PRD-AC1 to PRD-AC8, `outcome.json` has its new revision and the unit's criteria, and the blueprint, authoring record, stamp, README and diagram show the unit.
Weight: medium
