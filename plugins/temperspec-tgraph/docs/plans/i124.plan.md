## 2. Phases

### Phase 1: The base branch's head in a check's context

Goal: `git.base_head` holds the commit of the run's base branch (local, else `origin`, no fetch; empty for a run in place or with no ref), in the check context, the check worker's document and the preview, proved on a scratch git repository.
Weight: light

### Phase 2: The outcome check's guard for a spec the base branch changed

Goal: the outcome check reports `ts-spec-fresh` as fail naming each edited spec the base branch changed since the run started, pass for the others, and not applicable with its reason, and `outcome.json` at revision 12 holds the criterion with the overview row's text.
Weight: light

### Phase 3: Prepare writes the block from the repository's real layout

Goal: prepare builds the block from the repository's overview-spec folders, the folders beside them and the rule files' real location, installs nothing when the rule files are held, and leaves a `CLAUDE.md` that already names a specs folder unchanged.
Weight: medium

Goal: the README, the setup skill and the seven step prompts say what prepare now does and defer to the project note for the notes' folders and the rule files' location, with the phrases the prompt checks read kept.
Weight: light
