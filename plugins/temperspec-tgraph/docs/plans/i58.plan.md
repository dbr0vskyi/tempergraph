- Why this design: the engine already resolves `@repository` for a check (`resolve_command` reads the entry in the context's allow-list) and expands it for a step (`expand` at the start of an attempt), so the package change is its declaration: `@repository` and the five read-only git commands replace the six Python commands in the workflow's allow-list and in the code step's commands (RCM-B1 to RCM-B5). Every check that reads commands already goes through `_commands` in `checks.py`, so one place carries the refusal text (RCM-B2). The Python commands move into the file that `prepare` writes (RCM-B6), which keeps today's behaviour for a Python repository, and the one engine change is the host audit's reading of the entry (AUD-B17 to AUD-B19), without which rung 6 of `author verify` fails on the package's own allow-list. The alternatives (keep `VERIFY` beside the file; skip the entry in the audit) are rejected: the first keeps the Python-only list the task removes, the second leaves rung 6 failing on the package's own allow-list.
- Plan choices on points the specs leave to the plan, each a value or a place and no behaviour: (1) the file's text is built once in `routing.py` (`json.dumps` of `schema_version` 1 and the six commands, two-space indent, one final newline), and the code gate compares the file with that same text to decide that prepare wrote it (RCM-B9); (2) the helper that decides "written by prepare" serves three readers in `checks.py`: the evidence in `_result`, the source-file list in `_reading_lines` and the quick lane's guard in `_lane`; (3) the audit reads the target's file with the engine's own `repository_commands`, so the audit and a run read the same file; (4) a workflow that lists the entry, has no gate with a check and whose file is missing raises no `toolchain-not-covered`: no spec states it, this plan adds no behaviour for it, and the rule's existing logic stays as it is.
- Not edited, and why: spec 75 (CHK-B11) shows a file with no `schema_version` that the engine ignores. No behaviour of this task changes it, a spec edit with no such change is collateral, and the spec is near its 30 KB cap. The code report states it.

The engine's tests of AUD-AC8 to AUD-AC11 prove the audit, and the engine's suite runs the package's loading and its tests. The code report says whether the command was run by hand.
- Not decided by any spec, and not blocking: whether a step may change `tempergraph.commands.json`. RCM-B9 states the behaviour: a step's edit is accepted and counts as a change of the run.
