## 2. Phases

### Phase 1: The removal row kind and the refusals of the plan and expand checks

Goal: the plan check and the expand check accept the kind `remove`, ask it for no proof and no test row, and refuse a row for a file under `.claude/` and an unusable or shared removal path, each with a fix text of its own (R1, R2).
Weight: medium

### Phase 2: The removal after the session

Goal: a script in the `after` list of the code step and of a phase removes the file of each marked removal row before the commit, starts no session, passes a file already gone, and records a refused path in a report that names the row, the path and the reason (R4).
Weight: medium

### Phase 3: The gates read a removal

Goal: the code gate and the phase gate turn a refused removal into an environmental finding that pauses the run naming the path, leave that row out of the changed-file finding, and the preview of the code check fails no marked removal row whose file is still there (R5).
Weight: light

### Phase 4: The briefs, the rules and the judges

Goal: the prompts of the plan, expand, code, phase and triage steps, the plan rule, the rule for task notes and the judge texts of the code and phase steps say what PRW-B6, PRW-B7, FRM-B8 and FRM-B9 name, and tests pin each sentence (R3, R6).
Weight: light

### Phase 5: Fixture runs and the outcome mirror

Goal: fixture runs of the arm `single` and the arm `phases` with the package's own `after` scripts end with the removed file absent and no pause, keep it when the row is unmarked or the session times out, pause on a folder, a path outside the workspace and a refusal of the file system, and `outcome.json` mirrors the three edited criteria with a new revision (R7, with R1, R2 and R5 for the mirror).
Weight: medium
