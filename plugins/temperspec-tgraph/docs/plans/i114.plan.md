# Plan: spec budget at discovery and ids moved by a split

## 0. Hand-off

- Triage note: `plugins/temperspec-tgraph/docs/tasks/i114.triage.md`; hand-off: `plugins/temperspec-tgraph/docs/tasks/i114.handoff.md`
- Specs read: `plugins/temperspec-tgraph/docs/specs/05-discovery.spec.md` (ts-dis-form, ts-dis-budget, ts-dis-over), `plugins/temperspec-tgraph/docs/specs/00-overview.spec.md` (ts-spec-form, ts-spec-cap, ts-spec-links, ts-spec-moved, ts-spec-parent)
- Why this design: both gates already call one function (`_spec_form` in `checks.py`) and one parser (`parse_spec` in `specfmt.py`), so the budget goes into that function for the discovery call only, and the moved-id reading goes into the parser, fed with the repository's definitions by that function. A failed discovery check already sends the step round again with each finding in its retry prompt (engine spec 75, CHK-B1, CHK-AC5), so no routing or engine change is needed.
- Extra files opened beyond the hand-off's reading list: `plugins/temperspec-tgraph/rules/plan.rule.md` (the plan format); `plugins/tempergraph/engine/src/tempergraph/run/checks.py` (`read_text` decodes the file, so bytes are measured from the file on disk); `plugins/tempergraph/engine/tests/test_workflow_packages.py` and `plugins/tempergraph/engine/pyproject.toml` (the engine's suite runs the package's own tests, which fixes the verification command); `plugins/temperspec-tgraph/docs/tasks/i114.handoff.md` itself.
- Assumptions, from the hand-off, kept: (a) the budget is fixed at 400 lines and 30,720 bytes (30 × 1,024, "over" means strictly more) for every repository, no setting; (b) the outcome gate's `ts-spec-cap` stays at 400 lines, the byte figure is measured once, at discovery; (c) a split is recognised from the files: a criterion may name an id that exactly one other spec defines when the id carries a prefix that the criterion's own spec defines, in the run that made the split and in any later run.
- Assumptions of this plan: an overrun is one finding under `ts-dis-over`, and `ts-dis-budget` carries a pass finding only when no spec is over; the tests go in a new file of the package (`tests/test_spec_budget_and_moved_ids.py`) with their own small helpers, so the plan stays within the size limit for `simple` (the existing test file is large); the check keeps its existing finding "names X, which this spec does not define" for every id that the moved-id reading does not accept, and adds no new check that a criterion names a behaviour of its own spec.
