# Triage: i166e

## Task

GitHub issue (area: temperspec), "a plan row that deletes a file pauses the run, because a step session cannot delete". In run `temperspec/i144b` a plan row removed an old module. The code session has `edit` and `write` and a shell limited to the repository's declared commands and read-only git, so it tried `git rm` and the run paused on `tool_access`. A row naming a file under `.claude/` pauses the same way (#156, run `temperspec/i71`).

## Acceptance criteria

1. The plan check knows what a code session cannot do (delete or move a file, write under `.claude/`) and either refuses such a row or marks it for a script
2. A row that removes a file is carried out with no model (a script after the step) or by a tool the step declares
3. A fixture run whose plan removes a file ends with the file gone and no pause

## Intent

- Goal: a plan can say that a file goes away, and the run carries that out without a person, instead of promising a row the code session has no tool for.
- In scope: what the plan check knows about the code session's reach (no delete, no move, no write under `.claude/`); how a removal row is carried out with no model session, or by a tool the code step declares; a fixture run that proves the file is gone and no pause happened.
- Out of scope: giving the code session a general shell or `git rm`; making `.claude/` writable by a session (the task allows refusing such a row); the independent review and outcome gate, except where they must read a removal; other causes of a `tool_access` pause.
- Assumptions:
  - A1: the plan step and the expand step (`plugins/temperspec-tgraph/prompts/plan.md`, `expand.md`) are the places that write such rows, and the plan check (`plan_check` and `expand_check` in `workflow/temperspec/checks.py`) is the "plan check" of criterion 1. If wrong: criterion 1 needs another check and the plan spec names it.
  - A2: the phase step has the same tools as the code step (`edit`, `write`, a restricted `shell`), so the same limit holds on the arm `phases`. If wrong: the removal needs a different place on that arm.
  - A3: the quick lane is a code task like any other, and a quick-lane task that removes a file meets the same limit. If wrong: the quick lane's `Change` section needs its own rule.
  - A4: "move" is a removal of the old path plus a new file at the new path, so the code session can write the new file and only the removal needs the script. If wrong: a move needs its own script action.
