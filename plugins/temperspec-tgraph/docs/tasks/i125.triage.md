## Task

GitHub issue #125: temperspec: a trip back to plan keeps completed marks of unchanged rows. When a run trips back to plan, the completed marks of rows whose files are unchanged stay, and the code step after the trip codes only the rows the trip changed. Today a trip back redoes or relabels finished work (`row 3.2 is already marked completed`).

## Acceptance criteria

1. When a run trips back to plan and the plan step keeps a row whose text and named file are unchanged and whose file was not changed since the row was marked, the plan check accepts the row's completed mark instead of refusing it.
2. A row the trip back changed (its text or its file) loses its completed mark, and the plan check refuses a completed mark on such a row.
3. The code step after the trip codes only rows without a completed mark, and the code check does not require a change to the file of a row that kept its mark.
