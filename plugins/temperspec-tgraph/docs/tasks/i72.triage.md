# Triage: i72

## Task

GitHub issues #72, #73 and #74 (R-160 F7, backlog rows B46, B47, B48): temperspec's steps and checks must hold what the session record shows. A step reads the rule file it must follow (or the prompt carries the rule text), the expand step opens each file a row names, and the code step writes each phase's tests before its source.

## Acceptance criteria

1. (#72) Each step prompt that names a rule file it must follow either carries the part of the rule the step must follow, or the step's check fails, naming the rule file, when the session record shows the file was not read (opened with the read tool; grep lines do not count).
2. (#73) The expand prompt tells the session to open each file a task row names before it writes the row.
3. (#73) The expand check fails, naming the row and the path, when a row names an existing file that the session never read.
4. (#74) The code check fails, naming the phase, when the session record shows a phase's source file was changed before that phase's test file was first written.
5. Each check reads the session record the engine gives the check (or a general engine capability that gives a check the tool calls of the unit's session, stated in the engine's specs without naming a workflow); with no session record (a fixture or a stand-in executor) the criterion is recorded not applicable.
