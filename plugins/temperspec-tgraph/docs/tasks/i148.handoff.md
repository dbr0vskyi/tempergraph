# Hand-off: i148

## Problem

On the `phases` arm the phase check hands its judge every path changed since the run's base, so a judge that cannot run git cannot tell what the phase changed from what earlier steps wrote, and it grades `ts-phs-scope` PARTIAL or sets a gap. The expand check counts the files opened by one session only, so each retry of a visit moves its finding to another set of files. Discovery states the sorted evidence of the phase gate and of the join, the phase judge's brief, a record of every session of a visit for a check, and the expand check's rules for kept rows and for one finding.

## Decisions

- The triage note lists no owner decision (`Owner decisions: None`): none was answered and none took a default
- AC 4 and AC 6 say the check "sorted" the paths: the specs read it as sorted into two lists, the paths changed since the step was entered and the paths that only earlier steps changed with their steps, each list in ascending order of path, so that both senses of the word hold (stated by the task)

## Inferred behaviours

- PHC-B9, the rows of earlier phases: read in `plugins/temperspec-tgraph/judges/phase.md` (line 10), which already exempts the files of earlier phases' rows; the spec stated only "the phase's rows", and the first list of PHC-B16 for a later phase holds the files of the phases before it
- PHC-B16, ascending order of path and a list that holds no path stating so: the task says "sorted" with no key; the code keeps the order git gave and writes the changed-paths line only when a path exists (`plugins/temperspec-tgraph/workflow/temperspec/checks.py` lines 450-455)
- PHC-B17, steps named in the order of the commits and no step name for a commit that names none: `commit_step` is the only commit the workflow makes and puts the step's name in its subject (`plugins/temperspec-tgraph/workflow/temperspec/routing.py` lines 457-475); a person's commit on the run's branch names none
- PHC-B19, the join counts from the entry of the code step and says when its first list is empty: PHC-B16 applied to the code gate, as AC 6 asks for "sorted the same way"
- VSR-B1, an earlier attempt with no session record adds no call: the record of the visit then holds at least the calls of the attempt's own record, so a check that reads it never fails more often, and never applies less often, than one that reads `session`; the neighbouring rule is CHK-B25 and the risk note of the decision `plugins/tempergraph/docs/adr/a-check-is-given-the-tool-calls-of-the-attempts-session.adr.md` (a false failure from a partial record)
- VSR-B2, no record of the visit when the attempt's own record is `None`: CHK-B25 (a stand-in that reports tool names only, a dropped tool line, the preview)

## Open questions

- Which commit is "the commit at which the phase was entered" (AC 1)? Options: a) the commit at which the phase step was entered, so the first list of a later phase also holds the files of the phases before it, which the judge's brief already exempts as rows of earlier phases; b) the commit at which each phase's first attempt began, so the first list holds that phase's files only. Option b needs the engine to give a check the head at the start of each item of a map, or the commit script to know its item (the first open question of `phase-coding.spec.md`). Until answered: a. It needs no engine change: the expand check can record the head as a fact for later checks (CHK-B6), or the entry is the newest commit that the phase step did not make
