# Triage: i63-64

## Task

GitHub issues #63 and #64: temperspec conversation modes `blocking` (default) and `always`, one batched pause (an engine ask unit) holding triage's owner decisions as typed questions with defaults, answers by `resume --answers FILE` or `--decision answer:<name>=<value>`, and defaults taken at a passed deadline (`resume --apply-deadline`). The run's conversation value was not given to this step; the gaps are sorted anyway (as under `never`) so that the gate can read them. Assumptions stated by the task: under `blocking` triage sorts gaps and writes owner decisions with defaults as under `never`, and the run pauses once after triage only when there is at least one owner decision; under `always` it pauses once after triage with the owner decisions and also asks whether the findable gaps' readings are right (or, if that is not sensible, pauses even with zero owner decisions); the deadline is a workflow setting with a default of 24 hours; `never` stays as it is. Change scope: triage, the ask, discovery and the pull request description only (coding on the `phases` arm, #65, is another change).

## Acceptance criteria

1. The conversation setting accepts `never`, `blocking` and `always`; `blocking` stays the default; a start with any other value is refused before spend.
2. Under `blocking`, a triage note with one or more owner decisions leads to exactly one pause (an engine ask unit) holding every owner decision as a typed `choice` question with its options and its default; a note with none takes a route that skips the ask and pauses nothing.
3. Under `always`, the run pauses once after triage as stated in the assumptions above.
4. The answers (given by `resume --answers FILE` or by `--decision answer:<name>=<value>`) reach discovery, which closes each owner decision on the answer instead of the default; the pull request description lists answered decisions as decided and unanswered ones under `Assumptions to confirm`.
5. After the ask's deadline, `resume --apply-deadline` continues the run with each unanswered question at its default (#64), and discovery records those as defaults taken.
6. The conversation spec, the triage and discovery specs, a unit spec for each new unit, the README's "An unattended run" section and the overview say what is true now. Offline tests with stand-in executors prove criteria 1 to 5.
7. The package's model-free authoring check (`tempergraph author verify plugins/temperspec-tgraph`, rungs that need no model) passes, and the package tests pass through the engine suite.
