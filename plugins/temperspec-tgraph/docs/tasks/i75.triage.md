1. Discovery reads in parallel: one read-only item per gap of the triage note runs on the engine's read-only concurrent map, and a single writing session then closes the gaps (specs, records, notes, hand-off) from the items' findings.
2. The setup survey reads in parallel: one read-only item per component, followed by the single session that writes the overview and component specs.
3. When the engine can run the judges of one gate concurrently, the package uses it for gates with more than one judge; if no gate of the package has more than one judge, or the engine cannot, the package's spec records this as an open question with its default and nothing else changes for judges.
4. A run whose triage note has no gap, or one gap, takes no extra session for the map (no map item for zero gaps; one item for one gap is allowed).
5. The package's model-free authoring check (`author verify` rungs that need no model) passes and the package tests pass through the engine's suite.
