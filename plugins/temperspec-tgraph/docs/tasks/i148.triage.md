# Triage: i148

## Task

`batch-queue/tasks/i148.md` (GitHub issues #148 and #149). On the `phases` arm the phase check hands its judge every path changed since the run's base, including paths that triage and discovery wrote, so a judge that cannot run git grades `ts-phs-scope` PARTIAL or sets a gap and the gate pauses for a person (#148). The `ts-exp-opened` check of the expand step counts only the files the last session opened, so each retry moves the finding to another set of files (#149).

## Acceptance criteria

1. The evidence the phase check hands its judge lists the paths the phase itself changed, counted from the commit at which the phase was entered, apart from the paths that only earlier steps changed.
2. Each path that only an earlier step changed is listed with the step that changed it.
3. `ts-phs-scope` is graded on the phase's own paths: a path that only an earlier step changed does not lower its grade and is not a gap.
4. The phase judge's brief tells the judge that the check has sorted the paths and that it takes that sorting as given.
5. A fixture run on the `phases` arm, in which an earlier step wrote a document and each phase changes only the files of its rows, passes each phase gate with no pause.
6. The join after the phases, when it is handed changed paths, is handed them sorted the same way.
7. `ts-exp-opened` counts the files opened with the read tool over all sessions of the expand step's visit, not only the last session's.
8. A row that kept its mark and its text from an earlier visit asks for no new opening of its file.
9. One finding of `ts-exp-opened` names every file still unopened.
10. A fixture in which a first session misses one file and a retry opens only that file passes `ts-exp-opened`.
