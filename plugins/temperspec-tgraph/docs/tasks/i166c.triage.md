# Triage: i166c

## Task

GitHub issue i166c: temperspec: a plan row that deletes a file pauses the run, because a step session cannot delete

## Acceptance criteria

1. The plan check knows what a code session cannot do (delete or move a file, write under .claude/) and either refuses such a row or marks it for a script
2. A row that removes a file is carried out with no model (a script after the step) or by a tool the step declares
3. A fixture run whose plan removes a file ends with the file gone and no pause

## Intent

- Goal: prevent `tool_access` pauses caused by plan rows that require file operations the code session's tools cannot perform, by catching them in the plan check and providing a no-model execution path for such rows
- In scope: the plan check detecting rows whose Change implies an operation the code session cannot perform (file deletion, file move, write under `.claude/`); a mechanism to execute such rows without a code session; a fixture test that proves the whole path
- Out of scope: detecting other kinds of code-session limitations (network access, arbitrary shell commands not declared by the step); changing which tools the code step offers to its session by default; the `.claude/` restriction from issue #156 beyond what AC1 asks for
- Assumptions:
  - A1: A "move a file" means: delete the source file and create the target; the target creation is writable by the code session, only the deletion requires a no-model path. If wrong: the check and mechanism may need to cover the whole move atomically, changing the behaviour design.
  - A2: The `.claude/` restriction is about write access only. If wrong: read-access restrictions would also need to be covered, widening the check.

## Existing documents

- `plugins/temperspec-tgraph/docs/specs/code.spec.md`: covers the code step and its gate; acceptance criteria ts-code-rows, ts-code-changed, ts-code-verify cover row completion and verification; nothing about executing rows whose operations the session cannot perform
